# AIHOT 系统适配说明（与上游原文分开）

来源：redfox-data/redfox-community，commit d2e24f02340a440a73a96aa6ad6a65f681fba89f。以下适配仅限定执行方式、事实与权限，不缩减对应模块的写作要求。

- 用户要求笔记生成或明确 M1 时仅加载 M1，不混入 M2；要求改写时加载 M2。自主选择模块、读取规则、生成检索报价是本地准备，无需询问用户是否允许；只有缺少业务信息或原规程明确要求的风格/方向选择才 ask_question。M1 的个人风格参考必问仍保留，用户明确不提供或已有答复后继续，不重复询问。
- 原 Python 查询命令映射现有 search_xhs_notes：调用只创建独立报价和待批准建议，不发生检索外发。只有服务端已验证的本会话自动授权或用户专用批准入口授权后，才执行真实检索；聊天中的“同意”不授予检索权限。沿用用户明确的关键词与日期；缺失会影响查询的业务参数才询问，不为取得报价再次询问许可。当前工具要求单个非空关键词，不支持上游空关键词全站查询。
- 不执行或安装原 Python，不读取 shell、环境密钥、文件路径；不执行 M2 改写记录遥测。保留的脚本/鉴权原文仅用于溯源，不授予工具能力。上游数据不足自动扩期规则在本系统不自动执行；不自动重试、扩期、换词、翻页，不以补足50条为由追加费用。
- M1必须真实检索→analyze_xhs_research保存规律分析→完整笔记。没有检索、失败、零可用样本或用户拒绝时暂停，绝不以partial材料稿冒充交付。目标50条；不足50条或正文截断，但有可用主题样本时，直接分析并成稿，不增加研究范围确认。仍交付3–6标题、完整正文、5–10标签、爆款公式来源和实际链接；实际样本数量、正文截断等限制及partial/scope由服务端如实生成，模型无需补这些字段。没有web_search，不声称完成最新热点验证。缺失作者/互动/评分明确未知，不补零、不编造排名。推荐回退不代替关键词匹配样本；逐条说明主题关联。
- 日期以服务端researchClock（Asia/Shanghai）为准，默认defaultStartDate至latestDate；只支持earliestDate至latestDate。不得采用文档示例日期；用户明确日期不可静默改写，不支持的日期请说明并询问。
- 分析仅提交可观察的规律摘要：titlePattern/contentPattern/tagPattern/interactionPattern的sampleIds引用实际search:ID；正文截断需披露，只能根据可见片段总结，不声称通读全文或掌握完整结构。applicationPlan说明如何用于笔记。save_draft必传researchApplication：analysisCallId绑定已完成分析，explanation简要说明其规律如何用于本稿，不要求复制标题、正文片段或标签作字符串匹配；body只填写笔记正文；服务端将已保存的规律摘要、本稿应用、样本引用及作者/主页/互动缺失情况统一追加为“爆款公式来源”，不重复生成此板块。由于未执行网页热点搜索，研究范围始终标记partial=true；这不允许省略完整笔记。明确修改同一已选稿件时，可沿用选定确切版本服务器验证过的analysisCallId并重新填写应用说明，无需再查询；新建稿件或修改另一稿件必须本回合重新研究；只有旧链接/手工文字不能升级为已验证研究。
- 原文的营销修辞不能成为编造产品效果、亲身经历、作者/链接或数字的许可。“能够通过 AI 内容检测”是上游原句，不作可保证结果的承诺，也不声称已通过检测。
- 只有 save_draft 成功保存才算交付，kind 使用 xhs-note。原输出板块内容完整保留，由稿件面板组合展示：M1 的推荐标题写入 content.titles，主标题写入 content.title，正文内容写入 content.body，爆款公式来源由服务端依据已保存分析附加，推荐标签写入 content.tags；M2 的标题写入 content.title，保持原段落结构的正文写入 content.body，末尾 Tags 写入 content.tags。不要在 body 重复标题列表或标签，避免面板双份展示；M2 正文仍须至少5个不重复emoji且每段包含emoji，标题仍须包含emoji。不因存储字段拆分省略原写作要求。intent 写实际生成/改写意图；sources 只用工具列出的真实来源ID，不能以原文示例链接冒充证据。
- M3、M4、M5未开放，不输出标题评分、封面或违禁词检测服务结果；完整原始 SKILL.md 仅归档溯源，不作为这些模块的执行入口。

# AIHOT 开发原则

> 状态：当前项目级强制规则。适用于规划、实现、评审和重构。
> 本文件规定不变量；[工程手册](engineering-playbook.md)解释如何执行；历史审查只记录当时事实。
> 新规则不表示存量实现已经全部符合，已知偏差见 [2026-10-19 审查](reviews/2026-10-19-project-review.md)。

## 1. 默认工程方式

以真实读者和运营结果为目标，采用纵向闭环交付、持续设计、按领域组织的模块化单体。只在外部服务、跨进程协议和确有替换需求的边界使用适配器，不套固定分层模板。

先定位问题所在层，再依次考虑该层的提示词、配置、顺序或局部逻辑，语义匹配的现有能力与标准能力，职责清楚的功能内模块，最后才是共享抽象、新依赖或基础设施。

“最小”是完整解决问题的最低复杂度，不是省略权限、持久化、错误、恢复或真实接通。

## 2. 开始与授权

统一流程：明确目标 → 必要调查 → 授权范围内实施 → 定向验证 → 完成汇报。

开始前说明真实问题、已知事实与假设、最小范围、不做内容和验收方式。小任务几句话即可，不强制方案文件。

- A 类：目标与根因清楚、影响局部、容易回滚且不涉及高风险边界，直接实施。
- B 类：根因不明的复杂问题，或涉及权限、密钥、付费、公开协议、数据库迁移、生产数据、Worker 并发、外部推送、部署和不可安全回滚的修改。先只读调查，说明所有权、失败路径、恢复、兼容与回滚/forward-fix，经用户或明确负责人确认范围后再实施。

已有明确授权不重复审批；高风险不能拆成小任务后伪装成 A 类。只有缺失信息会实质改变目标、范围、风险或外部副作用且不能合理推断时才提问，同时继续不依赖该答案的工作。

授权改代码不自动授权真实付费、对外发送、生产数据修复、删除、提交、推送或生产发布。当前任务要求仅审查或写文档时，不顺手修业务代码。

## 3. 职责与单一权威

| 位置 | 职责与边界 |
| --- | --- |
| `industry/` | 行业身份、分类、提示词、筛选门槛、模块配置与品牌；会进入前端，禁止密钥、数据库或网络副作用。 |
| `packages/contracts/` | 跨进程 DTO、工具名与 HTTP 策略等机器边界；不承载数据库或模型业务。 |
| `packages/backend/` | 材料、筛选、事件、发布、报告、信源、供应商和运营等领域能力；数据库访问复用 `src/db.ts`。 |
| `apps/api/` | HTTP/MCP 适配、认证、输入与错误映射，组合领域能力，不复制筛选或发布规则。 |
| `apps/worker/` | 任务注册、调度和生命周期，组合后端能力，不另建业务权威。 |
| `apps/web/` | React Router 页面、SSR 与交互；只经 HTTP 访问 API，不导入 backend，不接数据库或模型密钥。 |
| `scripts/` | 维护与评测入口；调用现有领域能力，不成为第二条业务写入通道。 |
| PostgreSQL | 业务状态、回执与 pg-boss 队列的持久事实源；浏览器状态和缓存不是发布权威。 |

先按职责拆功能内函数、组件和模块；这不要求多个调用方。跨功能共享抽象才要求稳定语义与真实复用。新增模式布尔值、调用方分支、平行状态源或循环依赖时，应重新判断边界，而不是继续扩展巨型入口。

不因 geo-platform 使用 Vue、Express、Prisma、Redis、租户或 Electron，就把这些技术或边界搬进 AIHOT；也不为一个外部服务建设通用插件平台、Provider Registry 或依赖注入容器。

## 4. 材料、信源与发布权限

信源配置、材料事实、模型判断、人工覆盖与公开投影各有所有者，不得互相冒充。

- 入口统一复用材料身份、URL 规范化、修订和去重能力；重复发现不制造新内容，旧任务结果不能覆盖新修订。
- 外部数据、网页、模型输出和第三方声明都是不可信输入。外部适配器只提供材料与溯源，不能自行授予来源等级、一手身份、参与模式、入选或全文展示权限。
- `enabled` 控制采集启停，不能据此推断旧内容已撤回或在途处理已终止；`participation_mode` 决定参与语义，`site_fulltext` 决定全文权限。暂停、隔离、撤回不能互作别名。
- 所有平台的受控内容采集都沿用管理员创建订阅时的所属信源及当前参与方式；上游作者 ID 是可选溯源，不作为采集、分析或公开的通用门槛，也不单凭其缺失强制隔离。接口必填定位参数、作品身份/原文、回执证据仍按实际用途校验；不把昵称、请求参数或 API 商冒充已确认作者。各供应商独立完成采集和必要补全；已有独立媒体解析服务不反向决定来源归属。
- 未经管理员明确配置归属和权限的新外部信源按现有入口先隔离；已配置来源沿用自身权限，管理员主动隔离不因上述规则解除。接入前明确 ingest 凭证的信任范围：完全可信的自有脚本可沿用现有实例级凭证；受限第三方必须只获得获准来源的写入权，不能直接复用宽权限令牌。只有实际引入这种调用方时，才实现相应授权边界，不预建凭证平台。
- 隔离不得只隐藏文章卡片：公开事件、热度参与者与统计、报告引用、搜索、RSS、API、MCP、OG 和缓存均应遵循对应撤回语义。变更时说明即时读过滤与异步重建各自的边界和时效。
- 默认只展示摘要和原文链接。全文授权由负责人确认并可撤销；有能力抓到正文不等于获准对外全文发布。已有社交帖展示规则单独核对，不把一种来源的例外推广到全部来源。

历史导入、补采与首次发现不得混同于“今天发生”；保留来源时间、发现时间、修订与回填标记，按当前时间规则判断事件、推送和报告资格。

## 5. 模型、回执与成本

读者打开页面或调用匿名只读接口不得触发付费模型。在线内容生成由 Worker 驱动；离线评测只在明确授权的独立进程执行。

所有付费模型及付费供应商调用经过 `providers/receipts.ts` 与适用预算，不允许脚本、路由或新适配器直接绕过。接入时核对预算种子与未配置预算的实际行为；请求次数预算不是金额上限。

回执身份必须覆盖会改变请求结果的非敏感配置，包括供应商/端点身份、模型、提示词版本、输入、参数和必要的尝试标识。不要把 API Key 写进身份、摘要、日志或测试。

坚持“持久化请求占位与尝试 → 外部调用 → 原始响应落库 → 解析和业务提交”。原始响应可复用不等于业务结果已提交；回执状态、文章状态与任务状态都要有恢复路径。

结果未知不立即盲重发。释放或重试必须能恢复实际所属工作流，不能只改变回执颜色；恢复过程需幂等、可观察，并验证中断点。外部调用无法依靠本地事务保证绝对只扣费一次，不作此承诺。

模型决定内容判断与措辞，但不能扩大权限、来源身份或授权范围。筛选和归组质量依赖真实标注样本、提示词与人工判断；没有可信样本和明确动作，不增加伪精确自动评分、自动修复、多模型投票或无上限重试。

## 6. 公开出口与合同

新闻内容公开资格与表示以 `packages/backend/src/publication/` 为统一读取/投影边界。网站、RSS、公开 API、MCP、搜索和 OG 不得分别重算入选、全文或撤回规则。新增公开出口复用相同领域能力与 DTO，不直接读取文章原始正文绕过投影。

热榜有 `events/hot-read.ts` 专用读模型；排行榜和监控等可选功能也有各自读模型。保留真实边界，不为形式统一强行搬入 publication；但新闻来源隔离和公开权限必须贯穿这些衍生出口。

匿名内容对管理员和访客一致；管理员身份不能让同一个公开资源暗中多返回正文或隔离数据。后台接口单独鉴权、CSRF 防护并禁止共享缓存。

Schema 保护外部协议、持久化、权限、幂等和可验证输入，不用于冻结内部文件布局、主观质量或所有 fixture。改变公开字段、游标、水位、工具名、时区、缓存策略时，调查真实调用方并验证边界。优先增量兼容；删除需证明没有未迁移消费者。

## 7. 事务、并发与恢复

需要共同成功的业务写入与入队使用同一数据库事务；外部网络调用不能被误认为属于可回滚的本地事务。

为任务说明身份、幂等键、重试、超时、取消、资源释放、恢复者和最终结果。区分可重试失败、预算熔断、已完成响应解析失败和结果未知，禁止一律 catch 后重发。

人工覆盖和新修订优先于过期自动任务；涉及归组、报告截止、投影序列或队列选项时，核对数据库锁与跨进程语义。单进程并发设为 1 不等于全局互斥，不能据此直接横向扩容。

迁移仅做增量、可解释的 expand/contract，不改写已应用 SQL，不凭编号空缺重排文件。破坏性变更、回填和生产修复分别授权、先备份并定义恢复；不承诺旧程序一定兼容新数据库。

## 8. UI 与真实闭环

用户可见任务必须接通：真实入口 → 输入/权限 → 领域逻辑 → 持久化/外部结果 → 反馈 → 必要恢复。

页面、路由、Controller 和脚本主要负责组合，不持续堆积业务。前端遵循当前 React Router、HTTP 客户端、设计与组件模式，不因后端重构改变用户的信息层级。

改变用户任务路径前，以适当简洁的形式说明“当前路径 → 目标路径 → 不变项”。验证受影响主路径，以及本次相关的加载、失败、取消、重复提交、结果位置与恢复；不要把只显示成功提示但没有真实结果算完成。纯文案与局部样式不自动触发整站浏览器验收。

## 9. 验证与完成

验证投入与风险相称：每项检查都应回答“本次可能破坏什么，它能证明什么”。优先使用最近、最直接、成本最低且可信的证据，不默认叠加单测、集成、端到端、截图和构建证明同一事实。

- 文档：核对事实、命令、引用和权威关系，不因写文档自动要求全量测试。
- 局部逻辑：定向测试真实风险；接口或 UI 路径变化增加相应边界验证。
- 权限、付费、迁移、并发、公开协议和生产发布：补对应专项证据，不以普通 build 或冒烟代替。
- 外部调用用本地桩，数据库测试用独立 `_test` / `_ci` 库。安全阀只控制部分路径，不能代替无真实凭证、桩服务与必要的网络限制。

目标行为和相关风险已有充分证据、适用 CI 通过且无未解决具体疑点后即交付；不为数量、仪式或“再保险”重复全套检查。失败要区分实现缺陷、环境限制和验证未执行，不把重跑通过改写成首次全绿。

完成汇报说明变更、证据、未验证项和残余风险。仅有方案、未接通代码或默认关闭且无人接通的核心路径不算功能完成；等待外部授权时明确标记，不伪造成功。

## 10. 秘密、兼容与文档权威

密钥只在后端受控配置中。避免读取或输出真实 `.env`、连接串、Cookie、请求头和供应商原始敏感响应；配置排障先核对变量名和布尔状态。不要把密钥塞进信源 JSON、审计备注或行业包。

兼容层和 rollout 开关仅服务已确认调用方或发布切换，必须单一权威、可观察、可删除，并有结束条件。退役同步检查入口、Worker、API、UI、配置、测试与当前文档；历史方案不构成恢复授权。

仓库文档内部的权威顺序：法律/安全/隐私要求 → 当前明确批准的产品决策 → 本文件 → 适用的已接受架构决策 → 对应领域手册 → 工程手册 → 历史审查/方案。用户指令和更高层运行规则优先。

README 与 AGENTS 是入口，不复制整套规范；发现冲突应核对运行事实并修正当前文档，不静默选择有利说法。历史记录保留日期与当时结论，不用“已批准”“审查通过”覆盖后续事实。不得把本规范再实现成新的评分平台、审批系统或机械流程门禁。

# AIHOT 工程手册

> 状态：当前执行手册。强制不变量以[开发原则](development-principles.md)为准。
> 按任务阅读，不要求每次执行全部步骤。下述代码事实核对于 2026-10-19；变更前仍以当前代码、配置和运行证据为准。

## 1. 任务入口与风险

先回答：谁遇到了什么问题？从哪个入口进入？事实在哪里？改哪一层能完整解决？如何证明，以及失败后如何恢复？

| 任务 | 优先阅读 | 最小相关证据 |
| --- | --- | --- |
| 换行业、品牌或分类 | `docs/customize.md`、`industry/README.md`、对应配置与调用方 | 分类/文案与真实页面；涉及 DTO 时检查 API/MCP。 |
| 筛选、摘要、翻译 | `docs/selection.md`、`editorial/`、`providers/` | 标注样本、身份/长度守卫、回执与中断恢复。 |
| 新信源或外部上报 | `docs/sources.md`、`sources/`、`ingest/`、`content/materials.ts` | 原始样本、URL/修订、信源归属、隔离与补采。 |
| 事件、热榜、报告 | `docs/grouping.md`、`events/`、`reports/`、`jobs/` | 归组/人工覆盖、来源参与语义、截止时间与并发。 |
| 网站、RSS、公开 API/MCP | `publication/`、`contracts/`、API 路由、web loader | 同一内容跨出口的资格、全文、撤回与缓存。 |
| 管理后台 | API `admin-auth.ts`、backend `admin/`、web `admin.server.ts` 与 action | 登录/CSRF、输入错误、重复操作、审计、真实结果。 |
| 排行榜 | `docs/leaderboard.md`、`leaderboard/`、对应入口 | 上游样本、连接性/最优解门禁、上一版可用回退。 |
| 数据库、部署、运维 | `database/migrations/`、`scripts/migrate.ts`、`docs/deploy.md`、`operations/` | 升级兼容、备份恢复、权限、健康与停止时限。 |

表中 backend 子目录均位于 `packages/backend/src/`。普通局部任务直接做；触及开发原则所列 B 类边界时，先确认调查结论与范围。不要把文档数量、模块数量或测试数量作为完成目标。

## 2. 开发环境与命令

Node.js >=24.11 原生运行可擦除类型的 TypeScript，ESM 相对导入沿用 `.ts`。不要新增后端编译流程或把 `.ts` 导入批量改成 `.js`。现有 npm lockfile 是依赖安装依据，需要安装时才用 `npm ci`。

本机开发与 Docker 的完整启动说明见 [deploy](deploy.md)。不要为文档任务重装依赖或重建镜像。不要执行会展开真实环境变量的配置/环境转储，也不要复制当前业务数据库连接串到报告中。

测试环境必须是专用、可丢弃数据库，不只是把已有业务库改个别名。运行迁移前先核对目标；迁移脚本本身不是测试库保护器。

以下是本地 PostgreSQL 的示意，按自己的非生产账号配置，不要原样当作 Docker 服务连接地址：

```bash
export DATABASE_URL=postgres://127.0.0.1:5432/aihot_local_test
export NODE_ENV=test
export AIHOT_ENVIRONMENT=test
export AIHOT_CREDENTIALS_DIR=/nonexistent-test-credentials
export COLLECT_ENABLED=false
export MODEL_CALLS_ENABLED=false
export FEISHU_INTERNAL_ENABLED=false
export FEISHU_CONTENT_PUSH_ENABLED=false
export INDEXNOW_SUBMIT_ENABLED=false

# 独立空库已创建并确认后，先迁移；需要主题数据时才 seed --topics-only。
node scripts/migrate.ts
# node scripts/seed.ts --topics-only

# 先跑与改动有关的一项。
node --test --test-concurrency=1 --test-timeout=120000 tests/materials.test.ts

# 跨领域修改或现有 CI 要求时再扩展。
npm run typecheck
npm test
npm run build -w @aihot/web
node --test apps/web/tests/*.test.ts

# 已启动的本地站点；只能证明该脚本实际覆盖的只读路径。
node scripts/smoke.ts --base http://localhost:3000
```

部分模型测试需要在隔离测试进程把 `MODEL_CALLS_ENABLED` 设为 `true`，同时设置假密钥并把所有相应供应商指向本地桩；上面的默认关闭值会使这类测试失败，不能据此判断模型实现有问题。不得为跑测试修改已运行服务的安全阀或填入真实模型密钥。参考 `tests/setup.ts` 和相应测试的桩设置，不从真实 `.env` 自动加载。

根测试共享数据库及预算，按 `package.json` 串行执行。web 部分测试依赖构建产物；只需要纯函数测试时不必重建。运行容器内评测时先核对输出目录可写，不要等付费调用完成才发现无法落盘。

## 3. 从入口追一条真实链路

### 3.1 采集到公开内容

```text
信源采集任务 / 受控 ingest
  → upsertMaterial（URL、身份、修订、回填）
  → queueProcessing（必要时提取正文，再分析）
  → prefilter → 两次 score + structure → understand / summarize
  → 持久化分析、校验修订和人工覆盖
  → 归组 fact/story、摘要与热度信号
  → publication 投影与 selected 变更记录
  → 网站 / RSS / API v1 / MCP / 搜索 / OG
```

这不是所有材料必走全部步骤的强制流水线：isolated、signal、历史材料、预筛阻断、缺正文与复用回执都有分支。修改前读实际分支，不把示意图写成第二个执行器。

### 3.2 管理操作

```text
后台表单/action → HTTP 客户端 → session + CSRF
  → 运行时输入校验 → 领域写入/入队 → 审计
  → 进度或明确结果 → 页面 revalidate / 失败后保留输入
```

核对 401、403、400、409、5xx 的语义，不能把普通输入错误伪装成服务器故障。检查重复点击、超时后结果未知、任务已入队但尚未生效的显示；成功 Toast 不能代替持久结果。

### 3.3 读路径

web 使用现有 `api.server.ts` / `admin.server.ts`，复用超时、取消与错误处理。普通读取和管理操作的时限不同，不用无限 fetch 覆盖。API 路由只组合领域读取，公开请求不得接通模型。

## 4. 改行业、提示词与质量

行业事实优先放 `industry/`，框架能力放 backend/contracts/apps。只有明确的复用问题才抽共享模块，不为单一行业特例改全局协议。

改站名、信源范围、分类、重要性定义、隐私和条款先取得使用者判断。`industry/pages/` 是模板，不是已完成的法律确认。

筛选现状：预筛 BLOCK 停止；评分两次，分别绑定尝试标识；阈值按来源等级来自行业配置。改阈值前用真实标注样本看误选、漏选与分层误差，开发集和保留集分开；示例 JSONL 不是生产质量基准。

标题/摘要守卫与来源身份锚定属于事实保护，不是美感评分；保留原文溯源和确定性降级。归组的四种关系、候选时间窗、人工独立/合并操作需要共同核对，不能只看模型置信度。

评测脚本会调用模型并写数据库/文件，不是天然只读。真实评测需单独确认模型、样本、次数预算、数据使用与输出位置，禁止凭“回执可复用”承诺重跑绝对免费。现有两条评测脚本在模型调用前检查 `AIHOT_DATA_DIR/eval` 可写；未配置数据目录时使用仓库的 `.data/eval`。历史 R6 及修复证据见审查记录。

## 5. 新信源与外部适配器

现有 kind 包括 RSS、网页列表、JSON 列表、X、公众号与 external，优先选语义匹配的现有入口。不要为每个站点新建队列或采集框架。

新增适配器只承担认证、抓取、分页/游标、限流、时间和媒体解析，将材料交给既有去重与入队能力；付费 API 同时接回执和预算。保留供应商原始 ID、规范 URL、来源时间、发现时间和必要的非敏感溯源。

必须验证：重复上报、修订、缺失/未来/过旧时间、首批历史数据、分页部分失败、超时取消、恶意 HTML/URL、暂停或隔离后的再入站。来源级别、一手标识、全文和参与模式由管理员/受控配置决定，不接受第三方 payload 自授权。

以将来的 Redfox 为例：

1. 先确定真实 API 样本、数据许可、鉴权与成本，再决定是使用现有 external 入口还是增加一个局部适配器。
2. 如果由第三方直接上报，绑定允许写入的来源，未知来源先隔离；如果由受控后端主动拉取，复用管理员配置的信源与材料入口。按实际信任范围处理，不为自有可信脚本预建逐来源凭证系统。
3. 映射为现有材料输入，交给 `upsertMaterial` 与 `queueProcessing`；不直接写分析、事件、publications 或入选状态。
4. 用本地桩证明去重、修订、回填、暂停/隔离、预算与恢复，然后才申请真实小流量验收。

这是接入边界示例，不是本轮实施计划；本轮不接 Redfox、不创建凭证、不开启采集。

## 6. 回执、任务与并发

### 6.1 付费请求

使用现有 `paidRequest`。检查 service/purpose/subject/identity/attemptTag 是否与真正工作流一致，响应先落回执再解析；协议有效但业务解析失败时，应尽量复用已存响应，避免重复消费。

预算通过数据库锁保护同一 service 的请求次数；新增 service 要核对迁移/配置中的预算是否实际存在。金额、供应商计费和本地请求次数并非等价，不能当作支付账本。

当前 unknown 回执超过 30 分钟可自动释放一次，再次 unknown 留给人工；这是允许一次潜在重复成本的恢复策略，不是 exactly-once 保证。分析阶段的回执放行会在同一事务中重置同修订的 failed 文章并入队；新修订、非 failed 状态和其他工作流不会被顺带重置。回执已放行仍不等于文章已处理完成，应核对任务最终结果。人工处理应核对供应商、业务状态和队列，记录非敏感理由，避免直接改库补状态。

最小中断测试覆盖与本次风险有关的节点：占位后未发送、响应已存但业务未提交、请求已发但结果未知、释放后任务重建、旧修订迟到、进程优雅停止。不要只断言回执一张表。

### 6.2 队列与调度

业务写入和必需入队共同提交时，复用带 `db` 的现有队列入口；失败不能留下“页面成功、实际没有任务”。设置 singleton、重试和超时须匹配业务身份，不要一律无限重试。

当前分析、提取、采集、归组、摘要有不同本地并发；pg-boss 连接和业务连接池也独立受限。`events.group` 本地并发 1 不保证多个 Worker 全局互斥。增加进程前先证明事件归属、热榜计算、报告生成和重复调度的跨进程语义。

`ensureQueue` 当前只创建缺失队列；改代码里的队列选项不等于已有数据库队列已更新。升级时读实际选项并设计迁移，不直接删队列清任务。

调度以当前代码与北京时间业务规则为准。日报窗口是前一天 08:00 到当天 08:00，报告候选还受公开时间约束；不能简单改成自然日 SQL。回填、延迟任务、截止边界、重复补跑和已发报告都要有明确策略。

### 6.3 停机与恢复

现有 Worker 停止等待约 195 秒，Compose 留 210 秒；缩短会把进行中的付费调用变成 unknown。部署工具、进程管理器也必须给出足够停止时间。

排障依次看任务运行记录/心跳、文章处理状态、回执与尝试、预算、队列重试、投影/重建进度和对外结果。不输出连接串或完整供应商响应。修复根因后只恢复受影响范围，不清空整库或全量重新采集。

## 7. 发布、隔离、全文与缓存

新增新闻出口从 publication 读取，不从 articles/raw 临时拼装。检查 visibility、eligible、参与模式、selected 与 visible_after；不要只检查 selected。入选快照/变更序列需保证提交顺序、水位和删除事件，不随意用时间戳替代游标。

权限变化逐层核对：

| 层 | 必须确认的结果 |
| --- | --- |
| 材料/信源 | 暂停、signal、isolated、人工撤回分别影响什么，是否仍允许新入站。 |
| 发布投影 | 全文撤销、资格变化、入选移除、延迟公开与批量重建进度。 |
| 衍生读模型 | 事件代表报道、来源名/头像/计数、热度信号、报告引用是否仍残留。 |
| 出口 | 网站详情/列表/搜索、RSS、v1、MCP、OG、快照/增量的同一权限。 |
| 缓存 | 应用内缓存、SSR、HTTP/ETag 和下游缓存的有效期、失效或可接受延迟。 |

必须区分缓存旧值和重算仍泄漏；历史 R3 属于后者，现有热度、参与者和头像查询已排除当前 isolated 来源。来源变更仍走已有异步重建，公开响应仍受既有缓存时效影响；不要把重建完成后的查询修复宣传成所有缓存即时撤销。强权限边界先在读路径保证，再用异步重建恢复衍生数据。

复用 `contracts/http-policy.ts` 与现有响应器，管理员 no-store、公开资源共享缓存的策略不可混用。304 也是公开响应，不能绕过权限变化。已有链接与历史报告的撤回语义需负责人确认，不盲删原始材料。

## 8. UI 与后台闭环

沿用 React Router loader/action、现有组件和样式体系。交互改动先明确入口、输入、提交、等待、结果位置、不变项，不把内部重构演变成擅自改版。

请求保持超时与取消传递；失败保留可恢复输入；成功后以服务端结果更新页面。登录过期、CSRF 过期、400 输入错误、409 冲突、503 暂不可用要给出不同且可操作的反馈。管理员写入必要时复用幂等机制，不能只靠禁用按钮。

收藏/已读/主题等浏览器本地状态不是跨设备后端事实。新增本地持久化时验证读写失败与旧值，不为它建设同步服务，除非需求明确。

真实浏览器主路径只验证本次改变的流程和相关状态；布局变化才增加对应视口，纯后端修改不机械拍整站截图。涉及原型忠实度或新设计时另按实际设计任务验收。

## 9. 迁移、部署与运营

### 9.1 数据库

复用 `db.ts` 的 postgres.js 连接池和参数化 SQL。`unsafe` 只用于可信迁移/已受控内部 SQL，禁止把用户输入直接拼进去。不引入 ORM 或每表 Repository 作为例行“规范化”。

当前迁移按文件名记录并逐文件事务执行，不能据此假设已有校验和、全局迁移互斥或自动降级。只允许一个迁移执行者；新文件追加在当前最大编号之后，不填历史编号空缺，不改已应用文件。

验证既要覆盖空库，也要按风险覆盖上一版有数据升级、锁等待、失败重跑和新旧程序共存。先扩展字段/读写，再回填和切换，最后经授权收缩；不可逆操作用 forward-fix 与已验证备份，不写虚假的 down migration。

### 9.2 部署与秘密

按现有 Compose setup → api/worker/web 依赖关系执行。archive 检出没有 `.git` 时如实记录来源与未知项，不初始化伪历史、不擅自拉取覆盖当前文件。

健康接口的数据库 `SELECT 1`、容器 running 和 setup 正常退出各只能证明局部状态；不等于任务已消费、报告已发布或外部集成可用。发布验收检查本次风险涉及的用户/运营结果。

`COLLECT_ENABLED=false` 不关闭图标刷新、预览、图片读取等所有网络路径；付费阀、推送阀也不能替代网络隔离。测试/演练使用假密钥、本地桩、独立数据目录和必要网络限制。真实开阀逐项授权，别用 `docker compose config`、环境转储或日志尾随暴露秘密。

备份代码已有 dump 校验、文件打包和对象存储上传；`pg_restore --list` 成功不等于恢复演练成功。本轮没有做真实备份上传或灾备恢复，后续相关发布应验证独立库恢复、文件关联与保留策略。

排行榜、监控、飞书、IndexNow、备份等可选功能独立确认配置与故障语义。排行榜上游失败或计算未满足发布门禁时保留上一版，不用空榜覆盖；首次无数据的预期 503 不应伪装成成功数据。

## 10. 验证选择与完成汇报

| 风险 | 优先验证 | 不能替代它的证据 |
| --- | --- | --- |
| 文档/局部文案 | 事实、链接、命令与差异检查 | 全量测试数量。 |
| 材料身份/修订 | 独立库下重复、修订与迟到结果定向测试 | 页面正常打开。 |
| 权限/隔离/全文 | 同一对象跨出口、撤回、重算、缓存验证 | 只测管理接口返回 200。 |
| 回执/成本 | 桩调用次数、持久状态、中断与重入队 | 只断言 receipt.status。 |
| 并发/迁移 | 多参与者竞争或有数据升级、失败恢复 | 单进程单测/空库建表。 |
| UI 提交流程 | 一条真实主路径及相关失败恢复 | 只有类型检查、Toast 或截图。 |
| 公开协议 | DTO/运行时响应、字段/游标/错误、真实工具调用 | 只有 listTools 或打印 ERROR 的脚本。 |

现有 CI 是发布证据的一部分：类型检查、web 构建/测试、独立 PG 的后端测试、站点 smoke、Docker 启动。不要无依据删除断言使旧路径“通过”，也不要把本地尚未执行的 CI 写成已通过。

完成时简要说明：实际改动、验证与结果、未执行或失败的检查、外部依赖/风险及必要下一步。审查以按严重度排列的可定位问题为主，不把重构偏好当缺陷。证据充分即停止，不为流程感追加平台、审批、评分框架或反复复验。

历史审查保留日期、证据、适用范围和未验证项。后续修复在对应任务中给出新证据，不能仅改审查措辞为“已解决”。发现规则与代码不一致时区分目标约束和当前偏差，修正正确位置，不复制成两套权威。

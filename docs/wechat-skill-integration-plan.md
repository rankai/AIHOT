# 公众号创作 Skill 接入方案

日期：2026-11-01。状态：方案完成、待实施；代码基线`0b464ba`。依据[小红书与SOP复核](reviews/2026-11-01-assistant-skills-review.md)和[接入标准第8节](assistant-skill-integration-standard.md#8-2026-11-01复核补充与运营启停方案待实施)。本方案不代表公众号已可执行或已有获批供应商价。

## 1 目标与首版范围

将[Redfox公众号文案创作](https://redfox.hk/skills/no/ecrh6uQj)接为`wechat-write`，沿用统一助手底座。综合入口支持快捷按钮、技能下拉和自动语义选择；公众号专属入口用同一会话页、输入区、费用卡、稿件面板和历史，不复制Agent服务。

首版完成：话题理解 → 热文查询 → 有依据的规律分析 → 必要材料/风格询问 → 完整公众号文章 → 持久稿件/继续修改；具体产品推荐增加基于已给材料的差异说明。产出保留上游标题、正文、观点、标签、规律与参考文章板块。会员费用与查询费用仍分开确认。

2026-11-01用户确认的硬边界：公众号与小红书均为研究驱动的创作，查询、规律分析、成稿必须串联。实施时复用小红书本轮建立的真实检索证据、持久分析及准确版本复用机制，按公众号的文章字段与分析维度做局部适配；不复制执行器，不照搬小红书样本数量或字段。仅载入提示词、调用过一次接口、保存了一篇文章，均不足以通过验收。分析结果需要可观察的规律摘要、真实样本引用及本稿应用说明，不采集或展示模型私有思考。

小红书v3本地验收见[研究核心记录](reviews/2026-11-01-xhs-research-core-acceptance.md)。公众号复用时同时保留两项边界：旧研究只能用于明确修改同一已选稿件，新建不得借旧分析绕过研究；分析参数出错可反馈纠正，不能将失败对象按成功结果解析而卡住恢复。有可用主题样本即继续分析、成稿，样本不足或文本截断不新增范围确认；如实说明实际研究范围即可。应用记录只保留分析身份和简短说明，不增加标题、正文、标签的逐字命中校验。公众号仍未实施或启用。

首版仅接文本输入（粘贴、TXT/MD累计最多10个、现有稿件引用），不增加公众号登录、自动发布、封面生图、OCR、网页任意抓取、Word/PDF解析、外部支付或批量营销。用户需要时效补充资料但当前工具无法取得时追问或标明缺口，不编造联网结果。

纯“查热门文章/分析规律”也是原包描述中的用途，但与其“必须最终输出文章”的规则存在冲突。首版只开放“公众号创作”动作；仅研究请求先澄清是否继续创作，或引导已有数据工具，不把文章收费流程用于用户只想查询的需求。独立研究动作另行定义交付和价格，不本轮顺手扩展。

## 3 用户路径与操作体验

1. 综合入口“公众号创作”快捷动作与下拉使用同一个actionId；自动模式由模型在已启用候选内选择。专属`/assistant/wechat`仅限制候选，复用`AssistantEntry`。
2. 输入需求/附件；平台和目标清楚就推进，缺少受众、产品资料或原规程必须的风格选择才询问。附件卡片和费用模式保持当前交互。
3. 创作报价来自现有`assistant-turn/assistant`价目；相同模型和限额可复用当前200积分/次创作或修改价（配置值优先，不硬编码）。用户已有有效会话自动授权时，父创作仍可自动确认。
4. 助手提炼并展示精简的查询建议：关键词、具体日期、一次查询的积分。公众号查询首版逐次人工确认；即使输入区选择额度内自动，也需明确提示“本次查询需要确认”。不能借小红书的旧search授权自动批准。
5. 已查询并取得可用主题样本就继续分析、成稿，说明实际样本数量和信息缺口，不因不足10条或摘要截断再弹范围确认。用户要求补充研究，或当前没有可分析样本且适合扩期时，才提出扩大到近30天并单独报价。查询未执行、失败或没有可分析样本时不交付材料稿冒充研究型创作；用户明确另选通用写作才走对应流程。用户指定日期时不自行扩大或换词。
6. 使用现有步骤列表显示已收到请求、已加载创作规则、等待查询确认、正在查询公众号热文、正在调用创作接口、稿件已保存。只根据持久事件显示，不虚构模型内部思考或全文阅读次数。
7. 稿件在右侧显示，手机用现有对话/稿件切换；复制/编辑/保存版本/引用继续修改沿原实现。后续修改只需已有稿件时不重复查询。

## 4 精确工具与供应商合同

拟定模型工具：`search_wechat_articles`。这是新静态工具绑定，不是`search_xhs_notes`改名。

| 项目 | 已知合同/实现要求 |
| --- | --- |
| 精确请求 | `POST https://redfox.hk/story/api/gzh/search/hotArticleNew` |
| 鉴权 | 原脚本为`X-API-Key`；现有通用client使用`REDFOX_API_KEY`请求头。须核实该端点接受方式，必要时仅对这个operation增加固定鉴权适配，不全局替换旧接口头 |
| 输入 | keyword（英文逗号合并）、startDate、endDate、source（服务端固定；接受值须核实，不由模型指定） |
| 关键词 | 创作规程提炼2–5个去重词，具体实体保留主体词；逗号合并后≤200 Unicode字符，服务端校验。用户只允许一个词时不得自行加词，先澄清或明确采用受限范围 |
| 调用数 | 多词合并为一次HTTP，不按词循环请求；7天→30天扩展是第二次HTTP，另一条报价/回执；每回合最多两次实际外发尝试，每个查询子任务最多一次，不自动翻页、换词或循环扩展 |
| 成功响应 | `code=2000`，`data.articles[]`；明确成功空数组可作为空结果，结构缺失不能当空结果 |
| 业务标识 | 当前代码未注册该精确端点。供应商正式operationId与价格待核实；必要时使用明确的内部稳定ID，不猜测Redfox文档编号 |
| 链路 | normalize/成本准入 → quoteTool → 专用批准 → 现有createSynchronousQueryTx → 既有同步查询operation → redfoxRequest/paidRequest → 安全结果 → 父任务继续；批准事实、子任务与activation关联同事务写入 |

当前普通公众号搜索`PW97QFBS/FVQ8D4W5`、10W+推荐、原创榜不是此端点，不能替代它却声称原skill已完整接通。已有provider适配可以复用运输、回执和结果存储；需新增该端点的输入及`articles`响应shape。

现有同步查询默认允许技术重试，不能原样继承后还承诺“最多两次”。首版对新端点明确关闭临时拒绝自动重试（429/500/503、4004等）和未知结果自动重发；在现有operation/receipt准入中限定每个子任务一次实际外发，并按父回合核验累计上限。队列重复投递或重放已保存响应不算新外发，也不得突破上限。限流/临时失败保留状态并提示稍后重新处理，未知结果先核对；不能把技术失败伪装成样本不足，借扩期再次调用。这是新operation的局部策略，不改变既有小红书及其他服务的重试规则。

### 4.1 时间与扩期

服务端用`beijingDate/addDays`，冻结业务日期、时区、用户显式日期、最终查询范围；模型不用自猜“今天”。上游脚本默认`D-7..D`，不足10条时`D-30..D`，endDate含今天；这与小红书的昨天截止规则不同。上线前核实供应商边界是否包含端点日期，前台显示明确起止日期，不能未经证据把它改称严格7个自然日。

最多一次7→30扩期；记录安全规范化后的原始/可用、去重样本数量。上游不足10条自动扩期在本系统不直接照搬：已有可用主题样本时直接继续，数量不足仅披露范围；用户要求补充研究，或没有可分析样本时才考虑扩期。只有用户未明确时间时建议扩大，扩期保留关键词和同一业务日期锚点，并取得这次查询的费用授权。默认窗口如果跨日等待审批，按冻结报价执行；过期/供应商窗口已不接受则重新报价，不静默改参数。

### 4.2 数据完整性

安全模型结果至少包含：来源ID、标题、作者、原文URL、摘要、发布时间、阅读数`clicksCount`、在看`watchCount`、点赞`likeCount`、评论`commentsCount`；评分只保留供应商明确提供的值，不把它当预测。缺失为null/未知，真实0保留0。

优先有效原文URL/供应商id去重；无id但有可靠URL不丢弃，无id且无可靠URL不作为可引用来源，并记录排除数。不用摘要补成“原题”；可将无标题条目标为未提供标题。最多向模型投影10条可用文章，另带原始数、去重数、投影数、截断状态、请求窗口和缺失字段；限制记录与文本字节数，超限明确范围。

该热文接口提供摘要，**不保证全文**。因此只能报告由实际标题/摘要支持的规律；没有读到正文时，不声称已分析完整段落、结尾互动或全文结构。六维输出中无法验证的项写“现有样本不足以判断”，并标partial。若以后要全文研究，可在有必要时桥接现有公众号原文解析接口，另行报价和验收；首版不隐式读取10篇全文。

## 5 包、入口、执行与稿件复用

新增`skills/wechat-write/`下manifest、运行规则、adaptation、受控数据参考和fixtures。skillId=`wechat-write`，首版模块=`write`；包注册、资源hash与输入/交付合同沿标准，初始运营状态关闭。上游付款段落、Python命令不能作为可激活的工具指令。

综合入口增加`wechat.write`绑定；专属profile=`wechat`与薄路由共用页面。需同步AssistantId、API创建/转交/历史过滤枚举、前端助手标签/导航，不另建会话表。自然语言平台不明才问，手动选公众号则候选限定为该模块；关闭状态在两个入口一致。

`load_skill/read_skill_reference/ask_question/save_draft`继续使用。只扩展必要的静态业务工具分发及activities类型，不在全局执行循环写`if skillId===wechat`的整套分支；交付规则按既有模块合同绑定。原小红书工具、规则与任务支持保留。

首版作品复用`text-draft`，不新增`wechat-article`数据库种类；原标题列表、正文、标签、sources、partial/scope都可承载要求。正文含核心观点、必要的差异化说明及规律来源；引用映射真实sourceId。界面名称可从持久activation元数据派生“公众号稿件”，只是只读投影，无法解析旧来源时保持原标签，不根据当前会话猜稿件类型。正文目前是安全纯文本显示，不宣称公众号富文本排版或一键发布。

交付合同要求：新建须有实际热文检索、相关可用样本、据此形成的规律及其在文章中的应用，再实际保存标题/正文/必要板块；可用来源引用真实且属于本回合。缺研究或不能分析时暂停，不能用partial材料稿代替研究型创作。有可用样本但引用/信息覆盖不足时直接生成完整文章，标partial并写明范围，无需额外接受范围的问答。服务端保留真实分析身份、来源及简短应用说明，不以标题/正文/标签片段逐字匹配验证应用。上游3–6个标题、约1500字正文、核心观点、5–10标签与2–3篇参考的规则保留；实际来源不足时如实说明，不能捏造引用凑数。具体实体的差异说明必须可追溯到用户材料/真实资料；后续修改可复用所选准确版本已验证的研究和分析，不强制重复检索。

沿现有每回合8次模型请求、24k输入/4096输出限制。先用最长合理稿件及两次检索fixture确认能装入；不能为了方案好看假定一定足够。若输出不足或缺必要材料，说明缺口或要求缩小范围，不静默截掉规则、不隐式追加付费回合。增加限额或改模型必须重新核对预算、价目和授权。

## 6 费用、恢复与后台管理

- 创作会员价沿现有配置；查询价必须与这个确切接口对应。现有普通查询20积分不是新端点已批准的价格。供应商成本未知时先阻止新付费查询，不以估算冒充实扣。
- `100积分=1元`为用户计价基准，会员套餐仍沿原配置；不从供应商支付宝说明推导会员价格，也不改套餐。
- 首次检索与扩期分别由用户人工确认；拒绝首次查询则暂停研究型创作，不能静默降为材料稿交付。已有有效研究但拒绝追加扩期费用时，按现有样本继续，除非用户明确要求停止。另选通用写作沿既有任务选择、报价及结算规程处理。父创作有有效授权不等于查询有授权。
- 一次新HTTP对应原receipt尝试机制和成本事实，operation、activation、用户归因连通成本中心；重放已保存响应不再外发。请求未知先核对，不能以“再次查询”换新身份掩盖重复收费。
- 已付费但返回未知、解析失败、部分交付等沿现有结算规程；供应商费用与会员积分不强行做一一相等。保存文本不证明所有收费项都成功，不承诺失败一律无费用。
- 公众号开关沿SOP的“允许新任务”；关闭不影响已接受回合、历史稿件和成本归因。启用前校验规则、接口、模型、价目、预算及验收。

### 6.1 用户已确认：余额不足只在后台提醒

把Redfox业务码3210/3201归为安全的供应商余额不足状态；前台只显示“数据查询暂不可用，请稍后重新发起”，保留原任务状态。后台现有`/admin/data-tools`的Redfox账户/服务区域提示“Redfox余额不足，请充值”，带最后发生时间、受影响父回合及积分核对入口；运行详情显示具体问题。不另建充值页面或消息平台。

复用受控回执和告警投影；现有client会把业务失败合并为通用错误，alerts按失败文本且至少3次才提示，因此必须补精确识别与单次明确失败提示。凭据无效、限流、超时不能误标余额不足。正常受控请求恢复成功可清理该观测提醒，用户刷新页面不触发付费余额查询。

不执行上游alipay-bot安装/付款/轮询；不展示cashierUrl、订单号、余额充值金额给会员或模型；不自动重跑失败查询。余额明确拒绝的响应已经落为`received`，现有resume会复用该响应，不能充值后直接重发。首版复用现有结案路径：后台停止助手父回合及未结束子任务，再到`/admin/tool-prices?tab=review`分别核对父创作单和查询子单，按实际交付消费或释放原预约（consume=0为全释放）；不以人工加积分代替。原回执与供应商费用证据保留，已结算/释放的旧任务不可恢复外发；充值后用户重新确认新报价，以新命令发起。未知结果须先核对，不能按明确拒绝直接结案。本轮不新增余额专用重试机制。

| D | wechat-write包、action/profile、查询桥接、稿件和进度 | assistant功能内模块、contracts、薄路由；query人工确认 |
| E | 桩闭环、异常恢复与已授权小规模真实验收，完成后管理员启用 | 新Skill默认关闭；待明确的供应商合同不靠猜测放行 |

## 8 验收与启用条件

1. 来源文件/hash、运行资源不含支付/安装行为；加载只允许当前候选/模块；恶意材料不能改变工具、价格或费用模式。
2. 泛话题与实体推荐、已有/没有风格参考、手动选skill与自然语言冲突、仅研究需求分别走明确路径。
3. 2–5词仅一次HTTP；词数/长度/日期越界拒绝；跨上海午夜冻结；7天不足后拒绝扩期、批准扩期、重复批准、30天仍不足都可核对。429/500/503、4004、超时未知、队列重复投递和手动恢复均不能突破每查询一次、每回合两次实际外发的限制；未知结果不自动重发。
4. 缺字段、零值、无id但有URL、重复项、超过10条、成功空数组、畸形响应均不伪造样本；摘要不被称全文。有可用样本但不足10条/文本截断时无需范围确认即完成文章；零可用样本不能交付，真实来源校验不能随字符串匹配校验一并删除。
5. 从API/Worker桩完整走加载、报价、人工批准、子任务、基于真实样本的规律摘要、稿件、积分、成本归因；无检索直接保存不得通过，分析缺失/无关样本不算完成，已有研究修改可复用。刷新/网络断开、响应已落库但稿件未存、未知结果、停止与批准竞态可恢复。
6. 旧XHS自动授权不能支付公众号查询；父创作自动确认仍可用；第二次扩期不能吃掉“一次查询”额度；后台关闭与提交竞态符合SOP。
7. 余额不足仅后台提醒，前台无充值信息；配置错误、限流和未知不能误分类。余额明确拒绝覆盖停止父子任务、分别核对父/子单、完整释放或部分消费、审计、旧任务禁止再执行、新报价；未知结果不得盲发，不能只核对子单就宣称整回合结案。
8. 桌面三栏和320/390px手机检查附件卡片、skill下拉、查询确认、长稿、来源链接与错误恢复；按项目适用CI验证，不重复成本中心性能测试。

正式开通前待核实四项：精确端点正式标识/鉴权及source；当前供应商成本与会员查询价；日期边界和真实字段样本；当前模型能否在限额内稳定完成所需流程。本轮没有新真实付费授权：此前累计模型36/37、查询3/3；公众号查询需另行批准新增预算。可先完成无外呼fixture，价格核实后再提出小样本次数/金额上限。

本方案自审：扩展复用现有运行时与账本，新增能力由明确业务工具承担；后台只有一个技能运营开关；付款流程不接入；全文研究、自动发布与自动多查询授权不作为首版隐含承诺。独立复审提出的三项已修订：余额拒绝采用既有人工结案路径、调用限额覆盖实际HTTP尝试、子任务创建使用真实的事务入口。每项未验证依赖均保留启用门槛，不把方案完成写成能力上线。

# 助手输入区增量验收（2026-10-31）

范围：技能下拉、TXT/MD 多选附件、当前会话自动费用授权，以及用户追加的输入框轻卡和简化报价。基线为 dev `53556784a0d12dbede74846065312ba70ad0f80b`，工作分支 `codex/assistant-v1`；保留既有未提交开发。已完成本地实现和本记录所列验收，未提交、推送或部署。

## 用户操作结果

- 欢迎快捷入口与会话技能下拉共用目录。默认自动选择，手动 actionId 由服务端限定候选并冻结；未开放技能不能变成可执行调用。
- TXT/MD 支持一次多选，当前提交累计最多 10 个，已选会话材料与新卡去重合计。11 个整批在上传前拒绝；失败附件占位、阻止发送，可移除或独立重试。复用私有素材上传、配额、身份与幂等链。
- 附件在输入框同一圆角容器内，轻量卡片排列，手机两列；点击预览纯文本，右上角 × 移除本次引用。实际验证预览、关闭、移除及计数变化。未发送附件不承诺刷新还原，移除不删除私有素材。
- 费用入口只有“每次确认 / 额度内自动”。切到人工直接关闭自动模式；自动设置主区仅保留额度、可选一次查询、价格及“取消 / 开启”，详细规则折叠，重新读取只在异常时出现。
- 人工报价显示“本次 N 积分”、可用积分及“取消 / 开始”。待确认时报价独占输入区；取消恢复文字和附件，焦点回输入框。实际验证九张卡和原文均保留。
- 实测 390×844、390×700 与 390×500 手机视口及桌面。短屏附件区滚动，页面无横向溢出；390×500 的报价卡底边为 488px，开始/取消完整可见。仅视口仿真，不宣称已在真实手机软键盘上测试。

## 业务与计费验证

使用 Node v24.19.0、新建独立数据库 `aihot_assistant_inputs_test` 和 `aihot_assistant_inputs_ui_test`（127.0.0.1:56483）。0089/0090 迁移只应用于这些任务测试库。测试使用本地模型和检索桩，未读取真实密钥、未写业务库、无新增真实供应商调用或支出。原真实联调的 28 次模型/1 次检索计数未改变。

浏览器走真实 UI → API → Worker → 稿件 → 积分账本链。合成账户初始 1000 积分，本次测试创作价 7、查询价 3，仅用于验收，不是正式价格变更：

| 通用创作，10 份附件 | 7 | 人工 |
| 通用创作，无新附件 | 7 | 自动 |
| 自动额度耗尽后明确人工创作 | 7 | 人工额外授权 |

自动授权沿原 quote/reserve/settle/receipt，父任务及查询共用原会员/预算边界。回归覆盖：严格技能候选、旧命令兼容、显式空材料、引用所有权/文件变更、价格漂移、撤销、历史累计、并发与重放、父子事务、人工额外授权、零价以及既有恢复路径。新增授权表不是第二套钱包。

## 同日独立复审与修复

本轮由主会话复查 UI 并最终验收，Astra Medium 复核费用/权限/恢复并实施已确认的边界修复。沿用同一任务分支及独立测试库；不部署，不改变正式价格、会员套餐或供应商配置。审查发现以下四项，均已修复：

1. **P1：停止未知请求后可再开任务。** 新任务只检查父 run 的活动状态，停止后可能绕过未知回执，并覆盖当前任务入口。现对同会话父/子任务关联账单的 current/result/retained 回执统一检查；仍有 pending/unknown 且未核账时，人工和自动的新报价/提交都硬拒绝。原命令重放优先返回旧任务，核账完成后可解除，不改写未知回执历史。使用独立数据库构造父/子 pending、unknown 与 retained/result 回执，验证任务数、占额、当前任务 ID 不变，人工核账后解除。
2. **P2：检索审批与执行器次数口径不同。** 审批只看子任务数量，执行器还计实际请求尝试；累计达到硬上限后可能仍批准无法执行的查询。审批及报价刷新现同时检查持久的 child_calls，超限不新建子任务或占用积分。
3. **P2：提交响应丢失后遇 4xx 会误给取消。** 新增冻结提交的单调未知结果标识，后续权限错误不能把已受理但未确认的任务当作确定拒绝；保留核对/原命令重试，成功后只清该提交、保留下一轮草稿。浏览器实际让首次提交成功后丢响应、第二次重试返回合成 403，再恢复原命令，确认不显示取消原提交/重新报价入口，只有一条持久需求与一次任务，新草稿保留。
4. **P2：320px 短屏底部裁切。** 附件错误提示与固定不收缩表单相叠加，会把底部提示挤出视口。输入表单改为可收缩纵向布局，附件区域滚动，文字输入和发送保留。320×568 的表单底边从 583.6px 回到 555px；320×400 的表单底边为 388px、发送按钮底边约 351px，无横向溢出。

新增实操还验证：上传成功但响应丢失后原命令重试能恢复为可用；空文件阻止发送、移除后恢复；欢迎快捷动作与下拉同步；手动 xiaohongshu-rewrite 随报价发送，取消后技能和原文字保留；欢迎页选“每次确认”不建会话，选自动后建会话但保留两个附件、原文与技能；320px 费用菜单没有越界。

本轮浏览器使用同一合成账户实际完成两次创作，均经多次原命令重试；余额由 969 降到 955（仅两次各 7 积分），未结占用仍为 0，新会话只有两个 turn，无新增真实供应商支出。调试中一次热更新导致内存草稿模块与旧组件状态不同步，稳定后重新输入并复测；未将热更新现象计为线上功能缺陷。

最终结果：本轮后端相关组合 35/35、全前端 431/431、全项目类型检查、前端构建及 diff 空白检查通过。费用提示末次改动仅补充刷新/联系管理员的操作说明。原始日志为 `/private/tmp/aihot-assistant-inputs-20261031/{backend-review,web-review,typecheck-review,build-review}.log`。

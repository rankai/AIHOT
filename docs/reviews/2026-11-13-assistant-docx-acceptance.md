## 第二轮完整复审

复审范围为 DOCX 方案与当前实现的对应关系、附件操作、TXT/MD 兼容、历史快照和计费恢复。继续由 Astra Medium 执行确定问题的局部修复，主审检查实际差异；浏览器补验由 GPT-6.1 Terra Ultra 执行。

发现并修复三项：

| 问题与触发条件 | 最小修复及验证 |
| --- | --- |
| 上传文件主名超过 200 字符时，原元数据截断会丢掉 `.docx` 等扩展名，后续预览/绑定无法识别格式。 | 只截主名，保留扩展名；205 字符主名的 DOCX、TXT、MD 均通过上传、文字读取与绑定。没有重写历史素材名称。 |
| 二级列表经 HTML 转纯文字后丢掉层级，父子项可能粘连。 | 在原转换步骤保留常规项目符号、顺序编号和缩进，沿用脚尾注分隔；不实现 Word 排版或复杂编号引擎。 |
| 文字读取断网、超时或收到非 JSON 网关响应时，附件详情可能显示英文底层异常。 | 在原附件队列统一为中文可重试提示；保留确定性拒绝的具体原因，重试仍复用已上传资产。没有新增请求框架。 |

本轮受影响的核心局部测试 **18 项通过**：附件集成 7、解析器 5、前端材料规则 6。backend/web/tests TypeScript 检查通过，差异空白检查通过。上一轮共用素材 7 项和未改动路径的证据继续沿用，不重复全量测试。附件集成再次覆盖重复受理返回同一任务、源文件变化后已受理任务仍使用冻结文字、保存稿件及原 7 积分合成结算。上传和预览不产生新的付费任务；没有修改报价、冻结、停止结算或恢复实现，也没有借本轮宣称重新验过完整停止/恢复矩阵。

主审另用当前安装的 Mammoth 1.13.0 自带公开样本做临时解析核验（未复制样本进仓库）：`single-paragraph.docx`、`simple-list.docx`、`tables.docx`、`footnotes.docx`、`endnotes.docx` 均读取成功，其 `docProps/app.xml` 标记为 Microsoft Office Word。`tiny-picture.docx` 只有图片，按预期拒绝为空文字；`strict-format.docx` 是 Strict OOXML，当前明确拒绝，须另存普通 DOCX。此证据补充普通 Word 样本，不代表验证过 WPS、所有版式或所有 DOCX 子格式。复杂中文内容仍由合成样本覆盖。

架构结论：仍是现有素材上传与助手输入能力的增量扩展；复用原队列、卡片、鉴权、存储、幂等和任务快照。没有新建文档平台、解析任务队列、计费服务或历史迁移，未发现需要新增抽象的理由。

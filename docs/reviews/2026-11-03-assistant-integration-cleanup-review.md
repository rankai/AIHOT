日期：2026-11-03。对象：`codex/generic-skill-integration`，基线 `dev@67a9a56` 加当前已有未提交改动。初次为只读代码审查及方案修订；随后已获授权实施，修复证据见文末§6。未访问业务库、调用真实付费接口、提交或部署。 本文不是 localhost:3000 的运行验收。

## 1. 结论与范围

现有接入仍有需要收口的地方，不能以此前主流程通过宣布整体清理完成。本轮检查综合/小红书助手入口、技能目录和启停、两项研究写作的激活/查询/分析/保存、报价与恢复、结果保留及文档口径；三个只读子审查分别覆盖入口、Skill 合同、计费与恢复，由主会话复核关键路径。

- 原 S0 四类遗留项继续保留；共用规则污染还包括全局系统提示，不另拆重复问题。
- 新增 **7 项现有路径问题（R1–R7）及 1 项新包配置准入缺口（R8）**。以下均有源码依据；R2另有纯 tokenizer 容量复现，R8尚未执行临时包加载/保存负例。没有把静态判断写成端到端实测。
- 程序与 Skill 的职责边界还需明确到具体判断：不能只移走提示词，却继续用措辞、写作意图或标题/标签个数阻断本来合法的任务。
- 修复均纳入[封面方案 S0](../xiaohongshu-cover-and-skill-selection-plan.md#12-前置阶段先梳理小红书与公众号的重复流程控制)，**先处理现有问题，再做 Skill 级选择和封面接入**。不新增规则引擎、工作流框架或另一套计费。

## 3. 新增问题与最小修复

### R1 正确的研究说明会被关键词规则拒绝

**触发：**全部互动指标缺失，模型如实写“接口没有给出互动数据，不能据此比较热度”。小红书要求匹配 `未知|未提供|缺失|未返回`，公众号要求 `未知|未提供|缺失|不足以判断`；这句正确说明两者均不匹配。

**依据：**`assistant/xhs-research.ts:89–90`、`wechat-research.ts:35` 抛出普通 conflict；`execution.ts:201–205` 只把 `DraftArgumentsError` 交给模型纠正，其他错误进入 `needs_review`。这是用词判断，不是真实性证明。

**最小修复：**删除语义正则门槛；缺失事实沿已有结构化样本和服务端 limitations 明确。保留真实样本、来源归属和字段结构检查。确定可纠正的输入错误回到现有工具纠正路径，不能把措辞问题当作待人工核账。

**最小验收：**一条等价措辞在缺指标时可继续，缺失限制仍显示，未编造数值；不为多个同义词复制测试。

### R2 公众号合法检索结果可能撑满上下文

**触发：**用户明确要求补充研究，已批准的两次查询各返回10篇、每篇1500字摘要。`providers/redfox/wechat-hot.ts:32–35`允许该规模；`assistant/wechat-research.ts:14–16`没有模型投影预算，`execution.ts:215–222`保存后将结果继续带入模型请求，`model.ts:25–27`在超过冻结24k上限时拒绝。已经取得的付费查询结果因此无法继续被分析。

**容量证据：**使用项目 `js-tiktoken` 的 `cl100k_base`，合规中文样例单次投影18,227 tokens，两次投影加当前公众号 `write.md` 为40,352 tokens；尚未加入系统指令、工具 schema、用户材料和分析输出。计算方式见§6。这是静态容量复现，不是一次真实助手执行失败记录。

**最小修复：**沿小红书已有有界投影思路，限制送入模型的摘要体积，为两次查询、规则、材料及后续分析预留空间；保留样本身份/数量、原始持久结果和截断说明。两次结果的整体预算也要验收，不能只限制单条摘要。不要通过更换模型、提高费用或丢弃持久结果掩盖问题。

**最小验收：**合法最大样本加两次查询，检查实际组装后的请求仍符合冻结预算且可继续分析；与现有材料上限组合检查受影响边界，不做性能压测。现有两篇短摘要桩不构成这个证据，公众号方案原已要求最长合理稿件和两次检索验收。

### R3 研究稿修改的意图与保存合同矛盾

**触发：**用户明确选定已有研究稿版本并要求改写，模型提供合法研究引用，按共享 schema 和小红书适配说明填 `intent:"rewrite"`，却被保存检查拒绝。

**依据：**`skills/xiaohongshu-creator/adaptation.md:10–12`允许旧版本研究复用、要求填写真实生成/改写意图；`store.ts:39`允许 rewrite；`xhs-research.ts:111`与`wechat-research.ts:59`一律要求 draft。已有复用测试仍填 draft，未覆盖这个组合。**不是所有修改都失败，而是合法 rewrite 路径存在冲突。**

**最小修复：**统一意图语义；选定准确旧稿、研究归属和版本检查通过的改写应能保存，不为修改重新检索收费。研究新稿仍须有对应真实证据，不能因为允许 rewrite 就绕开检查；普通 M2 改写仍不强制研究。不重写历史 intent 或旧包。

**最小验收：**复用既有研究稿修改用例，实际提交 rewrite；核对新版本、原分析关联及无新增查询，补受影响公众号断言，不复制完整套件。

### R4 查询参数错误被送入重复恢复循环

**触发：**模型提供六个公众号关键词或无效日期。`tools.ts:92`的模型工具参数声明比`providers/redfox/wechat-hot-contract.ts:6–10`宽；`prepareSearch`（`tools.ts:319–338`）直接 parse 抛错，未转换为可纠正输入错误。小红书无效日期也可进入同类路径。

**影响：**`execution.ts:154–156、42–58`把任务转为 needs_review；调用保留 pending，恢复重复使用同一参数，又失败。此时尚无检索报价/子请求，用户无法从批准入口拒绝来解决。

**最小修复：**模型声明与真实工具输入约束一致；仅将明确的、外发前参数错误送回现有纠正路径。不要广泛吞掉 conflict；权限、归属、余额、未知回执继续按原边界处理。

**最小验收：**非法日期/过多关键词可在原任务纠正；失败准备阶段没有外部请求、检索子单或查询扣分，不以重新购买父任务作为恢复方式。

### R5 长期暂停任务的已付费研究结果可能先被清理

**触发：**检索子任务完成后，父任务在保存分析前停止/等待超过30天。`providers/operations/store.ts:213–215`为结果设置期限；`operations/result-retention.ts:37–48`检查子任务终态及其他结果引用，没有覆盖助手父任务仍需恢复的关联。

**影响：**尚未吸收查询的父任务可能得到零样本（`execution.ts:187–192`）；已吸收但未保存分析时，两项 analyze 仍需读取原 `operation_results`，清理后找不到样本。用户已付费取得数据，却可能被迫重新研究。

**最小修复：**在现有结果清理器中补充仍可恢复助手父任务的必要引用保护，沿已有 tool call/child run 关系处理，不引入第二份长期全量原始数据或单独保留服务。终结且不再需要的原始数据继续按既有期限清理。

**最小验收：**完成查询→分析前停止→推进时间并执行清理→恢复分析，无新增查询/扣费；同时确认不再被需要的结果仍可过期。

**范围限制：**已经完成的历史研究稿通过 `source_snapshot` 和分析调用结果复用，不直接依赖未清理原查询，因此不是“历史稿件全部失效”。分析已保存但稿件尚未保存的任务也可能继续，只是部分来源元数据会退化；修复后应一并检查受影响来源展示。

### R6 转交弹窗的失效目标仍会提交

**触发：**打开作品转交弹窗并选中小红书，后台随后停用小红书，综合助手仍可用。`artifacts.tsx:536–539`实时过滤选项，但 target 只初始化一次；`:611–616`只判断列表非空，仍提交旧 target。`controls.ts:235–247`新转交仅检查 profile 存在，可免费建立已不可选的目标会话。

**最小修复：**失效选择明确提示并要求重新选择，不悄悄改成综合助手；对新的转交提交复用目标可受理范围校验，避免前端刷新/提交竞态。**先核对旧命令结果再校验新受理**，结果未知的原转交继续按冻结目标幂等核对，不能误伤既有转交和历史稿件。

**最小验收：**弹窗打开期间选项变化，不发送失效目标、不创建新空目标会话；桌面和小屏各核对这个受影响交互，已有转交命令仍可恢复。SSR 不替代交互证明。这是入口一致性问题，不是已发现付费越权。

### R7 归档后其他窗口不会及时更新

**触发：**两个窗口同时打开一个空会话或已完成会话，一处归档，另一处保持可见。`controls.ts:194–211`更新 archived_at/queue_paused，却没有写会话事件；`use-snapshot.ts:68–81`和`snapshot-poll.ts:9–12`对稳定、无新事件会话不重读快照。

**影响：**另一窗口仍显示可发送，可能走到报价后才由`sessions.ts:225`拒绝。服务端阻挡有效，未发现由此产生付费越权，但状态反映迟滞。

**最小修复/验收：**归档事务复用已有会话事件；另一窗口收到后禁用新发送并保留草稿。补事件与快照刷新定向断言、一次双窗口操作；不新增轮询服务、版本系统或归档管理页。

### R8 新包声明研究合同却漏绑分析能力，缺少准入检查

**依据：**`catalog.ts:26–33、140–143`校验字段枚举及 manifest/binding 对齐，却未检查研究交付合同与必要能力是否一致；`tools.ts:258、276–287`按分析工具存在与否决定保存验证，`:270`只比较合同名称。因此匹配了同一个合同字符串，不能证明配置真的会执行研究检查。

**负例形状：**复制公众号包形成独立临时 ID，改唯一 actionId，保留 `writing-input@1`、`wechat-research-writing@1`、`outputKinds:["text-draft"]`，但 tools 仅含 save_draft，capabilities 仅含 save-writing@1，scriptBindings 清空，并正确重算 hash、临时注册。必须清空 scriptBindings，否则现有脚本能力检查已能拒绝，不能将那个不同的拒绝当作研究合同校验已实现。

**证据边界：**这是缺失一致性检查的源码推导，尚未实际加载上述临时包或执行保存。**当前公众号配置正确，没有证据表明现有任务已绕过研究。**

**最小修复/验收：**对已有有限合同校验必需能力/输出一致性，并确保声明研究交付的保存不能落入普通保存路径；现有正例可用，漏绑负例在进入用户新任务前被拒绝。沿既有目录/交付校验实现，不新增表达式/规则引擎，不给旧小红书 v2 追加新合同要求。

## 6. 静态容量复现记录

使用 `js-tiktoken/getEncoding("cl100k_base")`；摘要为下句重复40次后取前1500字符（无代理对）：

> 当你面对复杂的工作任务时，先确认实际需求，再记录观察到的问题和团队反馈。不要急着照搬他人的经验，试着把目标拆成可以执行的小步骤，并根据结果调整下一步行动。

构造10项 `{id,platform:"wechat",operationId:"wechat.hotArticleNew",sourceId,title,url,text,authorName,publishTime,clicksCount,watchCount,likeCount,commentsCount,popularityScore,recencyScore,relevanceScore,totalScore,missing,textTruncated:true,textMeaning:"summary"}`。标题“职场成长中值得记录的具体问题与行动方法”、作者“案例作者”、日期2026-11-01，四项互动值1000/10/20/2；四个评分为null并列入missing，URL为`https://mp.weixin.qq.com/s/sample`加序号。

一次投影为 `JSON.stringify({results:rows,metadata:[]})`：18,227 tokens；当前`skills/wechat-write/write.md`：3,896 tokens；`projection + "\n" + projection + "\n" + rule`：40,352 tokens。重复投影仅用于体积计算；真实第二次结果会有独立ID，不能用此记录声称测过完整消息链、查询去重或实际模型响应。

此复现不读取凭据或运行数据，也不发网络请求。本次其余证据来自代码/既有测试内容阅读；未重跑数据库测试或浏览器验收。

## 已确认的问题

### R1 / P2：已消费的中间模型回执导致停止后无法自动释放冻结

- 位置：`packages/backend/src/users/credits-settlement.ts` 的 `deliveryFacts` 与 `settleTask`。
- 触发：完成 `load_skill` 等准备步骤，已通过 `saveResult/advanceRun` 保存并消费模型回执；尚未交付稿件/方案，用户停止；无 pending/unknown，当前回执为空。
- 原因：把所有 `completed` 和 `received` 回执一起算入 `receivedReceipts`，再把未交付但有该历史回执的创作项目判为未定。
- 实测：同样冻结 30 积分，未调用模型的对照停止后释放 30；已完成中间模型步骤的目标场景却进入 review，扣 0、释放 0、继续冻结 30。走真实 `controlTurn(stop)`，不是只模拟计算公式。
- 影响：没有多扣钱，但已知无需收费的额度仍需管理员人工核对；部分查询已交付但创作未完成时也可能无法自动结清。
- 最小修复方向：区分已消费的中间模型步骤与尚未提交业务结果的成功回执；保留 pending/unknown、未保存交付的保护，不直接忽略全部 completed 回执。补一个针对性回归即可。
- 证据：`/private/tmp/aihot-task-fees-20261103/stop-completed-model-repro-1793707123406.json`（核心合成库，0 外发）。

### R2 / P2：引用已研究方案直接生图，仍被不再需要的研究预算挡住

- 位置：`assistant/skill-policy.ts:skillHealth/skillAdmission`、`assistant/sessions.ts:snapshotInput` 与 `assistant/task-pricing.ts:taskPriceDefinition`。
- 触发：显式引用已拥有、已保存、含真实研究证据的封面方案，只要求生成一张图片；视觉预算已用完。
- 实测：真实隔离库已保存三套方案，新增生图预算和价目就绪，但 M4 候选仍因 `assistant.vision` 预算耗尽被排除；报价返回 `assistant_task_selection_required`。0 模型、0 图片外发。
- 原因：准入先对整模块全部研究能力作健康检查，之后才读取所选历史方案；后续定价虽然会去除检索/视觉收费项，却已无法到达。
- 最小修复方向：核对所选历史方案的归属/版本/可复用证据后，按本次实际收费范围检查必需依赖；全新研究任务仍必须检查检索与视觉预算。不提高或绕过已用完的预算来掩盖问题。
- 图片交付如通过现有独立图片技能复用方案原提示词完成，只能证明该路径，不算 M4 历史方案入口通过。

### R3 / P3：旧费用展示仍混入新总任务模式

- `apps/web/app/features/assistant/current-task.tsx` 的方案选择仍固定显示“选好后查看生成费用。”，但新任务已冻结生图上限，应提示选择后继续制作。
- `assistant/tools.ts:proposalQuote` 为任务内分配返回根 quote 的占位金额 0；`turn-cards.tsx` 仍将其显示为“当时查询/分析/生成报价：0 积分”。它不是新增钱包报价，也不表示子服务免费。
- 影响：账务没有因此重复收费，但与“一次确认”的用户理解冲突。
- 最小修复方向：新任务以现有根任务授权事实显示“已包含在本次任务中”，不展示占位 0 报价；旧任务保留旧独立报价。更新已有 SSR 断言，不新增另一套费用状态。

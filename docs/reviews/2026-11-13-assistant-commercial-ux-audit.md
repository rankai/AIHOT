# 创作助手商用体验评估与优化清单

日期：2026-11-13。评估对象：`dev@0bcebb5` 对应的 localhost:3000 创作助手、小红书助手及当前已开放技能。状态：只读评估，未修改业务代码、配置、数据或部署，未新增付费调用。

## 1. 判断

**现有助手已经具备收费创作工具的基本使用闭环，但尚未达到成熟 AI 创作网页端“新用户容易上手、长期使用好管理、异常时不困惑、交付后便于使用”的完整体验。**

限定在当前支持的文本材料、文章、笔记和单张图片任务内，可以作为有运营支持的商业初版使用。不能据此宣称已经达到 ChatGPT、元宝等成熟产品的整体体验水平，也不能把本地验收等同于线上稳定性认证。

当前差距主要在历史查找、异常解释、方案比较和作品带走。应先完善这些现有路径；不用再建设一套助手框架、钱包、任务编排或独立作品管理平台。

## 2. 证据与边界

- 浏览器操作交给按用户要求配置的 GPT-6.1 Terra / Ultra 子代理；主代理复核当前截图、代码能力清单与结论。模型名称来自任务配置，并非浏览器自行验证。
- 本轮实际查看 localhost 的新对话、技能菜单、材料入口、历史列表、小红书笔记、封面方案、异常任务；操作历史稿件复制。手机检查是 390px 浏览器视口模拟。
- 没有启动新的报价、任务、停止或恢复，不更改旧任务 64。异常页查看只能证明提示现状，不能证明本轮执行了退款或恢复。
- 当前界面问题用本轮截图支撑；既有五项真实任务、一次确认与结算结果仅作为已有功能证据，见 [真实任务验收](2026-11-13-assistant-live-ux-review.md)，不冒充本轮重新生成。评估基线为已部署的 `dev@0bcebb5`；早前部署记录不纳入这次 A/B 与 DOCX 提交。
- 实际打开了用户指定的 [元宝](https://yuanbao.tencent.com/chat/naQivTmsDa) 与 [ChatGPT](https://chatgpt.com/c/6aea9fa8-ca0c-83e8-8fbd-ea5100c68bbf)，未发送消息。参考观察包括具名能力入口和带简述的材料/工具菜单；未形成完整参考产品验收。元宝保存截图仍是主体加载态，主代理未采用；ChatGPT 本轮没有保存截图。因此不以它们论证完整视觉对标或性能优劣，也不收录私有聊天内容。
- 未覆盖真机软键盘、触屏、读屏、长时间使用或大量用户。无全量测试、性能测试和新的真实付费测试。

## 3. 已有能力应保留

目前不是只有一个聊天壳：新对话有六个快捷动作，既支持手选技能，也支持自动选择；附件支持多选、预览、失败重试和移除；有任务费用上限、余额不足提示、一次确认、停止与结算机制。

当前作品已经支持 Markdown 阅读、历史版本、人工编辑、未保存编辑保护、精确版本继续修改；图片有预览和指定版本下载。会话有归档/删除，历史支持按助手筛选与加载更早记录。不能把“无版本管理、无复制、无图片下载、无附件”重新列作缺陷。

既有真实验收记录中，通用创作、小红书写作、公众号、图片生成和小红书封面已交付；封面选择方案后直接生图、没有第二次报价。最近三项修复已经部署：完整封面意图识别、正文 Markdown 显示、旧取消提示清理。下一阶段不重复开发这些能力。

## 5. 优化清单

“先补齐”表示建议优先于扩大自助使用范围；“随后优化”表示高价值易用性完善；“按需扩展”不是当前商用的统一门槛。清单包含体验缺口和产品能力边界，不全部等同于程序缺陷。

| 编号 / 优先级 | 现状及影响 | 最小调整与复用 | 验收标准 |
| --- | --- | --- | --- |
| U1 先补齐：归档后可找回 | 有归档操作，但没有已归档列表或恢复入口。原 URL 仍能看，不代表普通用户能找到。代码确认，未归档真实会话。 | 复用历史列表、会话菜单、`archived_at` 和原归属校验，增加“已归档”筛选及恢复。 | 测试会话归档后能从界面找回、查看原作品并恢复；不丢历史、不新建任务、不产生费用。 |
| U2 先补齐：异常状态和操作后果 | 任务 64 提示等待核对、220 积分暂留，但输入框主按钮仍为“停止”；用户不容易理解停止是否退款、之后谁处理。 | 沿用已有任务状态、联系管理员与处理结果入口；用一句白话说明当前情况、可做什么和积分何时确定。停止继续放在输入框主按钮，提示须匹配已有后端语义。 | 用户无需懂“回执/冻结/核对”就能判断是否需要重发、找谁、哪些积分尚未结算；不承诺立即退款，不新增自动重试或二次确认流程。 |
| U3 随后优化：历史查找与命名 | 同主题标题截断后几乎相同；仅按助手筛选与创建时间排序。会话多后要逐条点开。 | 现有侧栏加关键词搜索、会话重命名和轻量时间信息。搜索扩展现有列表接口，不只筛前 50 条，也不新建搜索服务。 | 能找到早于首批 50 条的指定会话；改名不改需求、作品或计费记录；小屏长标题可区分。 |
| U4 随后优化：三套方案便于比较 | 已有结构化方案，但布局、配色说明较长；390px 一屏难以比较三套。 | 每套先显示已有信息的短摘要，如风格、布局、配色，详细说明继续折叠；保留研究依据和提示词。不足以可靠提炼的旧方案保留原文，不用额外付费模型批量补摘要。 | 用户可以先看出三套差别再展开细节；选择仍指向原方案、原任务和原费用授权。不开三次生图来做缩略图，也不把占位图冒充方案效果。 |
| U5 随后优化：文案拿走就能用 | “复制文案”可用；备选标题不随正文复制，Markdown 原文复制到其他编辑器可能保留标记。不是复制失败。 | 复用现有作品/精确版本：主操作复制可读纯文本，菜单提供原格式、单独标题/标签及 TXT/MD 下载。先覆盖常用动作，不堆一排按钮。 | 复制及下载与所选版本一致；不把未保存编辑误当已保存作品；在普通文本框实际粘贴检查。公众号富文本排版另行验证，不承诺复制就能完整同步发布样式。 |
| U6 随后优化：用户语言与能力说明 | 历史回复有“加载创作技能模块”“冻结范围内的第二个关键词”等；新对话虽有快捷动作，但缺少选择后的示例和简短交付说明。 | 在现有能力元数据/提示词和用户状态投影中，用“查找相关笔记”“换一个关键词继续查找”等行动语言；选定动作后给一个可编辑示例或一句帮助。历史对话可就地发现小红书的写作/改写/封面能力。 | 不要求理解 Skill、M1/M2 或接口；一次选择可继续输入。不拆分小红书 Skill，不增加必填向导，不过滤或重写已保存历史文本。 |
| U7 随后优化：图片细节检查 | 已可在作品面板预览与下载，尚无独立放大/缩放入口；手机检查封面小字不便。 | 复用现有受保护图片资源和弹层，支持点图放大、关闭返回原位置；下载继续用精确版本实现。 | 看清图片小字，退出后保留阅读位置；失败可重试，不变成新生成请求，不改下载或费用链。 |
| U8 按需扩展：常见材料输入 | 仅 TXT/MD，链接作为文字，用户要先转格式；限制广泛办公创作场景。 | 按实际客户材料优先补一种常用格式，通常先 Word/PDF 文本；复用附件卡、上传、私有存储和权限。用户图片理解与 URL 正文读取分别定界。 | 格式、处理结果、提取失败和费用说清；服务端真的解析后才向模型传递。不能只修改文件选择器，不能声称支持扫描 PDF 或任意网页。 |

费用入口的当前位置和下拉形式已经满足既定设计。当前不建议再移动入口或重做授权：任务范围、预计最多积分、余额缺口、结束后的实际扣分仍应来自现有报价和账本。U2/U6 主要改善用户如何理解，不改会员价格、冻结上限或结算规则。

## 6. 对话流畅度与动效

已有自动刷新、真实执行步骤、发送/停止切换、排队和“有新进展”入口。既有验收记录显示用户上翻阅读时没有被完成消息强行拉走。当前没有充分证据支持再重做轮询或换一套聊天框架。

下一阶段应针对长任务检查：正在执行哪一步、需要用户回答还是后台等待、完成后去哪里、失败后如何继续。用真实事件更新轻量状态；减少重复的过程说明，默认展示有用进展。不要模拟思考链、虚构百分比或为了动效多调用模型。

本轮没有重新跑进行中任务，因而不宣称动态等待、所有网络中断和真机键盘体验已全面合格。只在对应交互修改后做核心局部测试和受影响页面操作，避免再次重复五条付费链。

## 7. 可以后置的扩展与独立观察

- 跨会话作品库、文件夹、标签：先用 U1/U3 解决找回与搜索，观察是否仍有真实管理障碍，再决定单独作品库。
- DOCX/PDF 导出、公众号富文本发布、跨平台一键发布：有价值，但涉及格式或账号授权；不属于当前商用体验必须全部补齐的条件。
- 参考图、图片局部修改、品牌模板：需要真实工具能力，不能只加入口；与简单图片放大分开排期。
- 版本差异对比、协作审批：已有版本与未保存编辑保护，暂不为个人创作使用增加协作系统。
- 内容质量单样本：本轮查看任务 68，用户要求约 300 字，正文约 455 字，并出现用户未提供的“我这两天在用”。记录为交付质量观察，不推断所有任务都存在，不在本轮改模型或新建通用质量门禁。后续若处理，先在对应 Skill 校准长度和事实表达。

## 8. 建议执行顺序与收口

1. **先完善历史与异常理解：U1、U2、U3。** 解决“东西去哪了、现在该怎么办、积分会怎样”的日常信任问题。复用现有列表、控制菜单和状态，计费/恢复机制保持原样。
2. **再完善比较与交付：U4、U5、U7，并在涉及页面中完成 U6。** 不新增另一层作品平台；保留精确版本、编辑保护与原授权。
3. **最后按用户材料决定 U8。** 不把所有格式、发布平台和图片编辑一次性装进本轮。

局部验收围绕每条标准；没有代码变化时不重复全量测试。发布到更广泛用户前，补一次真实手机软键盘和触屏操作，并让不熟悉系统的人独立完成现有任务，记录卡住点、需要解释次数和找回/导出成功情况。不是新建埋点平台，也不是再加一批泛化测试。

收口不使用“达到商业级 90%”或“无任何问题”这样的无依据数值和承诺。依据用户能否理解费用、独立完成任务、找到旧作品、清楚处理异常和带走结果判断。

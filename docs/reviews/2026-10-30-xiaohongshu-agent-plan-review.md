日期：2026-10-30。对象：[接入方案第三版](../xiaohongshu-agent-integration-plan.md)与[技能接入标准v1](../assistant-skill-integration-standard.md)。范围：完整上游Skill静态审计、当前系统映射、组件兼容性，以及统一底座/多入口、技能路由、执行/费用/恢复/交互设计。没有实施业务功能。第1–5节保留首轮调查和评审，第6节记录多入口扩展，第7节记录快捷动作、模块复用和标准化接入复核。

## 6 第二轮：统一底座、多助手入口完整复审

### 6.1 用户确认与本轮设计

用户确认的产品方向为“统一底座、多个助手入口，同时保留综合入口”，首版先做创作助手和小红书助手，考虑公众号等后续扩展。本轮授权仍为修改方案和评审，不修改业务代码。各项具体合同如下：

| 决策 | 第二版明确的行为 |
| --- | --- |
| 共享能力 | 一套会话协议、Worker、模型适配、工具、积分、回执和作品存储；多个助手是版本化配置，不是独立Agent部署 |
| 首版综合入口 | creative：用户给定材料的提纲/起草/改写使用自有general-writing；明确小红书需求时选择已接入模块 |
| 首版专属入口 | xiaohongshu：默认小红书平台与规程，复用同一小红书模块、工具、模型和价格策略 |
| 能力真实范围 | 阶段A只开放通用写作和M1子集/M2；后续模块按阶段启用。公众号专属能力不首发，可由用户选择标注清楚的通用稿 |
| 身份与版本 | session的assistant_id不可变；quote冻结profile/候选模块/输入/模型/限额；turn及model step继续冻结实际执行内容 |
| 模型路由 | 需求+上下文+候选目录决定技能；含糊时澄清；发生在已报价回合内，共享8次真实外发额度；GET和转交不调模型 |
| 权限 | profile与激活模块共同限制工具，叠加当前用户权限及能力开关；选技能、换入口、旧版本快照均不授予额外权限 |
| 跨助手继续 | 显式选定稿件/brief，新建目标会话；不迁移财务授权、在途任务、待批准动作或完整聊天 |
| 后续扩展 | 新增受审阅profile/skill、必要工具和作品类型，经验证启用；不复制底座，不把公众号采集当作公众号账号写入 |

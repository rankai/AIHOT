## 1. 接入后用户得到什么

仍然只有一个 **「小红书创作」Skill**，同时出现在创作助手与小红书助手。新增三个用途，不新增助手窗口或三个独立 Skill：

| 用户动作 | 原模块 | 完整任务及交付 |
| --- | --- | --- |
| 起标题 | M3-A | 查询同主题爆款标题 → 分析标题规律 → 生成 10 个候选，附参考、推荐理由和编辑参考匹配分。 |
| 评标题 | M3-B | 查询同主题爆款标题 → 六维评价 → 综合分、问题说明及修改建议。支持一个标题，或同主题最多 10 个标题比较；跨主题先选定本次主题。 |
| 检查违禁词 | M5 | 对用户确定的文字调用 Redfox 检测 → 标记实际命中 → 给出逐项替换建议 → 交付最小修改文案与可下载文本。 |

用户可以点击现有用途入口，也可以直接描述需求，由当前任务识别选择。技能下拉仍只列「小红书创作」，这三个用途沿用 Skill 内的快捷动作，不在全局下拉增加三个同名技能。需求明确时直接准备任务报价；已有原文、主题或已选稿件不重复索要。M3/M5 的编号只用于代码和后台说明，不出现在普通用户操作中。

首批 M5 输入覆盖：粘贴文字、当前会话明确引用的作品版本、现有 TXT/MD/DOCX 附件。**一次任务检查一份明确文案或一个文件**，沿原脚本 content/file/url 互斥且一次一份的范围；不新增跨文件拼接、位置映射或批量文档任务。助手仍支持累计上传最多 10 个附件；有多份且未明确检查哪份时，在报价前复用材料选择明确本次对象，不默默只检查第一份。DOCX 仅检测已有提取文字，不包括内嵌图片。单份检测文字最多 10,000，原附件大小与解析限制不变。

**明确不随本次开放：**图片 OCR、网页正文提取、DOC/PDF、新的图片上传、自动发布、扫描所有历史稿件、持续监控。原 Skill 有图片/网页入口，但当前宿主没有相应输入能力；不能检测 URL 字符串后声称已检测网页。

**复合任务边界：**本次完成三个独立用途。当前任务合同只选择一个模块，暂不增加“写笔记＋评分＋检测”任意串联引擎。用户一次要求多个模块时，报价前明确选择本次先完成的用途，其他用途在结果上可引用继续；不能静默漏掉要求、自动拆成多个收费任务，或执行中再弹第二次报价。后续若确需一次任务串联多个模块，单列交付范围与费用评审，不靠扩大候选权限实现。

## 2. 原 Skill 与现有实现核对

### 2.1 原包依据

使用已归档的 Redfox 原包，来源页为 [小红书创作 Skill](https://redfox.hk/skills/no/gwE5gmpt)，仓库提交 `d2e24f02340a440a73a96aa6ad6a65f681fba89f`。完整来源与文件摘要见[原包清单](reviews/2026-10-30-xiaohongshu-skill-manifest.json)。本次读取的 `title_score_guide.md`、`xhs_trend_data_format.md`、`prohibited_word_core_workflow.md`、`fetch_xhs_trends.py`、`check_sensitive_words.py` 与清单 SHA-256 一致；没有执行原 Python 脚本，也不宣称这是 11 月 17 日上游最新版。

实施前的 v9 包虽保留完整原 `SKILL.md`，运行模块仅 M1/M2/M4，缺 M3/M5 的执行绑定及对应参考资源。完整原文存在不等于能力已开放。

### 2.2 不能直接复用的细节

1. `providers/redfox/xhs-covers.ts` 会丢弃没有安全封面 URL 的数据，且面向看图裁剪标题；M3 只需要标题，不应被这些封面条件过滤。共用四类响应 schema 与指标解析，保留独立标题投影，不把 M4 的筛选条件改成两用。
2. 同一聚合端点在既有真实联调中验证的关键词上限为 **含逗号 30 个 UTF-16 单元**；原脚本写 200。M3 沿用实际限制，最多 5 个去重关键词，不静默截断或拆为额外付费请求。
3. 旧通用违禁词 operation 的本地输入为 content、最多 2,999 UTF-16 单元；该旧分支保留。2026-11-18 M5 真实回执确认小红书分支单次实际最多 2,000（含重叠），须使用 `X-API-KEY`、固定 platform/source 并在外发前校验，不能照搬原脚本或旧通用分支上限。
4. 当前高亮清理仅接受 `banned-word`、`industry-banned-word`；原 M5 还识别 `sensitive-word`。新投影须覆盖三类，仍不直接渲染供应商 HTML。
5. 当前 binding 每种收费能力最多 2 次，任务交付只有 writing/plans-only/image；作品只有文字、笔记、封面方案和图片。M5 长文、M3 报告需要有限合同扩展，不是“只加 Markdown 就能上线”。

## 3. 用户流程与费用交互

共同路径：**选择用途或描述需求 → 确定材料与范围 → 一份任务报价／授权 → 执行 → 查看结果**。默认自动／可选每次确认沿用现有设置，不恢复逐接口确认。

- 起标题：输入“给通勤防晒霜起 10 个标题”，或引用已有笔记要求起标题，提取明确主题即进入报价。泛词仅在缺乏可用方向时询问；不声称已查热点来包装未经检索的建议，不自动搜索 10 个方向。
- 评标题：粘贴标题或引用稿件，自动提取主题；同一主题可比较多个标题。不要把 M3-B 的“合规安全性”模型评分说成已调用 M5 检测。
- 检查违禁词：明确本次一份待检测文案，不把需求指令、历史聊天或所有附件默认拼进去。摘要展示所选文件或稿件版本、文字量和全文/部分范围；只检测原文，不先让模型润色再查询。正文同时含 URL 时仍可检查这段文字，但只有 URL 或用户明确要求检查链接页面时，应提示粘贴正文，不能把 URL 检测冒充网页检查。
- M5 范围、批次数与“文案将发送至检测服务”放在现有任务说明，首次调用前可见，不仅藏在折叠详情里；手动模式一次确认，自动模式沿当前发送授权，不另建隐私确认弹窗。用户明确拒绝外传则不调用。后台保留实际供应商归因，前台不暴露凭据、operation ID、回执号或 UTF-16 技术术语。
- 长文默认按用户要求的全文准备分批计划，并在报价中写清“检查全文，分 N 段”。若用户要求只查前段，在同一报价准备中选定范围；不额外加“是否允许分批”弹窗，也不静默只查前 2,000 字。只查部分时默认可见“仅检查所选部分”。
- 积分不足时不受理执行，保留输入、附件和所选用途，沿用现有查看积分入口。范围或材料变化使报价失效，沿原请求重新准备；已经授权的任务内分批不再报价。
- 执行步骤只显示真实业务事件，例如“查找参考标题”“整理标题建议”“检查文案 2/3”“检测报告已保存”。不制造虚假进度百分比或暴露内部推理过程。

## 4. M3 标题能力

### 4.1 查询与分析

新增受控能力 `search-xhs-titles@1`（命名为拟定），复用固定 Redfox 聚合端点，使用标题用途的固定 operation 标识 `xhs.titleResearch` 区分 source、回执和结果投影；沿用 `redfox.query` 预算。它是已有供应商适配器的一项操作，不是新 Provider 或重复 HTTP 客户端。

生成默认 D-7 起查，M3 指令根据真实同主题样本是否足以分析，必要时在同一授权内同词扩到 D-30 一次；评分默认 D-30，最多一次。原评分指南“小于 5 条时提示样本较少”只用于如实展示，不再借用为 M3-A 强制追加收费查询的程序阈值。扩期为空时保留首查可用样本，只有本任务已完成的所有标题查询均无可用样本且查询额度用尽时才以无样本结束。服务端只限制已批准的日期、同词扩期一次、前次查询已明确完成及总次数；不增加新的内容质量状态机。原任务范围禁止扩期时，少量样本如实说明，零样本结束。

报价时冻结用户主题、日期、全站/主题范围和最多查询次数，不为提前生成关键词再增加一次模型调用。具体关键词由 Skill 在首次查询提出并保存，服务端校验数量及 30 单元长度；扩期沿用首查规范化后的原词。日期沿用 Asia/Shanghai：D-7／D-30 起查，数据有效范围以供应商实际返回为准，不声称包含今天的实时数据。用户明确禁止扩期则只查一次；服务仅支持 startDate，不伪装支持任意 endDate。用户要求不可满足的精确截止范围时，报价前说明限制，不能静默放宽。全站热点只在用户明确要求时允许空关键词，不能以空值代替缺失主题；单独按实际接口合同验收。

四桶原始数量、去重后有效标题数、实际纳入分析数分别记录，不能混用。候选需真实 photoId 和非空标题，不要求 coverUrl；跨桶重复保留来源归属、分析只计一次。缺失互动值保持未知，`w+` 保留近似展示，不能变成精确统计。参考链接从已保存数据构造，不让模型编造。

复用现有有界投影方式：每桶至多 20 条、合计至多 80 条，并按模型输入预算再限量；标题尽量完整，不能把已裁剪标题当完整标题评分或判重。原始响应仍存回执。上下文只携带本任务必要样本、结构化结果和引用，不反复塞入整份历史或完整四桶响应。

模型按 Skill 总结结构、主题、利益、情绪等规律，不展示内部思考。保存结果时同时保存简短规律摘要与实际引用，默认折叠。服务端只核验本任务已有成功查询、引用归属与交付字段；不写固定“思考阶段 1/2/3”状态机，不把 M3 规则放进共用 `save_draft` 提示词。

无有效样本时，结束并说明“未找到相关参考标题”，保留查询结果，释放未交付的创作费；不能自动降级为无研究的标题生成或捏造六维评分。少量有效样本可以继续，但说明本次参考范围有限，不为凑数量换题或追加第三查。

### 4.2 输出与评分适配

M3-A 交付 10 个不同候选、逐条理由与参考。标题按 Unicode 码点计数不超过 20（含标点；组合 emoji 可占多个，前端统计同口径），验证数量/长度，不以代码给内容质量打门槛。原包限定具体产品形态、不混入其他品类的规则留在 M3 指令，不能为了凑样本把“防晒霜”扩成“防晒衣”。

M3-B 每个标题保留六维分数、理由、加权总分与等级。维度分为 0–10，服务端按 **15%、20%、25%、20%、15%、5%** 计算总分，再统一取一位小数并按显示值确定 S≥9、A≥7、B≥5、C<5，避免显示 9.0 却标 A。S 级说明亮点及参考，不强制修改；A/B/C 级给主要问题、2–3 个修改版本及适用场景。实际参考不足 3–5 条时按实际数量展示，不造样本。对照多标题时共用本次主题研究，不新增逐标题查询或收费项目。

沿用早期[主方案 §2.3](xiaohongshu-agent-integration-plan.md)已明确的适配取舍：

- 不强制候选“匹配指数只能 8–10 分”或为了不重复分数造差异；可展示 0–10 的编辑参考匹配分，注明不是点击率或流量预测。
- 标题与样本重复时显示重复提醒，不直接给 S/9.5+；六维评价仍正常进行。
- 不将 S 解释为“流量 Top10%”或承诺爆款。样本统计只允许基于真实样本与明确分母。
- “合规安全性”仅为模型编辑参考，未调用 M5 时不标为词库检测通过，也不自动追加收费检测。

上述差异写入 M3 的 adaptation，原文归档不改，不把我们改过的行为称为原 Skill 原样执行。

## 5. M5 检测能力

### 5.1 原文与分批计划

报价前复用现有材料快照，在任务范围中保存本次文案的来源引用、精确版本、文本摘要和覆盖范围；这是本次需补的有限能力，不是现有报价已经支持。

- 粘贴文字取用户明确要求检测的原文；有说明与正文混排时，只接受能与原消息唯一核对的原文片段，不让模型重写后再检测，也不要求模型计算字符偏移。无法确定则复用现有澄清入口。
- 附件取该输入 ID 的完整提取文字；已有作品按指定版本取发布文案的标题、正文、标签，排除候选标题列表、研究附录、参考链接和系统提示。复用 `projectArticleVersions` 的历史正文投影，文本组合规则由服务端确定、供前台预览，不能直接检测作品 JSON。报告引用须明确取“原标题／候选标题／建议修改稿”，不能把整份检测报告再当正文。
- 当前代码在 `inputIds` / `artifactVersions` 未传时会带入历史材料；新检测路径必须保存明确的单一对象及来源选择，不能把这个旧默认值解释为“用户授权检查全部”。先校验会话及材料所有权。检查当前编辑稿时沿用“先保存再继续”，取消保存不外发，不拿旧版本冒充当前输入。

同一个原文来源只保留一份权威快照；批次计划存范围与摘要，发送文本从该快照派生，不另存多套可变正文或建立材料库。正文、来源版本或范围变化必须使未接受报价失效；任务受理后修改其他稿件不改变这次冻结原文。

单次小红书检测内容遵守真实接口 **2,000 UTF-16 单元（包含前文重叠）**限制；总范围最多 10,000，超限在任何检测外发前提示缩小范围，不静默截断。前台沿现有字符统计作简短说明，内部按统一口径冻结、计价与验证，不照搬 Python `len()` 的不同计数方式。

≤2,000 单元一批，不为加上下文把原本一批的短文变成两批。长文在报价前确定所有批次：非末批核心区间为 1,700–1,800 单元，优先在该范围内的自然句界切分；后续批附带前一核心区间末尾至多 200 单元原文，降低边界切词漏检。边界避开代理对，最终每次请求仍须≤2,000；末批可更短。核心区间完整覆盖且不重叠，单份 10,000 单元最多 6 批。该固定切分办法只服务现有接口长度限制，不建设跨文件切分或可配置的切分引擎。

命中换算回原文位置后去重；重叠区域中的有效命中仍计入，不能因它在前一批的核心区间而丢弃跨界词。相同位置不重复计数或修改。每批仍是一次真实查询，重叠文本已纳入报价前的实际批次计划，不再额外加收按字费用或临时扩充授权。批次位置、文本摘要及计划算法版本固定，刷新、恢复或模型改参数不能重分片或重新计价；有未决批次先暂停，不跳过继续买后续查询。重叠仅降低切词问题，不承诺覆盖所有长度的词语或平台审核规则。

这属于输入完整性和外呼限额控制，不是复制一套由程序控制的写作流程。原 Skill 的“长文先选范围”合并到现有报价准备，技术上的多批不增加多次费用确认。

### 5.2 检测接口与结果证据

沿用 `API_1791881343238` 的 query operation。输入增量增加可选的固定平台枚举：旧调用不传时保持原请求与回执身份；助手 M5 必须显式传“小红书”。该分支由适配器注入固定 source「小红书违禁词查询-xhs」并使用原 M5 的鉴权头，不能由模型传任意 platform/source/URL/凭据。平台语义必须进入回执身份，不与旧的通用检测缓存混用。

复用 `media-tools.ts` 的响应校验与清理，形成可追溯的命中区间、词语及类型：

- API 业务成功、原文字段、标记内容缺一不可。缺字段、原文不一致或解析失败不解释为“无违禁词”。原始响应留在原回执，不透传给前端。
- 识别 `banned-word`、`sensitive-word`、`industry-banned-word` 三类标记；解码后与实际请求内容核对，生成安全文本及位置。页面用 React 文本节点加粗命中，不执行供应商 HTML。
- 区分同词不同位置与去重词数。英文子串误报按出现位置处理：可解释地标出疑似误报并保留原始命中，疑似误报不自动改正文；不能像原脚本那样因为另一处较长英文词包含该子串，就全局删掉所有同词命中。独立出现的同词仍保留有效检测结果。此差异必须留在适配说明和样例中。
- 没有检测回执时不得由模型伪造“已检测”。零命中是有效检测结果，展示“本次未检出”，不声称保证过审。

每批通过受控工具 `check-xhs-words@1` 调用同一供应商能力，引用已冻结批次而不重新传任意文字。沿用一个工具调用关联一个查询子任务的方式，批次序号映射原任务计费项；最多 6 批串行执行，不额外引入并行批处理系统。

**不可直接继承通用查询的重试默认值：**当前 `synchronous.ts` 为一般查询配置最多 3 次重试，M5 属于其中；M3/M5 助手子任务应沿已有研究查询的零自动重试方式接入，并在外发回调阻止同回执再次付费发送。限定为本次受控助手调用，旧数据工具行为不顺手改动。429/5xx、缺业务成功码、供应商余额不足或响应未知按原回执进入现有恢复/核对，不因“只读查询”自动发第二次。供应商余额问题沿后台提醒，前台给出简短的服务不可用说明。

### 5.3 修改建议与交付

检测事实先保存，模型按服务端提供的命中 ID 和局部原句给出替换、理由及必要的邻近语句微调；服务端依据原文位置及原句匹配应用修改，模型不自行计算偏移。正文不重写、不增 emoji、不改语气与排版；原文命中和建议稿改动分别加粗，标记只在展示层生成，下载直接取保存的纯文案，不用正则清洗整份报告而误删用户原文。区间不匹配、重叠冲突或改动越界时保留原文并说明该建议未能应用，不能仍标为“完整修改稿”。这只是 M5 内的有限替换函数，不建设通用修订、合并或文本差异编辑器。

完整原文留在任务材料快照，模型上下文使用有界的材料索引、必要预览及命中附近片段，不在每一步重复注入 10,000 字原文、全部工具响应和历史报告。已明确范围的引用不重新让模型读取全文选范围；混合消息需要识别时可读取一次实际必要文本，不能只给截断预览却猜测剩余正文。复用现有模型输入预算检查，并补到报价前 `snapshotInput`、报价识别、`execution.ts` 的初始材料及后续工具消息投影；现有 `compactAnalyzedResearchContext` 只处理已支持的研究消息，不能假定它已覆盖 M5。仅在新输入/交付合同下调整，不全局截断旧任务上下文。限制不足时在冻结前保留输入并提示缩小范围；执行中仍可能失败时按已有证据恢复或结算，不增加无限模型重试。

交付三个部分：**检测结果 → 修改建议 → 建议修改稿**。报告保留来源版本、覆盖范围、批次结果和检测时间。建议修改稿不自动回写用户原作品，也不标为已经再次通过检测；再次检测属于新的明确任务，不隐含多次外呼。

- 全部完成：原文命中加粗、逐项建议、最小修改后的完整文案；支持复制及下载 TXT，复用现有下载方式，不另外建文件服务。
- 全文零命中：保留三部分但简短表达“未检出／无需替换／原文”，原文可下载。原包对此同时存在“三部分必出”和“零命中不出文件”的冲突；沿用早期主方案明确的原文可导出取舍，写入适配说明。
- 部分完成、建议无法完整应用或用户停止：从已保存查询结果在会话详情展示实际已检/未检范围、已命中内容及必要说明，不另建“部分报告”作品类型，不写完整交付标记。不能给“全文未检出”结论，也不能开放误导性的“下载优化全文”。停止后不为补报告新增模型调用。

实施时明确的建议容量：累计命中超过 200 项、单批提供给模型的安全投影超过 12,000 字符、不同有效命中区间重叠而无法安全替换，或累积请求经既有上下文处理仍超过该任务冻结模型的实际输入额度时，停止于查询结果，说明已检查 N/M 段、建议报告未完成；不截断后冒充完整交付，不收报告整理费。上下文不足收尾只适用于尚未外发且没有回执/decision 的步骤；已经外发的步骤保留原核对与恢复路径，不能据此提前释放未知费用。完整查询事实沿原子任务结果和工具记录保留；开启下一任务后仍可在原会话位置查看。该上限用于本次有限报告合同，不新增分级价格、配置平台或多模型分治流程。

完整报告落库、`assistant_delivery` 交付证据、工具完成与根任务结束须沿现有事务和幂等键衔接。`execution.ts` 已将新的标题和检测报告保存工具纳入既有交付识别；报告与交付证据一起保存，避免“已保存但继续调用模型”或无法结算。仍复用既有持久步骤执行器，不另写一套报告工作流。

## 6. 一次授权、定价与结算

继续使用 `member_tool_quotes`、`member_credit_charges`、`member_credit_task_items` 和现有成本中心，不新增钱包、账本或 Skill 专用支付流程。

**定价建议：**沿用现有助手创作价作为“标题／检测报告整理”基础项，沿用对应 Redfox 查询价按实际调用批次计费，不新增逐标题价格。以下仅用当前已记录的创作 200、查询 20 积分举例；实施启用前通过现有价目管理核实实际生效价格和成本资格，不在代码中写死，也不把原接口已有价格等同于新增动作已获报价授权。

| 用途 | 报价冻结范围 | 示例上限 |
| --- | --- | ---: |
| M3-A 起标题 | 报告创作 1 次＋默认最多 2 次查询；用户固定范围只查 1 次 | 240／220 积分 |
| M3-B 评标题 | 报告创作 1 次＋近 30 天查询 1 次；同主题比较不逐个重复查询 | 220 积分 |

M5 报价明确包含报告整理与修改建议；不是把原工具页的 20 积分“单次查询”换个入口后暗扣 200。若另需只有词库结果的低价服务，应另定产品范围，不能在实施时悄悄加一个收费模式。原数据工具价格与用法不变。

M3 标题用途新增 operation 后，复用现有价目/成本管理注册其映射，金额依据同端点已批准规则，不能仅更换操作名称却遗漏成本行。M5 沿用原 operation 的批准价并核对平台选项是否影响收费。历史 0.06 元查询成本仅为既有估算依据，不作为本次实时核价；实际生效行、计价单位、模型价格和预算缺失时不开放相关动作，不新建凭据或预算体系。

启用时只通过现有 `saveToolPrice` / 供应商成本管理补本次精确条目并留下审计，保留现有自定义价格。不能为 M3 重新执行全量 `applyApprovedMemberPrices`：当前实现会停用并重建其他工具价目，这超出本次范围。套餐、充值、已有模型价和旧报价快照不变。未付费执行前的必要意图识别仍计入现有 `assistant.quote-preparation` 平台成本与调用预算，不向会员新增一个“识别费”；手选且信息完整时复用直接报价路径。

### 6.1 报价与受理使用同一份范围

`submitTurn` 已从 `task.scope` 分别取出 `research` 和 `wordCheck`，再校验严格的 `TaskChoice` 并重建同一冻结范围：报价、确认受理、过期重报和队列轮到执行时，都要使用同一有限范围合同。

- M3 保存交付模式、主题范围和冻结日期；M5 保存来源 ID/版本、原文摘要、全文或所选范围、批次区间/文本摘要与计划版本。`task.scope` 返回前台时仅含必要范围信息，不重复塞全文或供应商原始响应。
- 确认时服务端按原来源还原并验证同一输入摘要，不再次调用模型识别或临时重新切片。范围变化则保留输入、拒绝使用旧报价；原价格是否失效继续由现有报价有效性规则决定，不以客户端金额为准。
- 队列只在轮到它并准备费用时确定本次计划；已接受任务按原冻结版本恢复。不存在“按今天的算法重切旧文、沿昨天价格执行”的路径。
- M5 最多六批使用现有任务收费项目分别绑定精确参数；沿用 `allocateTaskItem` 的冻结输入匹配，加上父任务锁下的批次身份核对。相同批次即使被模型以不同工具调用 ID 再次请求，也复用原子任务/结果；不同位置但内容相同的两批仍按各自区间区分，不能占用彼此的额度。复用现有命令键、回执 window 和原任务收费项，不新增批次账本。

### 6.2 交付与恢复结算

结算要求：

1. 余额不足上限不执行。授权时只冻结一次；查询、分批、保存不再单独扣钱包，子任务只记录交付，根任务统一结算。
2. 查询成功并保存有效结果即有查询交付，零命中也算一次；HTTP 失败、未知状态和解析未完成不当作已完成查询。当前结算按规范化 query 结果判定成功，因此错误、未解析摘要不能作为普通查询结果写入后被误计费；原始响应及诊断沿现有回执和任务记录保存。
3. 创作／报告项只在完整有效作品持久化并关联 `assistant_delivery` 后消费一次；M5 全部检查完成且零命中仍是一份完整报告，按报价收取报告项，不收不存在的“替换次数费”。只查询无成品、未完成全部选定检测范围的部分报告不作为完整创作交付；明确未交付时释放该项。模型已调用不等于会员一定要付创作费，供应商消耗另记成本。
4. 成功返回但交付尚未落库、外部结果未知时保留既有待核对处理，不强行退费或重发。已保存回执恢复后只补解析/保存，沿原批次、子任务、授权和价目快照。
5. 停止后关闭未外发批次，已完成的按事实结算；未决请求沿现有核对路径。必须接入现有停止时工具收尾和“模型无交付”证据，避免报告未保存但所有积分长期卡住，也不能为消除卡住而直接改账。
6. 查询重放、保存重放及刷新不可新增计费项或重复结算。每个批次计费分配时同时校验批次输入摘要和序号，不能只检查“还有一个同价查询名额”。

| 中断位置 | 必须沿用的收尾行为 |
| --- | --- |
| 冻结后、尚未外发 | 关闭未发送调用，释放未交付项目；已发生的报价识别只归平台成本。 |
| 已完成部分查询，用户停止 | 已成功查询按原价计费，其余查询和未交付报告释放；会话保留部分结果，不为补全报告再调模型。 |
| 原始响应已存，规范化结果未存 | 使用原回执补解析/保存；在结果核清前保留待核对，不能把解析失败当零命中或免费成功，也不能重新查询。 |
| 查询子任务完成，父工具仍 running | 将原子任务的有效结果补回工具状态后结算。`closeResearchCallsForStop` 已在原 M1/公众号收尾机制中覆盖 M3/M5，不另建停止器。 |
| 模型返回了报告，但业务保存未完成 | 沿已有模型步骤的决策与工具调用重放本地保存，作品和交付证据同事务，不再购买一份模型回答。没有有效报告时保留缺失交付事实。 |
| 请求已发，结果未知或停后迟到 | 先保留占用并沿现有核对/结果恢复处理；收到可核实交付才结算。停止意图不能触发下一个批次。 |
| 报告已落库、结算或响应中断 | 读取原作品并幂等结算；不会再生成报告。已经结算或退款的任务不得恢复为新的付费执行。 |

成本中心沿既有供应商／服务／模型／Skill／用户／父子任务归因。M3 正确标为标题聚合查询，不记成视觉分析；M5 每批归到同一任务，汇总按真实回执计算，不把根任务预算再算一遍成本。

### 7.1 作品体验

- 标题候选使用紧凑列表，候选文字、推荐理由和单项复制；默认不展开参考数据。点击复制不修改旧笔记标题，不发起新任务。
- 评分先显示综合结果和主要建议，六维详情可展开；手机纵向展示，不让宽表格挤出屏幕。评分保留完整原标题，明确“编辑参考”。
- 检测报告先显示覆盖范围与结果，再看命中和建议修改稿；“复制修改稿／下载修改稿 TXT”只取建议文案字段，不能直接调用当前默认拼接标题、正文和标签的 `artifactText` 把报告一起导出。复用已有 Blob 下载、文件名、复制反馈；下载文件与展示的建议文案（去除展示标记）一致。零命中标为“下载原文”，不伪造已做修改。
- 报告默认只读，避免手工改分数或文本后仍带“已检测”状态。复用现有精确版本引用继续修改／再次检测，产生新的明确任务；不覆盖原报告，不重写被检查的旧稿。其他可编辑稿件的未保存保护不变。
- 新结果到达仍尊重用户当前阅读版本；从对话“查看标题／查看检测结果”打开该任务的精确作品，不跳到最近一张无关图片。同步现有作品名称、完成通知和材料引用过滤；`selectedArtifactVersions` 已纳入新增报告，标题报告只引用候选/原标题，检测报告只引用建议文案，不将研究附录当作待写正文。

### 7.2 版本与启停

新版本只用于新受理任务。旧 M1/M2/M4 任务沿原包 hash、范围及价格恢复；新版本不把旧“创作”授权扩成 M3/M5。后台一个开关控制整个小红书 Skill，不增加固定隐藏名单；显示新增动作及真实依赖状态。

v9 的共享 adaptation 仍写着“M3、M5 未开放”。新版本要同步修正这条适用范围说明，并确保三个新模块实际加载自己的原规程与适配说明，不能只增加按钮或 binding。v9 原文保持不变；v10 的 M1/M2/M4 原任务规程与工具权限保持原范围，新增 M3/M5 不把它们的检测/评分规则注入旧模块。

发布前后使用现有升级/旧报价校验，过期或版本不匹配的未确认报价不能直接执行；已接受任务不因停用被取消，历史作品可读、成本和结算照旧。新增报告的读写代码需随同版本发布，不承诺含新作品的库可以任意回退旧程序。旧包清理只在确认无冻结任务引用时另行处理，不纳入本次顺手清理。

# 后台工具与采集流程易用性优化

当前范围（2026-10-23）：优化已有两条主流程，保持 UI 风格和后台架构。基于 PR #4 的 `c7671c1`，分支 `codex/admin-workflow-usability`。验收通过后，用户已授权提交、推送、创建独立 PR 并运行 CI；新 PR 以 `codex/agentkey-phase2` 为目标，仅包含本次调整。保持 PR 打开，不合并、部署或发起真实调用。第三阶段和五条暂缓路线不在本次范围。

## 现状与最小改动

1. 数据工具混排八个工作区与四个跨页按钮。保留现有工作区，按查询/创作、素材/费用排列；顶部突出“进度与结果”和“采集订阅”，预算及回执入口放在费用工作区。简短说明提交后自动进入对应执行记录；素材上传在素材库查看，不能声称所有按钮都创建执行记录。工作区写入现有 `view` 参数，刷新/返回可定位，切换不清除未提交表单草稿。
2. 执行记录只能点击编号。增加明确的“查看进度 / 查看结果”入口；保留编号与原状态、回执和恢复语义。详情支持进度/结果直接定位，提供返回工具、相关订阅/信源及同订阅历史的入口。
3. 平台采集订阅只显示 activeRun，完成后结果入口消失。每条订阅始终提供“执行历史与结果”，复用 operation_runs 按 subscription_id 过滤；不增加 latestRun 持久字段或新表。列表收拢次要详情，使主要操作可见；编辑/新建时滚动定位现有配置区域，不引入新编辑页面。
4. 原生 X/公众号信源中的主订阅从信源详情管理。其历史入口同样带 subscriptionId；保留信源页原有混合采集历史，不把旧 RSS 抓取日志伪装成统一执行记录。
5. 执行记录列表增加按现有状态筛选；在数据库 LIMIT 100 之前应用订阅/状态条件，避免只筛最近全站 100 条而漏掉所选订阅的历史。兼容已有批量采集：除 subscription_id 外，也匹配原冻结 input.members 中的 subscriptionId，不新建关系或改变归属。保持管理员认证，非法过滤值拒绝；没有外发、队列或业务状态写入。

## 责任与边界

- 主控负责现状调查、只读 API/SQL 连接、测试环境、集成复审和浏览器验收；前端执行器负责指定页面、组件和定向 Web 测试。所有 Git/GitHub 操作由主控执行。
- 专用验收环境：PostgreSQL `127.0.0.1:65434`，数据库 `aihot_admin_workflow_20261023_test`、角色 `aihot_admin_ux`；空库应用原有 75 份迁移。与既有 65433 实例、日常数据库分离；未修改真实配置。
- 复用现有 AdminPage/Card/Button/表格、React Router、API 和 operation_runs / collection_subscriptions。无新表、状态、供应商能力、队列或通用框架。
- 不改变提交、权限、导入、供应商切换、预算、回执恢复和调度行为；业务错误不改写为成功/空结果，完成与未返回结果分开说明。

## 验收

- 数据工具能清楚找到执行记录；代表性表单通过本地桩提交后打开正确执行详情，刷新/返回保持工作区位置。私有素材与费用的查询去向说明准确。
- 已完成、进行中、等待/失败的记录均有明确入口；直接查看结果不会改变执行状态，详情仍能访问诊断与恢复操作。
- 无 activeRun 的订阅仍能打开自己的历史，其他订阅记录不混入；超过全站 100 条的旧订阅记录仍能按范围查到。非法过滤条件拒绝。
- 信源主订阅的历史与返回入口定位正确；平台订阅编辑/新建不因页面导航丢失草稿；原生抓取历史入口保留。
- 定向后端/路由/Web 验证、相关类型检查；桌面与窄屏逐处截图和批注，主控查看实际渲染。使用独立 `_test` 数据库与本地桩，不读取日常库/生产库，不用真实供应商填充测试数据。

实施顺序：只读过滤连接与前端入口 → 定向验证 → 浏览器两条流程验收 → 集成复审。最终记录实际证据，不将本地桩结果表述为真实供应商可用性验证。

## 实施与验收结果（2026-10-23）

以上五项已实现。集成复审补齐了两处连接：从执行详情或工具草稿进入订阅时首次定位编辑器，刷新状态不抢焦点；批量执行列出全部关联信源供选择，不默认返回第一条信源。原生信源主订阅与平台订阅统一使用“执行历史与结果”入口文案。

- 后端：`tests/admin-operation-history.test.ts` 1 项通过，覆盖管理员认证、非法参数、过滤先于 100 条上限、单订阅与批量冻结成员匹配、状态组合、无结果以及读取不改变执行/回执/订阅占用。运行于上述独立测试库，拦截供应商请求。
- Web：`collection-source-entry`、`collection-detail-render`、`operation-result-export-render`、`collection-subscription-data`、`source-history-data` 共 43 项通过；包含真实组件初次定位与刷新不抢焦点、各工具返回工作区、批量信源链接、空结果与恢复入口保留。
- 类型：全仓 `npm run typecheck` 通过；后续前端修正后 Web typecheck 再次通过。`git diff --check` 通过。对本次六个 UI 目标执行一次 Impeccable 机械检查，结果为空；主控另行查看了实际截图，不以机械结果替代视觉验收。
- 浏览器：查询表单 → API → 现有执行器 → 回执与结果落库 → 详情；查询条件 → 订阅草稿 → 保存/启用 → 运行一轮 → 同订阅历史 → 结果 → 返回编辑区，均走通。执行器由验收脚本显式驱动，没有启动定时 Worker。两次供应商执行都只访问本机 MCP 桩，查询记录 #110、采集记录 #111 均已完成；#111 的订阅 #4 解除占用。
- 额外页面状态使用明确标记的本地样本：等待、需核对、停止、已结束、完成空结果、批量原生 X 及旧 RSS 抓取历史。原生 X 主订阅历史正确包含批量记录；旧 RSS 保留抓取日志，没有虚构统一执行详情链接。
- 工作区切换与浏览器后退保留当前页面未提交草稿；刷新保留工作区位置，不承诺刷新或跨页后保存所有未提交内容。窄屏沿用原有横向滚动表格，页面主体无新增横向溢出。

# 助手技能接入标准 v1

状态：v1接入合同，2026-10-30；修订2026-10-31。首版代码已实现本地目录校验、受控加载、权限与持久执行；适用范围和验证状态见文末“首版实现映射”。新增输入区已实现并完成本地验收，见[输入区验收](reviews/2026-10-31-assistant-inputs-acceptance.md)；以[工作区方案第12节](assistant-chat-workspace-plan.md#12-输入区增量修订材料技能与费用确认2026-10-31)为本次技能绑定、材料及自动授权的范围权威。适用于[创作助手接入方案](xiaohongshu-agent-integration-plan.md)中的统一底座、综合入口和专属助手。项目强制规则仍以[开发原则](development-principles.md)为准。

本标准定义我们系统内部如何接入经审阅的技能，不宣称兼容所有外部SKILL.md、插件或Agent客户端。外部规程可按需适配，外部脚本不会因进入技能目录而获得执行权限。首批general-writing和xiaohongshu-creator共同验证这套合同，公众号等后续沿用。

## 1 接入物与复用边界

一个技能的接入物包括manifest、模块规则/已声明参考资源、输入/交付schema引用、来源与使用许可说明、验收fixtures。首版保存在backend的assistant功能私有目录，由代码发布；不增加通用插件后台、运行时安装器或上传任意执行代码的入口。

只使用已有工具的技能，增加上述接入物及profile/快捷动作绑定，不另建会话、队列、账本或付费请求通道。需要新工具时，先在对应业务领域实现适配、权限、费用、回执、恢复及结果合同，再由manifest引用。新增工具和类型化输入/结果schema属于必要代码扩展，不能仅靠提示词声明实现。

通用执行器只认识技能/模块/工具合同，不按具体skillId复制分支。只有业务模块确有特殊执行需求时才增加该模块的受控工具或局部处理器，不把差异堆入全局Agent循环。

## 2 可校验的技能manifest

使用现有Zod在私有配置加载边界严格校验；未声明字段拒绝，不宽松吞掉会影响权限/执行的配置。以下为内部接入合同字段，不是第三方SDK接口；实际可接受字段以 catalog.ts 的严格schema为准。

| 字段组 | 必需信息及规则 |
| --- | --- |
| 格式 | formatVersion=1；与技能内容version、模块version、结果schemaVersion分别管理；未知格式拒绝启用 |
| 身份 | 稳定skillId、不可变version、manifestHash、packageHash；同一id/version不得指向不同内容 |
| 来源与维护 | 自有或外部来源、固定提交/版本、许可/使用授权证据、维护责任和审阅记录引用；缺失许可须明确标记，不能据此启用未经确认的复用 |
| 路由说明 | 显示名称、用途、不适用范围、有限意图示例、模块摘要；关键词仅是描述，不构成唯一选择规则 |
| modules | 每模块moduleId、version/hash、输入schema引用、入口规则resourceId、允许的共享/专属资源、工具合同引用、模型能力要求、输出合同和交付判定引用 |
| resources | 每项resourceId、包内相对路径、UTF-8文本类型、字节数和sha256；首版只读Markdown/纯文本/JSON规则数据，不加载可执行代码 |
| fixtures | 每模块成功/缺材料或不允许/交付三类样例引用；新外部工具另有该工具的回执/恢复测试引用 |

工具、输入及输出schema、交付判定只引用代码中已存在且版本兼容的合同ID，不允许manifest注入函数、Shell命令、供应商URL、网络权限、凭据或“免费/免确认”覆盖项。每模块的资源和工具独立声明，共享资源也必须显式列入；不能因为M1启用就公开M3/M4/M5规程。包内moduleId、resourceId分别唯一；全目录的(skillId,version)唯一且内容一致，不同技能可以有同名模块，必须保留技能命名空间。

哈希覆盖manifest的规范化非哈希字段、模块资源内容和所引用合同版本，计算过程排除哈希自身；整体身份冻结后不可修改。路径、文本或schema引用发生变化要发布新内容版本，不能以相同版本热替换。提示词版本、输入schema版本和manifest格式formatVersion都进入可追溯记录。

资源验证拒绝绝对路径、`..`、符号链接逃逸、未声明资源和哈希不符；引用解析只在已审阅包内进行，无运行时网络拉取。初始保护限额为manifest≤64KiB、单文本资源≤128KiB、包内规则文本合计≤1MiB；进入模型前仍须满足本回合上下文token上限，超限明确拒绝或请用户缩小材料，不静默截去必要规则。

配置加载先检查身份/格式、资源完整性、模块引用、模型能力要求可识别、工具/交付合同存在及兼容性。无效模块不能进入可执行目录；共享身份或必要资源无效时整个包不可执行，并记录维护者可见诊断。未启用模块可以保留在发布包中，但不能出现在模型可选集合里。

## 3 技能目录、快捷动作和可用性

后端形成三个投影：

- 用户界面投影：名称、任务快捷actionId、允许选项、说明、可执行状态及原因；不包含完整规则和供应商诊断。
- 模型目录投影：本回合冻结的允许skill/module/version/hash、用途、输入要求和简短示例；不包含未启用技能或全部工具。
- 执行配置：完整经验证的资源、工具、输入/输出schema及权限上界，只在后端使用。

可用性由“接入物验证有效、已实现/启用、profile允许、模型兼容、当前用户权限及外发/价格/预算条件”共同决定；前端状态是提示，quote、load和实际外发还要重新核对。验证有效不等于已启用，也不等于用户已授权某次付费动作。

现有综合入口快捷按钮提供规范化taskHint；自然语言输入从同一候选目录选择。新增输入区方案要求欢迎快捷按钮与会话下拉共用actionId，自动模式在profile允许范围内语义选择，手动模式由服务端进一步限定skill/module候选。二者继续走quote→turn→工具建议/有效授权→执行→交付；actionId不允许浏览器指定任意版本或工具。意图不明或与已选动作冲突才澄清；不得额外增加一条付费分类链。旧taskHint保留兼容语义；新skillSelection.actionId已由服务端严格绑定，并冻结在报价及任务快照。

“公众号创作—未开放”可以作为前端展示项，但不生成有效taskHint、不进入模型目录、不创建费用。未来该动作具备真实能力并通过验证后再启用；静态展示项不是虚假的可加载Skill。

## 4 加载和引用读取协议

| 操作 | 模型输入 | 后端校验与成功返回 |
| --- | --- | --- |
| load_skill | skillId、moduleId | actor/turn/model_step由服务端提供；从turn快照解析版本，校验候选、模块范围、当前许可、模型能力、资源/合同完整性；返回activationId、固定skill/module版本/hash、入口规程、允许引用资源索引、下一步骤可用工具描述及outputKinds |
| read_skill_reference | activationId、resourceId | 激活必须属于当前会话/回合；只在activation所属技能包中解析resourceId并核对其允许集合，不能全局按同名ID取资源；返回已验证的固定文本、类型、hash；不读取新版本或任意路径 |

加载和读取只读本地已审阅资源，不调用供应商，不创建工具charge。激活事实记录在既有turn/模型步骤关联内，无需另建一个执行状态机。重放身份为turnId + skillId/技能版本/hash + moduleId/模块版本/hash；相同身份返回同一激活事实，不覆盖旧调用的model_step和模块快照。本地加载重放本身不增加模型次数或产生额外业务调用；模型新发请求再次提出同一load仍按真实外发计数，不能借重放名义免除请求额度。

模块业务输入按其input schema校验；入口规程为追问所需材料可以先加载，未满足必需输入时只能澄清，不能执行依赖该输入的业务工具或将缺失输入视为已确认。澄清后的模型请求照常计入回合额度。

新工具只能在后续模型步骤经服务端组装的schema中公开。一次模型响应中先调用load_skill，再提出此前未公开的工具，后者不能被追认。模型提出“加载”只改变已授权候选中的激活范围，不改变profile、供应商、模型、价格、额度或批准事实。

失败返回稳定errorCode、可展示reason及服务端计算的nextAction；不能让模型凭“可重试”自行重新付费：

| 错误类别 | 示例errorCode | 允许的处理 |
| --- | --- | --- |
| 不存在/未启用 | skill_unknown、module_unknown、capability_unavailable | 说明缺口；仅可选当前允许能力或停止，不下载新技能 |
| 范围/权限 | scope_denied、permission_denied | 拒绝当前动作；提示可用操作，不能换助手绕过 |
| 输入/模型 | input_required、input_invalid、model_incompatible | 补材料/更正；更换模型需要新报价，不自动降级 |
| 完整性/兼容 | resource_missing、integrity_mismatch、contract_incompatible、format_unsupported | 不执行受影响模块；保留诊断给维护者，不省略规则继续生成 |
| 版本/上下文 | version_unavailable、context_limit | 在途版本不可取得则待核对；超限缩小范围或新回合，不静默换latest |

以上加载协议是后端内部模型工具合同，不要求新增公开HTTP加载API；前端只通过已鉴权options、会话、报价和执行协议操作。

## 5 工具桥接与权限校验

每项业务工具在后端有一个静态、类型明确的桥接绑定。不是可由外部包扩展的通用Provider Registry。

| 合同项 | 单一权威 |
| --- | --- |
| toolId / contractVersion / 输入schema | 代码定义的模型输入及规范化参数；actor、session/turn/call身份、幂等键由后端注入 |
| 领域映射 | 指向现有normalize/quote/create/control/read或局部纯本地函数；新增外部工具指向对应provider适配；不自HTTP访问本系统API |
| 权限与副作用 | 代码明确本地读取/本地写入/外部动作，所需所有权、预算、报价/批准；manifest只能引用，不能改为免费或跳过检查 |
| 结果与交付 | 现有安全结果投影、结果schema/版本、来源引用及可验证交付规则；模型看必要业务结果，不看原始回执/密钥 |
| 执行与恢复 | 关联既有operation/receipt事实和负责的恢复路径；模型不能指定无限retry、直接改状态或另开账本 |

有效工具始终取：该回合profile允许范围 ∩ 激活模块及明确通用工具 ∩ 当前会员权限 ∩ 已实现且当前允许执行的能力。提出工具调用时还必须属于该次model_step实际公开的schema；批准和外发再次验证当前权限、输入/版本、所有权和授权范围。

读取规则不能扩大集合；任务快捷按钮不能批准费用。现有费用确认卡通过专用后端批准命令处理；下一次可选额度内自动模式须验证用户明确创建的会话授权，在相同领域事务中校验限额、关联报价与预占，不能由模型或前端模拟批准。材料输入能力与费用授权分别校验，上传文件不等于同意付费读取。导入文案/网页/供应商结果不能修改身份与工具权限；历史版本冻结不能绕过账号停用或撤销外发。新增来源和发布权限仍遵循项目既有边界。

## 6 执行、结果与错误的一致处理

模型步骤、工具调用、父子任务和回执沿[主方案第6–9节](xiaohongshu-agent-integration-plan.md)执行。技能不自建运行状态；包可用性、turn的phase和operation的运行状态是不同概念，终态事实仍由现有operation确定。

工具提交返回runId仅表示已受理。执行器持久保存child关联、等待可交付结果，再生成匹配的tool result并继续模型；不能把“已受理”作为搜索结果、图片或检测已完成证据。给前端的进度事件可以先显示受理状态。

给模型的完成结果包含工具/call身份、结果schema版本、经验证业务数据、必要来源/作品引用、完整或partial覆盖范围。失败结果包含稳定错误分类和允许的下一动作，不将服务器异常堆栈或原始供应商响应直接透传。以下为现有状态的投影和处理规则，不另持久化一套状态权威：

| 事实 | 执行器动作 |
| --- | --- |
| 完整本地/供应商结果已保存 | 提交匹配tool result及业务结果，再推进；引用真实来源/文件 |
| 部分结果 | 显示已完成/未完成范围，按模块partial规则判断可用性及结算，不当作全量完成 |
| 等待用户/批准/child | 保持持久等待，不额外调用模型轮询或偷偷重交 |
| 已有完整HTTP响应但解析失败 | 重用已保存响应，本地重解析；确需新付费请求时重新检查授权和剩余额度 |
| 发送后结果未知 | needs_review，保留回执和费用核对链，不自动重买 |
| 取消/撤权 | 阻止新动作，迟到响应留证据但不覆盖新版本；既有费用按事实处理 |
| 参数或合同失败 | 明确错误；用户补输入或维护者修合同，不统一catch后重新外发 |

输出保存与计费引用同一个模块交付合同，验证outputKind/schemaVersion及必需证据；结构验证不代替内容质量评估。新增输出类型在代码中登记schema和安全展示/导出方式，未知类型不执行嵌入脚本或直接注入HTML。父回合与子工具的独立报价/结算继续遵循主方案。

## 7 接入、升级与完成条件

按接入物声明→来源/许可及规则审阅→schema/资源/依赖校验→模块fixtures→受影响工具专项验证→profile/action绑定→获准真实样例→默认关闭后配置启用的顺序完成。只有前端展示项不能视为接入完成。

版本更新创建新不可变版本。quote后配置变化重新报价；已提交turn使用旧候选、规则和工具合同，旧规则/资源及工具执行支持至少保留到相关在途任务可收尾。结果schema、安全渲染和导出支持的生命周期更长：保留到仍引用该版本的作品按保留策略清理，或完成可验证的兼容迁移，不能随着最后一个任务完成就撤除。停接新任务与撤销外发许可分开；旧版本不可执行时明确停止/待核对，不用新模板偷偷重跑。

最小验收随风险增加，不为每个纯提示词模块重复整套供应商测试：

| 接入情形 | 必需证据 |
| --- | --- |
| 每个模块 | manifest与资源有效、依赖已存在；成功样例、缺输入/不允许样例、完整/partial交付样例，加载重放不改变版本 |
| 目录/加载器初次实现 | 越界/符号链接/未声明资源/哈希错/合同版本错拒绝；标准错误可处理；模块间工具不越权；不同Skill的同名模块/资源不串包；重复模型外发仍计数 |
| 快捷动作和语义路由 | 同一能力共用执行链；hint冲突澄清、更换使报价失效；未开放公众号不可执行；等待期间不能旁路批准 |
| 只复用已有工具的新技能 | 新包与profile/action/schema绑定即可由相同执行器运行；通过无外呼的扩展fixture，不增加skillId专用执行分支 |
| 新增或改变付费/外部工具 | 该工具输入、所有权、预算、报价、每次HTTP回执、未知结果、停止、重放和父子事务专项验证 |
| 版本退役 | 在途任务按旧合同收尾；旧作品仍能安全查看/导出，直至作品清理或兼容迁移完成 |
| 真实启用 | 接口/模型能力和价格有证据；小样本在另行授权的数据/费用范围内运行，结果和实际调用数可核对 |

当前成熟度：目录校验、受控加载、双入口及持久任务已有实现和验收证据，真实联调范围及限制见[2026-10-31流程验收](reviews/2026-10-31-assistant-live-acceptance.md)。手动技能严格绑定、文件输入和会话自动费用授权已实现，新增验证使用独立测试库和本地桩，不将既有真实联调冒充新功能证据。新增技能继续用fixtures验证复用边界，不能仅凭本文件称为生产成熟或任意Skill即插即用。

## 首版实现映射与后续接入

首版是代码随版本发布的受控目录，不是任意上传外部 Skill 即运行的插件平台。

| 边界 | 当前实现 |
| --- | --- |
| 目录与完整性 | `packages/backend/src/assistant/catalog.ts`：严格 manifest/schema、路径和包内引用、资源大小/哈希、模块合同、fixture引用校验；技能资源位于同目录 `skills/` |
| 已启用能力 | `general-writing/write`、`xiaohongshu-creator/M1` 单关键词检索子集、`M2` 给定材料改写；小红书v2按用户指示使用固定上游写作原文，来源及本地评估范围见文末2026-10-31更新 |
| 多入口 | `creative`、`xiaohongshu` profile 与快捷动作；服务端固定会话身份，前端菜单不构成授权；公众号仅显示未开放 |
| 加载 | `load_skill` / `read_skill_reference` 为内部模型工具；候选、版本和哈希冻结到回合，激活绑定当前回合；加载后的工具在下一模型步骤公开 |
| 业务复用 | `execution.ts` / `tools.ts` 连接既有 operation、receipt、预算、会员积分和 Redfox 检索领域；不另建队列或收费账本 |
| 会话与作品 | `sessions.ts` / `controls.ts`、私有会员 API、版本化作品/来源、显式转交；已批准命令幂等，读请求不调用模型 |
| 页面 | assistant-ui ExternalStore runtime 展示后端持久状态；按步骤轮询，不是 token 流式输出 |

新增公众号等技能的最小接入步骤：

1. 在私有 `skills/` 中增加自有或已获授权的规则、manifest及fixtures，使用新版本并生成完整性哈希。source schema区分 owned/MIT 与 external；当前外部包记录固定URL/commit、NOASSERTION和user-directed-local-evaluation依据，不把未声明的上游许可标成MIT。
2. 在 `catalog.ts` 注册经审核的包、profile/模块和快捷动作。若新增独立assistantId，同步扩展contracts、服务端枚举及入口；数据库assistant_id已采用稳定标识格式，不需为每个新助手新增表。
3. 只使用现有文本作品/工具的技能，复用会话、审批、队列和积分。新增输出类型或业务工具时，先补对应类型合同、输入/交付校验、安全投影、价格/预算和恢复适配，再列入manifest。不能用提示词赋予尚不存在的能力。
4. 用目录负例、权限/报价、工具批准、持久交付及中断恢复测试证明接通，再在对应入口启用。旧回合所引用包版本须保留至存量任务结束；目前无自动版本仓库或动态下载器。

助手复用现有 `modelFor("assistant")`、`MODELS` 和后端模型凭据；后台模型能力设置优先，其次 `ASSISTANT_MODEL` 注册键，默认 `default` 沿用 `LLM_*`。不使用独立 `ASSISTANT_BASE_URL/API_KEY`。回合冻结版本2的注册键、供应商、实际模型、端点、凭据变量名和生成参数，不保存密钥；执行时不重新选择模型。端点变化或旧版快照停止外发，已有结果仍可查看、回合仍可停止；同端点密钥轮换允许。积分价格按实际模型标识匹配，仍需单独配置 `assistant-turn/assistant` 价格；供应商凭据存在不代表已配置价格或预算。

当前模型适配是 OpenAI-compatible Chat Completions 的非流式 text-tools 路径，tokenizer仅实现 `cl100k_base`，仅用于本地输入限制估算，不是供应商精确 token 计量或金额上限；回执 usage 来自供应商响应，缺失保留未知。`ASSISTANT_MODEL_VERIFIED=true` 是运营方经真实兼容性验证后的声明，不是自动探测；不能把任意模型配置成已验证。首次上线仍需另行授权真实模型/检索验证、配置价格和预算，并确认保留/清理策略。

未发送草稿与未知提交的重试信息仅保存在当前页面进程的账号/会话隔离内存中：支持站内离开再返回，整页刷新后读取服务端已接受的会话/任务；未发送草稿不承诺跨浏览器或刷新保存。服务端quote消费和命令幂等仍是收费权威。

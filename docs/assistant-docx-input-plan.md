# 助手 DOCX 上传与文字提取方案（U8 第一阶段）

日期：2026-11-13。状态：**已实施，核心局部测试与代表性隔离浏览器验收通过，未部署**。用户后续已授权实施 DOCX；本轮改动使用独立测试库与本地模型桩，不修改 localhost:3000，不执行真实付费调用。

依据：[商用体验实施方案](assistant-commercial-ux-implementation-plan.md)的 C / U8。代码核对基于 `codex/assistant-delivery-ux-1113`、`dev@0bcebb5` 及当前未提交的 A/B 改动。A/B 的验收结论继续有效；DOCX 尚未部署到日常实例。

## 1. 目标与范围

用户可以直接添加 Word 文档作为创作材料，不必先复制正文或转换成 TXT。操作仍是：**点加号 → 多选文件 → 在输入框里看到附件卡片 → 查看提取的文字 → 描述需求并发送**。预览可选，不增加“确认解析”步骤。

这是助手共用的材料输入能力，创作助手、小红书助手及可用 Skill 共用。DOCX 不是新 Skill，不进入技能下拉；不用为公众号、小红书或图片技能分别接一个 Word 工具。图片技能可以把文档文字当作创作说明，但不会因此获得识别文档内图片的能力。小红书和公众号原有研究流程不变。

本阶段支持 `.docx`、保留 `.txt` / `.md`；只交付文字提取。`.doc`、`.docm`、PDF、OCR、图片理解、音视频、链接正文抓取、Word 在线编辑和 DOCX 导出均不包含。无需 Word、LibreOffice 服务、Python 环境或新的供应商配置。

实施核验边界：当前支持普通 Word DOCX（Transitional OOXML）；Strict OOXML 会明确拒绝，需要另存普通 DOCX。已补验解析库自带的 Microsoft Word 样本，WPS 实际保存样本尚未验证。第二轮复审的修复与证据见[验收记录](reviews/2026-11-13-assistant-docx-acceptance.md#第二轮完整复审)。

## 3. 内容与限额

### 3.1 提取什么

| 文档内容 | 首版行为 |
| --- | --- |
| 标题、正文、段落、手动换行 | 保留文字及阅读顺序，保留必要换行；不还原字体、颜色、分页和版式。 |
| 普通列表 | 保留各项文字和层次分隔；不保证 Word 的复杂自定义编号完全一致。 |
| 普通表格 | 按行列顺序转成文本，单元格有分隔、行有换行，不能把相邻单元格直接粘成一句话。合并单元格不承诺版式还原。 |
| 超链接 | 保留显示文字；不访问目标地址，不读取外部文件。 |
| 脚注、尾注 | 解析器返回的注释文字放到文末，并与正文分隔；用样本确认引用文字不会混入另一段正文。 |
| 图片、图表、嵌入附件和公式 | 不识别图片文字、不计算公式、不执行嵌入内容。存在这些内容时，预览内提示“已读取文字，图片或其他嵌入内容未读取”。 |
| 页眉、页脚、批注和复杂浮动排版 | 不作为首版保证提取的正文范围。预览固定简短说明读取范围，不声称已完整还原 Word。 |
| 尚未接受/拒绝的修订 | 提示先在 Word/WPS 中处理修订后重新上传，不替用户决定采用修改前还是修改后的内容。 |

不因普通文档自定义字体或样式产生大段警告。只把可能缺少材料内容的情况转换成简短提醒；解析器原始错误、XML 节点名不展示给用户。

### 3.2 文件和文本限制

| 项目 | 方案值与依据 |
| --- | --- |
| 累计附件数 | **最多 10 个**，沿用现有多选及已选会话材料的计数规则。混合 DOCX/TXT/MD 合计，不按格式分别给 10 个。 |
| TXT / MD 单文件 | 维持 **2 MiB**，不随 DOCX 一起放宽。 |
| DOCX 单文件 | 建议 **5 MiB**，包含文档内图片等压缩内容；服务端在接收字节时就限制，不只做前端检查。 |
| 单份可用文字 | 维持 **30,000 字符**，不是 30,000 汉字或模型 token；以服务端既有字符串长度口径计算。超出拒绝，不默默截取。 |
| 一次任务的合计输入 | 继续经过当前整体快照 85,000 字符检查、模型输入上限及研究预留检查。10 个附件不等于承诺可提交 300,000 字符。 |
| 页数 | 不设置页数额度，DOCX 分页依赖字体与排版环境；用文件大小、提取文字和解压资源限制代替。 |

DOCX 的 5 MiB 是本方案建议值，不是现有已上线配置。后端通过现有 `inputCapabilities` 增量返回各格式大小限制，前端据此校验和显示；保留原 `maxFileBytes` 作为旧调用方回退，不在多个页面硬编码不同上限。

首版 DOCX 只有成功提取非空、未超长的文字后才注册为可用素材。损坏、超长或无法读取的 DOCX 不占用永久文件名额；失败临时文件沿现有上传清理路径删除。TXT/MD 当前“原文件可保存、超过助手文字限额后拒绝引用”的行为维持，错误提示根据实际结果区分，不统一声称文件已经保留。

## 4. 用户操作与提示

1. 加号仍只显示图标。菜单项改为“上传文件”，下方简短说明“支持 Word（DOCX）、TXT、MD，最多 10 个”。字节限制放在菜单说明或错误提示中，输入框不常驻一大段限制。
2. 多选后继续显示现有紧凑卡片，长文件名省略但可查看全名，右上角移除位置不变。DOCX 用现有文件图标及类型文字，不做大号封面缩略图。
3. 现有上传请求会在返回前完成提取，因此 DOCX 卡片如实显示“上传并读取中”，不伪造已上传成功或百分比。请求成功后读取已保存文字，卡片显示“可用”；字符数放预览，避免卡片拥挤。
4. 点卡片打开现有附件预览，标题为文件名，说明“助手将使用以下文字”。正文使用纯文本预览，不把转换产生的 HTML 插入页面。预览说明图片和版式不读取；只有实际存在遗漏风险时再显示对应提醒。
5. 文件全部可用才允许正常发送/排队。个别失败不删除其他成功卡片，也不丢输入；用户可以重试失败项或移除后继续。不能自动忽略失败附件并直接发起任务。
6. 切换技能、快捷动作或在页面内切换会话，沿现有草稿保护。移除上传中卡片后，迟到的结果不能重新添加卡片；移除只取消这次引用，不删除其他会话使用的文件。
7. 已提交/已绑定的文件恢复沿现有服务端输入及请求恢复机制。尚未持久化的浏览器 `File` 不承诺整页刷新后还能续传；如丢失则提示重新选择，不新增浏览器文件库或断点续传系统。

错误文案按实际原因给出下一步：

| 情况 | 面向用户的提示与操作 |
| --- | --- |
| `.doc` 或其他格式 | “暂不支持这种文件，请另存为 DOCX，或上传 TXT / MD。”重新选择。 |
| 文件过大 | “这份 Word 文件超过 5 MiB，请删除不需要的图片或拆分后上传。”重新选择。 |
| 加密、损坏或无法识别的包 | “无法读取这份 Word 文件，请取消密码保护，或在 Word/WPS 中另存为 DOCX 后重试。”不假称一定是密码问题。 |
| 只有图片/空文档 | “没有读到可用文字。图片中的文字暂不支持识别，可以粘贴正文。” |
| 文字过长 | “这份材料超过 30,000 字符，请保留本次需要的部分再上传。”不保存一份被悄悄截短的材料。 |
| 合计输入过多 | 沿现有上下文拒绝，保留草稿和附件，提示减少本次材料；不先冻结积分再发现超限。 |
| 网络、服务繁忙或提取超时 | “这份文件暂时没读好，可以重试；其他材料已保留。”重试沿用上传标识。 |

不可通过重试解决的格式/超限错误突出“移除并重新选择”，不让用户反复点击同一个无效重试。提示仍放附件附近或预览详情，不新增阻塞弹窗。

## 5. 服务端最小实现

### 5.1 解析器与资源边界

选用成熟 DOCX 库 Mammoth 做文档语义转换，ZIP 容器检查使用 yauzl；当前后端尚未直接依赖这两者，实施时固定依赖版本并核对 Node 24 兼容及安全公告。现有 `fast-xml-parser`、`sanitize-html`、`cheerio` 可复用做包元数据检查及最终文本整理，不自行编写完整 Word 转换器，也不依赖别的包间接安装的 ZIP 库。

Mammoth 官方支持段落、列表、表格等转换，并明确提醒不可信文档需要资源隔离；本方案只把 HTML 当作服务端短暂中间结果，禁用外部文件访问、文档内样式映射及图片读取，再整理为纯文字。[Mammoth 官方说明](https://github.com/mwilliamson/mammoth.js#library)。选择结构转换是为了保留表格分隔、列表与换行，不使用其已弃用的 Markdown 转换，不直接输出 HTML 给浏览器。

容器检查在调用文档解析前完成。yauzl 提供逐项读取与实际展开尺寸检查，但具体资源上限仍由平台负责。[yauzl 官方说明](https://github.com/thejoshwolfe/yauzl#api)。本方案建议：最多 1,000 个 ZIP 条目、总展开量 20 MiB、单个 XML 4 MiB；目录声明与实际解压字节均检查，超限立即停止。拒绝重复/越界条目、加密或宏文档伪装、缺少必要内容类型及正文关系的普通 ZIP。XML 不解析 DTD/外部实体，外部关系不触发网络或文件读取。扩展名必须为 `.docx`；标准 DOCX MIME 及浏览器通用二进制/ZIP MIME 仅用于进入检查，最终以实际包内容判定，不能只改后缀绕过。

解析放在一个可终止的 Node Worker thread 中，接收有界字节，不接收数据库连接或供应商配置；超过 5 秒即终止并走失败清理。设置有限 JS 堆，配合上述输入/展开量限制，不把线程内存设置冒充完整沙箱。复用现有单 API 进程最多 2 个上传的限制；线程只做这一次解析，不引入常驻解析服务、任务队列、解析状态表或重试调度器。多进程的总并发仍受各进程部署数影响，不声称是全站锁。

### 5.2 一次提取，保存结果

```text
原有私有上传请求
  → 扩展名/MIME/字节限制
  → 有界 DOCX 检查与文字提取（数据库事务外）
  → 原文件及提取结果一起注册为可用素材
  → 本人附件文字预览
  → 原有会话绑定、报价快照、冻结及任务执行
```

复用 `stored_files.metadata` 保存一份可选的 DOCX 提取结果，不新增表或数据库迁移：格式/提取规则版本、源文件 SHA-256、文字、文字摘要、字符数及有限的用户提示码。最多 30,000 字符，避免反复解压，也保证部署新版解析器后历史任务不因重新提取而改变材料。原文件仍为 DOCX，真实 MIME 与 `kind: document` 保持一致，不能把二进制文件标成 TXT。

**必须同步收紧 metadata 的投影：**当前 `publishUpload` 审计会展开检查结果中的 metadata，后台素材列表也能读取 metadata。新增全文前要改为明确的安全摘要投影，审计/列表只记录格式、字节、摘要、字符数、提取规则版本和结果码，不能把文档正文、内部 HTML、原始解析错误写入日志或列表响应。正文只经本人附件文字接口和已有会话权限返回。

上传成功只表示原文件与提取文字均已持久化。相同上传标识与相同字节返回已有素材和已有提取结果，不覆盖或升级它；同一标识换内容仍返回冲突。失败、断连或数据库注册中断沿现有不可变文件与上传恢复路径处理，不另建一套身份。

### 5.3 接口、绑定与冻结

- 在现有助手路由增加一个鉴权的附件文字读取接口，例如 `GET /api/assistant/attachments/:key/text`，组合 `ownedToolAsset` 与 `readAssistantAttachment`。返回文字、来源摘要、格式、字符数和必要提示；`Cache-Control: no-store`。该 GET 只读取结果；DOCX 缺少有效提取结果时拒绝，不在读请求里启动解析。
- TXT/MD 继续用现有 UTF-8 校验；前端也改用此接口预览。原始文件下载仍走现有 `/api/tools/assets/:key/content`，其二进制内容不会被替换成文字。
- `readAssistantAttachment` 对 DOCX 读取持久化提取结果；继续检查归属、可用状态、原文件字节及 SHA-256、文字摘要和长度。绑定、报价、确认阶段复用，不在会话/积分事务内再运行 DOCX 解析线程。
- `attachInput` 和首次请求仍只接收 `assetKey`。绑定结果写入已有 `assistant_session_inputs`，保留来源文件摘要、文字摘要及提取规则版本；不接受客户端改写正文冒充该文件的提取结果。
- 执行消费已经冻结的输入快照。上传、预览或更换解析器不能覆盖已接受任务的材料；缺失/修改文件拒绝新的引用，旧会话已保存文字和作品照常读取。
- 接入是平台材料能力扩展，不改任何 Skill 的名称、执行脚本、绑定版本或研究约定；DOCX 也不能直接进入图片/视频供应商的媒体上传通道。素材目录可以列出它，但其他工具仍按原能力允许类型过滤。

## 6. 费用、历史和恢复不变量

上传与本地文字提取不调用模型、不调用 Redfox，不新增积分价格、预算服务或成本中心收费项。模型使用文档文字生成内容时，继续经过既有报价、一次任务冻结上限、实际结算及成本记录；文字变多可能增加模型输入用量，仍受现有上下文和供应商预算限制，不承诺生成成本不变。

| 边界 | 必须保持 |
| --- | --- |
| 上传/预览/失败重试 | 不创建付费任务、回执或积分冻结；失败文件不会让助手先建一个空会话。 |
| 报价后增删/替换附件 | 沿现有草稿失效及重新核价路径，不把新材料塞入旧报价；报价绑定的输入来自服务端实际文字。 |
| 确认后修改输入框 | 仅影响下一次草稿，不改当前任务输入或收费授权。 |
| 排队、停止与异常恢复 | 队列消费原冻结材料；恢复原任务、原回执，不重新上传/解析/冻结积分来代替恢复。 |
| 移除与删除 | 卡片移除不等于删除文件；会话引用对原资产的删除保护继续生效。 |
| 历史兼容 | 旧 TXT/MD、旧作品及旧输入不批量回填。DOCX 提取结果缺版本/损坏时不猜测修复；原历史快照仍可读，新引用给出重新上传提示。 |
| 发布回退 | 不做数据库破坏性变更。若后续上线需要回退，先停止接收新 DOCX，保留已保存输入和只读结果；不能承诺回退到完全不认识 DOCX 的旧代码后仍可新引用它。 |

## 7. 改动范围与实施顺序

| 步骤 | 改动位置和内容 | 完成标准 |
| --- | --- | --- |
| 1. 提取与存储 | backend `operations/` 内补小型 DOCX 解析模块及线程入口；扩展现有上传检查、元数据与安全投影；固定所需依赖 | 合法文档一次提取并持久化；无网络/付费；损坏和资源超限有明确结果及清理。 |
| 2. 助手引用接通 | `assistant/attachments.ts`、`sessions.ts`、API `user-assistant.ts`、相关 contracts | 本人预览与服务端绑定得到同一文字；原事务、摘要、幂等和历史语义保持。 |
| 3. 原 UI 扩展 | `materials-data.ts`、`materials.tsx`、`composer-controls.tsx` 及必须同步的素材类型提示 | 多选、混合格式、卡片、预览、失败重试和移除在原入口完成。 |
| 4. 局部验收与收口 | 扩展既有附件测试，补少量 DOCX 样本；更新材料格式与 U8 状态文档 | 核心检查通过；桌面/手机走完实际操作；明确未覆盖的 Word 特性。 |

预计 **2–3 个开发工作日**，含核心测试和代表性浏览器验收；是实施估算，不是已消耗工时。先在正常 Word/WPS 样本上确认解析质量和资源边界，再接 UI，不同时扩展 PDF/OCR、异步任务平台或全文检索。发现现成库无法满足已列出的正文/表格要求时，先收窄或调整局部解析方案，不扩建通用文档框架。

## 8. 最小验收清单

优先局部测试，不默认跑全量。TXT/MD、素材权限及幂等沿用并扩展 `tests/assistant-attachments.test.ts`，前端规则沿用 `apps/web/tests/assistant-materials.test.ts`；纯 DOCX 样本解析按需要单独一个测试文件，不为每条文案拆一个测试。

| 核心组 | 必须证明的结果 |
| --- | --- |
| 内容提取 | 正常 Word/WPS 的中英文、标题/列表、手动换行、普通表格、带图片文本可用；预览文本与绑定及模型输入快照一致，非仅“上传 200”。脚注尾注不混段；未处理修订明确拒绝。 |
| 拒绝与资源 | 伪 DOCX、加密/损坏、空文档、超大小/字数、解压超限和超时被拒绝；无外部关系读取，无遗留永久坏文件，不把解析器错误原文暴露。 |
| 权限与幂等 | 他人不能预览/绑定；重试不重复素材；文件内容篡改不能新引用；审计/素材列表没有提取全文。 |
| 草稿与恢复 | 混合 10 个、再加第 11 个、长文件名、单个失败、上传中移除后迟到、切技能保留；已上传但预览响应丢失只重读，已接受任务仍用原文字。 |
| 费用与兼容 | 上传失败无会话/费用记录；有效材料随现有任务一次冻结；重放受理/恢复不重复冻结。用本地模型/供应商桩完成一个文档创作闭环，不重复整套真实付费测试。TXT/MD、历史作品与其他工具媒体类型不回归。 |

浏览器使用隔离实例和合成文档，按用户既有验收偏好由 6.1 Terra Ultra 操作：桌面主路径、390px 混合多附件/失败恢复、320px 长文件名与预览关闭，深浅主题各取代表场景。检查卡片紧凑、可点击预览和移除、菜单正确关闭、无页面横向溢出；不是“所有技能 × 所有格式 × 所有屏幕”的穷举。软键盘/真机不可用时明确未覆盖。

此功能不依赖新的真实供应商测试预算。实施验收仅需本地桩；如发现只能通过真实模型验证的具体问题，再单独报预算。验收记录区分源码判断、局部测试与浏览器实测，不把尚未开发的结果提前写为通过。

## 9. 自审结论

| 检查 | 结论 |
| --- | --- |
| 是否真正减少用户操作 | 上传一个 DOCX 即可使用，预览可选，没有格式转换向导、解析确认或新增收费弹窗。 |
| 是否只改文件选择器 | 否。上传字节检查、服务端提取、持久化、预览、绑定与冻结输入都有明确落点。 |
| 是否复用当前能力 | 上传、所有权、存储配额、会话材料、卡片、错误恢复、计费和成本中心保持单一链路。 |
| 是否漏掉安全或恢复 | 已明确展开量/超时、私有全文投影、幂等、事务外解析、原文完整性、历史稳定与失败清理。 |
| 是否过度设计 | 两个专用库分别承担文档和 ZIP 解析，薄线程承担有界执行；没有新服务、队列、数据库表、通用插件框架、RAG 或文件管理后台。 |
| 是否擅自扩大产品范围 | 无 PDF/OCR、图片识别、在线 Word 编辑或导出；不借 DOCX 改动 Skill 流程。 |
| 是否改变收费 | 本地解析免费；后续创作沿用原价格、冻结/结算/恢复和调用成本记录，既有预算不调整。 |

方案已补正三处容易遗漏的边界：10 个附件不等于合计文字无限制；全文不能随 metadata 进入审计/列表；已绑定 DOCX 不能因解析库升级被重新提取覆盖。上述为实施验收要求；实际结果与未覆盖项见 [DOCX 验收记录](reviews/2026-11-13-assistant-docx-acceptance.md)。

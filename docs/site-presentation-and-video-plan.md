## 1. 目标与产品边界

在后台“内容”分组的独立“栏目管理”页面中管理前台栏目入口的名称、显隐、顺序及列表数量，允许按现有内容条件新建栏目，并提供可靠的全站视频列表。复用现有后台布局、组件、色彩、字体和导航分组风格，保持内容发布流程。

先区分三个概念：

| 对象 | 本次管理什么 | 不改变什么 |
| --- | --- | --- |
| 站点栏目入口 | 预置栏目显示名称、显隐和组内顺序；按已有内容条件新建的列表栏目 | 对应业务功能、采集启停、后台入口、既有内容权限；改名不修改 ID/路径 |
| 内容分类入口 | 模型、产品、行业、论文、教程、观点的显隐与顺序 | 分类 key、文章归类、模型提示词、日报分节、分类 RSS/API |
| 展示数量 | 精选每批卡片数、全部动态/视频每页条数，以及每个自建栏目的每页条数 | 实际入库数量、精选门槛、热点排名算法、报告生成数量 |

“显示几个栏目”由勾选结果计算，不另存一个可能与显隐冲突的栏目数量。“每页几条内容”才是单独的数值配置。

新栏目是既有公开内容的一个浏览入口。例如“产品资讯”使用产品分类、“Agent 专区”使用 Agent 标签、“产品视频”使用产品分类加已确认视频条件。符合条件的新文章按现有发布流程公开后自然进入，不需要再建采集订阅、不复制文章、不触发模型。这里的“全部公开内容”精确指**现有全部动态的公开池**，仍遵守 `eligible`、公开范围与发布时间等条件，不扩大到所有入库材料。

### 已确认的隐藏语义

用户已于 2026-10-24 确认：**隐藏栏目只移除导航/分类入口，旧链接仍可访问，内容权限保持不变。** 展示开关不禁用路由，不改变来源参与模式、文章公开范围、全文权限、入选状态或采集任务。隐藏分类后，其文章仍可出现在未筛选列表中；RSS、公开 API、MCP 及报告继续遵循原有规则。

### 已确认的视频观看方式

用户已于 2026-10-24 确认本期采用：**视频列表 → 现有内容详情 → 原站观看**。使用已有且符合展示权限的封面，没有封面时展示视频占位标识。复用现有详情和原文链接；本期不实现站内直接播放，也不新增下载、转码、播放流续签、上传发布或私有生成产物的公开路径。

### 已明确的视频栏目范围

用户最新确认覆盖**全站已确认包含视频的公开内容**：包括抖音、快手等视频作品，以及带视频的 X 推文、微博、公众号/普通文章和含视频的混合图文。平台、供应商和 `news/x` 频道均不是排除条件。

展示单位仍是一条原内容：一条推文或文章包含多个视频，也只展示一张内容卡片，不拆媒体、不复制文章。纯图片、纯动图、只有视频封面/标题/链接而无可靠视频语义的记录暂不纳入；信息不足表示未知，不等于已确认无视频。引用/转发链接本身不是证据；已随本帖取得且能核实引用关系、作品身份和真实视频类型的内嵌引用可算作本帖含视频。只有链接或关系/媒体缺证的保持未知，不改变既有 X 转发导入限制。

此前“只收主体视频、排除 X/普通文章附件”的约束已被本次决定替代。撤回拟议的 `primary:true` 及主体/附件分类，改用第 5.2 节的一项轻量含视频确认信息。现有公开资格仍是前置条件，不因确认有视频就自动发布。

用户已于 2026-10-25 最新确认后台入口边界：**“内容”分组增加“栏目管理”，设置页不保留该功能的入口或说明。** 此决定替代此前“设置页保留跳转”的安排；后台共用导航照常显示，不因当前在设置页而隐藏。栏目管理不出现在前台可编辑导航定义里，不能被自己隐藏。

一期产品选择已经确认并实施。新增栏目的筛选范围、独立管理入口及追加开发已确认，其余常规实现细节按本方案执行。具体路线尚缺的含视频证据见第 9 节，真实数据操作和真实调用仍须单独确认。

## 3. 栏目管理的操作流程

追加开发前路径：后台 **设置 → 前台栏目与展示**。

当前已实现路径：后台 **内容 → 栏目管理 → 新建/编辑/调整 → 保存更改 → 查看栏目**。后台地址固定为 `/admin/columns`；前台自建栏目仍为 `/columns/:id`，两者不混用。独立的是管理页面入口，保存与内容查询继续复用现有能力。

- 在后台“内容”分组的“内容诊断”之后加入“栏目管理”；沿用现有 NAV 派生桌面/手机入口和选中态，不加栏目数量徽标或额外导航计数查询。
- 设置页移除原栏目区域及其草稿/提交处理，不保留栏目说明、跳转链接、只读清单、保存按钮或嵌套编辑页。后台共用导航的“栏目管理”仍正常存在，避免为当前页面再派生另一套导航。
- 前台栏目、分类入口和列表数量全部移入同一管理页。二维码、通知目的地和预算仍在设置页。既有信源、采集订阅、数据工具、执行记录和后台认证不随栏目设置变化。

### 3.0 页面组织与组件复用

采用现有 AdminPage、Card 和行布局组织同一页面，不增加多层管理路由、拖拽依赖或设计体系。页面顶端保留一个“新建栏目”按钮；正文依次为“站点栏目”“分类入口”“默认列表数量”，其中分类入口说明为“控制前台分类筛选栏，不新增分类”。

| 位置 | 操作与反馈 | 直接复用 |
| --- | --- | --- |
| 栏目列表 | 按既有内容/模型/更多组列出名称、预置/自建、显示状态、内容范围摘要、适用的数量及操作 | 现有分组/EntryRow 局部扩展，Badge、Button、现有字体/间距/颜色 token |
| 行内编辑 | 点击编辑展开，名称/分类/标签/含视频条件/数量就地修改；不另开抽屉或详情管理页 | Field、Input、Select、现有复选框和同一 presentation 草稿 |
| 排序及显隐 | 同组上移/下移和显示开关；端点禁用，精选固定；改动暂存在草稿 | 现有移动函数、校验和按钮反馈 |
| 保存区 | 单一“保存更改”按钮、未保存提示、放弃修改、恢复默认及上次保存时间；恢复默认的保留/隐藏语义写在旁边 | 现有 useAdminAction、保存回显及 Toast；只有一条操作区，长页置于页尾并在窄屏换行 |
| 查看 | 已保存栏目打开前台新标签页；未保存的新栏目提示“保存后可查看” | 现有链接风格与安全的新标签页属性，不增加草稿预览 API |

预置栏目不能用自建筛选器改变原业务：其内容范围显示“系统栏目”，仅按已有能力改名、显隐、排序及适用数量。精选/全部/视频的数量仍只在“默认列表数量”编辑一次，行内仅显示该值；自建栏目的数量在自身行内编辑，其值不再出现在另一份数量表。热点榜、日报等不适用页大小的位置显示“按原页面规则”，不制造无效输入。

窄屏继续用同一行结构换行，名称、范围和操作可完整访问；不为复用 DataTable 而强塞其最小 640px 宽表，也不复制桌面/手机两套草稿。保留现有深浅主题与语义颜色，状态有文字，长名称和标签可换行，字段有标签，按钮可键盘操作。默认只显示范围摘要，例如“产品分类 · Agent 标签 · 仅含视频”；展开后解释分类与标签需同时满足。

### 3.1 编辑方式

- “站点栏目”按现有内容、模型、更多分组列出。可配置项提供显示开关与上移/下移；“精选”显示固定状态，不提供隐藏开关。顺序由数组位置表达，不同时保存另一份排序数字。
- “分类入口”单独列出六个既有分类，提供同样的显隐与排序操作。显示“已显示 N 个”，不让管理员编辑分类 key、模型分类规则或日报结构。
- “列表数量”使用有上下限的数字输入，见第 4 节。
- 草稿只在当前编辑器内，行内输入直接修改这一份草稿；“收起”只收起编辑区，不表示保存或撤销。取消未保存的新行仅移除该行；“放弃修改”恢复整份已回显的服务器配置。“恢复默认”对预置项恢复行业默认；已有自建栏目保留定义并隐藏，放到内容组末尾，避免因恢复默认破坏已保存链接。后者仍需保存才生效；操作旁明确说明该语义，不建设配置版本平台或发布审批流。
- 显隐/排序/编辑均不即时写入。出现修改后显示“有未保存修改，离开或刷新会丢失”；统一保存整份配置，提交中禁用新建及编辑/保存操作，复用现有重复提交保护。字段错误在对应行可见，必要时展开并定位首个错误；不把被折叠的无效行变成无法解释的禁用按钮。
- 保存后以服务器响应同步已保存值和当前草稿，显示修改时间；自动 revalidate 不覆盖仍未保存的草稿。网络错误、输入错误及服务故障保留当前草稿，提供重试；401 沿用现有登录跳转，重新登录后需重新填写。不额外建设跨登录/跨页面草稿存储或全站离开拦截机制。
- “查看栏目”只指向已保存内容并在新标签页打开，避免离开当前草稿；已有栏目有未保存改动时标明“查看已保存版本”，新建草稿保存成功前不提供可访问链接。保存成功不承诺前台缓存即时刷新，沿第 6.3 节说明生效时效，不增加后台内容预览器。

### 3.2 固定边界与多端一致性

- 首页 `/` 的“精选”入口固定显示，后台标出固定原因；桌面与手机都不能隐藏，服务端也拒绝隐藏该入口的配置。“全部”分类重置项固定显示，避免所有筛选入口被隐藏后无法恢复。保留“一手”的既有筛选语义，本期不把它伪装成内容分类。
- 桌面导航：同一分组内按配置排列，空组不显示；允许第 3.3 节的显示名修改，不新增跨组拖拽、任意 URL 或图标上传。
- 新“视频”入口位于内容组“全部动态”之后，默认隐藏，可在同组调整顺序。
- 手机底栏：沿用当前“精选、全部、日报、更多”的位置体系，“精选”和“更多”固定显示，“全部/日报”可隐藏，业务项按共同配置应用相对顺序，“更多”仍在末尾；不自动把其他业务栏目塞入底栏。可见项减少时等分布局。视频及其余可见入口在“更多”页展示。
- “更多”页从同一入口清单派生，过滤底栏已经显示的入口；保持现有“内容/偏好/关于”卡片分组，它与桌面的“内容/模型/更多”并不相同。允许每端保留固定的布局映射，各组内消费同一显隐与相对顺序，不保存第二套可编辑配置，也不为了代码统一重排现有 UI 分组。外观切换和法律链接保留。
- 页面匹配关系由当前实际底栏派生，包含日报/周报/月报的既有归属；非底栏页面继续归“更多”，不能保留一份失真的 `MORE_PATHS`。
- 模型榜/监控被 `FEATURES` 关闭时，后台显示不可用原因；展示配置不能重新开启其路由、接口或任务。
- 隐藏分类后，未筛选列表仍可出现该分类文章。直达旧分类 URL 时显示当前筛选说明和“清除筛选”，不悄悄切换到另一类。
- 条款、隐私、备案、品牌回首页等基础入口保持现状，本期不纳入运营隐藏开关。
- 初始默认值保持现有入口与数量；新“视频”入口默认隐藏，完成本地验收并确认上线范围后再显式开启。

### 3.3 预置栏目改名

- 同一编辑行提供“显示名称”，只存一个可选覆盖值；留空使用行业/导航原默认名。修改稳定 ID 所对应的名字，不按旧名字查找栏目。
- 桌面侧栏、手机底栏（如该栏目本来在底栏）、更多页和后台同一行使用一致的覆盖值；未改名时保留现有“全部/日报”等短名称与更多页文案。不额外持久化桌面名、手机名、SEO 名等多套名称。
- 对应列表页的栏目标题、浏览器标题及“返回某栏目”等指向该栏目的文本同步使用覆盖值。带日期的报告标题、榜单名称、关于页品牌文案、反馈提示等内容标题继续表达原业务含义，不做全站字符串替换；首页站点级 `SITE.homeTitle` 仍由行业品牌配置管理。
- 所有改名均为纯文本，去首尾空白后 1–20 字；长名在窄屏省略或换行并保留完整可访问名称。预置项留空恢复默认，自建列名不可为空。无自定义 HTML、URL、组件名、图标上传或国际化词条管理。
- 精选身份仍为固定显示的首页入口，可以改其显示名；手机“更多”为结构入口，不纳入新建或改名。修改“模型榜”名称不启用被 FEATURES 关闭的模块。
- 本轮改名指**站点栏目名称**。现有“模型/产品”等分类词典、文章分类徽标及模型规则维持原意；可以新建一个名字不同、使用该分类的栏目。若要全站重命名分类字典，需作为独立产品选择确认。

### 3.4 新建栏目的最小表单（内容条件已确认）

用户已确认先支持“产品资讯”“Agent 专区”“产品视频”及“产品分类中带 Agent 标签的内容”等方式。仅提供以下字段，不做任意条件编排器：

| 字段 | 建议行为 |
| --- | --- |
| 名称 | 必填显示名称；创建后可改名 |
| 只显示含视频的内容 | 复选框；不勾选为现有全部动态公开池，勾选为已确认含视频的公开内容。内部仍只有 all/videos 二选一，不再增加第二个“范围”开关 |
| 分类 | 可选一个当前行业分类，不选则不限分类 |
| 标签 | 可选一个标签，精确匹配；提供现有行业词表建议并允许输入合法实际标签 |
| 显示 | 新建默认隐藏，可在第一次保存时明确勾选显示；隐藏后仍可通过直达链接访问 |
| 每页条数 | 独立 1–40；新建草稿默认复制所选全部/视频列表的当前数量，保存后独立维护 |
| 顺序 | 进入内容组末尾，可与预置内容栏目一起上移/下移；数组顺序为唯一顺序 |

分类与标签同时填写时取交集；未填写时不限该项。空标签不是“无标签”。内部 `entity:` 标记不作为本轮可输入标签，避免把内部实体标记当作普通展示标签；不新增分类、标签或模型规则。不允许本期保存多分类 OR、多标签表达式、任意 SQL、来源权限条件或外部地址。

标签沿现有精确匹配与最长 60 字限制；分类自身隐藏只隐藏原筛选入口，仍可被自建栏目使用。不同栏目可以同名，内容和路由按稳定 ID 区分；不为显示名新增唯一性索引或自动改名规则。

后台仍用同一表单草稿：点击顶部“新建栏目”在内容组末尾添加并展开编辑区域，定位到名称；同一时刻只保留一个尚未保存的新建行，再点新建定位已有草稿。可取消该新行，保存后允许继续新建。无内容时前台展示正常空态和已配置范围，不扩大查询或自动采集。保存后的栏目先用隐藏/编辑管理，本期不增加删除入口；隐藏、改名和恢复默认均不破坏旧链接。

新栏目使用不随名称变化的系统 ID，例如 `custom-<uuid>`，前台固定路径 `/columns/:id`。草稿创建时生成一次，重试保存沿用该 ID；服务端校验格式与唯一性，不允许借 ID 覆盖预置栏目。没有可编辑 slug、改名重定向表或多级栏目树。自建栏目在桌面内容组、手机“更多”的内容组出现，不扩展固定手机底栏。

### 3.5 新栏目到内容的读流程

`/columns/:id → 现有 /api/site/pool 的 columnId 参数 → 严格读取已保存栏目定义 → 同一 loadPool → 共用 PoolPage → 现有内容详情`。

- API 从配置解析该栏目的固定范围、分类、标签和默认数量。访客只传栏目身份和 `q/tab/page/pageSize`；同一请求混入 category/tag/videosOnly/channel/topic 等其它筛选参数时返回输入错误，不能覆盖或绕过定义。
- 将解析后的分类、标签、视频条件直接传现有 pool 的单套条件和计数缓存键，无需增加第二层查询范围或另一套 SQL。默认 pageSize 由栏目决定，浏览中明确携带的合法 pageSize 沿用第 4 节的稳定分页规则。
- 本期自建栏目页只提供栏目内搜索、时间/相关排序、分页；固定条件以简洁说明显示。去掉关键词/清除搜索只清读者搜索，不清管理员条件。避免再放一排可替换固定范围的分类标签控件。
- 卡片的分类/标签若可点击，明确指向现有全站分类/标签浏览（沿用 `/all`，视频栏目可沿用 `/videos`），属于离开栏目查看该分类/标签；不假装在栏目内再叠加第二标签，也不改现有 pool 为多标签规则引擎。标题/正文入口、视频封面仍进入同一详情。
- 详情继续使用原内容身份和现有返回逻辑：从栏目在同标签页正常打开详情后，返回恢复上一页地址和原查询；新标签页或没有应用历史时，仍按内容入选情况回到精选或全部动态。本期不额外承诺跨标签页还原栏目，不新增 `returnTo`、返回路径校验器、浏览历史或详情缓存分支。
- 栏目 ID 有效但被隐藏，直接访问照常；严格读取成功且没有此 ID 才返回 404；配置故障返回可重试错误，不能降级成全站无条件列表或伪装成不存在。公共导航壳仍可用行业默认降级。
- 复用搜索繁忙页组件；重试链接保留栏目与搜索上下文，“浏览栏目”可以清关键词/排序/页码，但保留栏目和有效页大小。不把自建栏目错误回退到全部动态。
- 必须接通现有错误映射：网站 API 的 `siteHandler` 为实际 `SearchBusyError` 返回可识别的 `search_busy` code，Web `loadOr404` 仅对此 code 使用 busyRedirect；其它 503 保持暂不可用错误。自建配置读取失败/分类失效显示“栏目暂不可用，请稍后重试”，不能声称“清搜索即可浏览”。在既有响应结构内区分 code，不新增错误框架；`/all`、`/videos` 的真实搜索繁忙流程同步保持有效。
- 页面标题、canonical 与分享地址使用真实 `/columns/:id` 和生效的读者参数，沿用现有搜索页 noindex 规则；栏目改名不改 canonical。文章 canonical、原文和分享身份保持不变。

## 4. 展示数量与分页契约

| 配置 | 默认值 | 建议有效值 | 精确含义 |
| --- | --- | --- | --- |
| 精选每批数量 | 20 | 整数 1–40 | 每批最多多少张聚合卡片，不是卡片内所有报道条数 |
| 全部动态每页数量 | 40 | 整数 1–40 | 包括其分类/搜索结果，每页最多多少条公开内容 |
| 视频每页数量 | 20 | 整数 1–40 | 视频范围内分类/搜索后的每页条数 |
| 每个自建栏目 | 创建时复制所选列表当前值 | 整数 1–40 | 该固定内容范围内每页最多条数，之后与其他栏目独立 |

不足设定数量时显示实际结果；不能为凑数放宽相关性、精选或权限规则。数量 0 不表示隐藏，显隐使用独立开关。

同一列表中的六个分类筛选共用该列表的数量配置，不为每个分类本身保存一套页大小；自建栏目有独立身份，因此拥有自己的页大小。

首页热点条、热点榜、主题目录及日报内部结构各有现有读模型或生成规则，本期不把它们改为统一的“任意栏目数量”。如需改变这些内容数量，应单独确认对应产品含义。

实现约束：

1. `/api/site/timeline` 和 `/api/site/pool` 的网站请求使用后台配置。公开 v1、RSS、MCP 的 limit 和输出契约不随网站设置改变。
2. 精选保留现有锚点游标；改变批次大小不会改变排序/聚合身份。恢复已读/返回位置继续使用现有快照，不新建持久状态。
3. 全部和视频复用同一个 pool 查询。返回实际 `pageSize`，分页链接带上这次浏览的有效大小，避免管理员在用户翻页途中改数量而造成 OFFSET 跳跃；新增浏览从当前配置开始。
4. 保持现有最多 2,000 条的浏览/计数范围。页数和允许的最大页码由实际大小计算，同步修正原来固定 50 页的解析与分页逻辑。末页 LIMIT 为 `min(pageSize, 2000 - offset)`：例如每页 30 条时第 67 页最多 20 条，不能读到第 2,010 条。页大小参数必须是合法整数、最多 40；不可借参数扩大查询规模。
5. 视频条件贯穿列表、搜索的两种排序、总数、今日数量及计数缓存键。不能只过滤本页已取出的 40 条，也不能拿全部内容总数充当视频总数。
6. 保持现有首页搜索进入 `/all` 的规则，带上适用的分类条件；全部动态搜索仍在 `/all`。视频页搜索、分类及分页始终保留视频条件，不能跳回全部内容。筛选变化回第一页。

## 5. 视频内容如何接通

### 5.1 同一条内容，多一个浏览维度

视频是内容形态，不是第七个行业分类，也不是新的 `news/x` 频道。同一条公开内容可以同时出现在全部动态、视频列表和已有精选中；不复制文章、不创建视频发布状态。

公开候选必须同时满足：有可靠的本条内容含视频证据、已经进入统一材料链、满足当前公开列表资格。仅保存在执行结果中的查询数据、隔离信源材料、私有素材与生成视频不进入列表。视频页默认跨 `news/x`，不继承排除 X 的频道条件。

新增 `/videos` 页面，通过现有 `/api/site/pool` 的受控视频筛选参数读取。复用已有分类、搜索、日期列表、分页与空态。一个局部视频 SQL 条件复用于列表、时间/相关搜索、总数及今日数量；在翻页前筛选，通过 article_id 关联媒体，不能只在取出的一页内过滤。保持现有 publication 资格及 source 撤回机制，不另写第二套内容查询。

### 5.2 最小媒体契约

复用 `articles.media` JSONB，不新增视频表、文章类型列或另一份发布状态。媒体事实由受控入口及材料领域负责，公开资格继续由 publication 负责。

- **媒体层唯一新增持久字段：现有 video 媒体项的可选 `confirmed:true`。** 它只表示“已根据本路线/正文契约确认这条内容包含真实视频”，不表示公开、精选或人工审批。视频筛选要求同一个媒体项同时 `kind=video` 且 `confirmed=true`。不同时保存 `has_video`、`primary`、来源平台推断或另一个状态。
- 这个字段不能直接省掉：旧 SocialData 把 `video` 和 `animated_gif` 都存成 `kind=video`。缺少确认字段的旧记录保持原显示行为，但不自动进入新视频列表。新 SocialData 输入仅原始 `type=video` 可确认，`animated_gif` 不确认；无需扩大既有公开 kind 枚举或批量改写所有 GIF。
- video 允许没有播放流地址和封面；image 的有效图片 URL 仍必填。兼容既有 video.url，不把原文网页地址冒充媒体 URL，不为栏目保存临时播放流。无媒体 ID/地址时最多合并一个含视频事实项，避免每次重试叠加占位。
- `articles.media` 是视频筛选的唯一权威。X 的 `x_post.media` 继续承担既有帖子显示；不复制确认字段、不同步维护第二份筛选状态。X 卡片已有媒体预览时不再加一套重复缩略图，必要时用同一公开媒体投影补有据封面。
- SocialData 已有 `quoted_status` 内嵌对象，引用文字也已进入父帖正文；在现有适配点局部校验父帖明确引用关系、引用帖数字 ID/作者 handle、原始 `type=video`，父帖若同时携带引用 ID 则须相符。通过后只向父材料 articles.media 合并含视频事实，沿用原引用关系；不把引用封面冒充父帖封面、不改父作者/来源、不另建文章或持久 role，不递归查询。旧 quoted.media 的 kind=video 已混入GIF，单独不足以确认；其他供应商引用关系/媒体未证时保持未知。
- 可使用明确作品类型、媒体附件类型、官方说明为“含视频”的严格布尔值、已核实字段语义的视频链接或专用视频作品契约。必须关联到当前作品；封面、时长、平台名、标题、任意 mp4/网页链接不能单独作证。图文类型与视频附件可以同时成立，不能按旧主体口径当作冲突；同一对象明确声明无视频却同时带正向证据才是需保守处理的冲突。
- 尽量消费现有已验证 record；需要原回执的路线只在既有证据验证通过后抽取媒体事实，作为内部导入参数。AgentKey 现有结果严格投影比较保持兼容，不给旧 operation_results 强制补字段、不弱化证据验证，不让任意 raw 进入标题正文。
- 网站 DTO 只增可空的视频预览字段；封面按现有 URL 校验、代理与权限输出，原站链接仍来自文章。confirmed 不对外成为新业务状态；raw、下载地址、私有产物不输出。
- 检查受影响的图片代理、图像模型及正文消费方：无 URL 的视频事实不传入图片处理，播放流不能误当图片。保持旧图片及 X 动图显示兼容。

### 5.3 卡片与详情

- 沿用现有卡片、日期分组、小图和 X 帖样式，增加一个明确视频标识；不做短视频瀑布流、自动播放或重复媒体区。
- 标题/封面进入现有详情，再通过“去原站观看”打开原文。保留来源、收藏、已读与返回列表位置；有多个视频仍只打开原内容。
- 缺封面或坏图用本地占位，不排除合格内容，不请求供应商补图。
- 普通文章封面沿用现有 `body_mode` 权限，summary 模式不新增正文图片；X 保持既有媒体展示例外，不把该例外推广到其他来源。文字摘要可公开并不授权播放流或全文公开。
- `summary-only`、撤回、隔离、未到公开时间按既有公开规则处理；确认含视频不绕过这些规则。
- 不扩大正文 HTML 的播放权限，不因原 HTML 已允许某些 `<video>` 标签而建设统一播放器。

### 5.4 非供应商入口的最小覆盖

“全站”是跨现有来源筛选，不等于替所有未知记录追查视频。除已接平台外，只在已经拿到的数据中识别明确事实：

- **RSS/Atom**：在现有 XML 解析中读本条 enclosure 的明确 `video/*` MIME，Atom 用 `rel=enclosure` + `type=video/*`；Media RSS 的本条 `media:content` 只按明确视频 MIME/medium 及无冲突条件识别。媒体地址须有效，只有缩略图/播放器链接不够。复用候选 media，不增请求或另一套 feed 解析器；保留视频事实，不受现有“最多六张图片”的截断影响。
- **已有正文 HTML**：在现有正文提取/材料保存中识别正文范围内明确的 `<video src>` 或 `<video><source src type=video/*>`。使用已安装 DOM 工具与既有 URL 规则；只处理已经取得且关联本条正文的内容，排除代码示例、站点装饰及广告区域。对 sanitizer 会去掉的 source，可在已确定正文片段、净化前只抽取事实，HTML 公开许可保持原状。
- **JSON/外部 ingest**：不把任意 raw 中的 video 字样当作可信结构，也不扩展对外写入协议。若沿既有处理取得明确正文则走同一正文识别，否则未知不纳入。将来有实际调用方要报告媒体，再单独定义其输入契约。
- 不解析任意 JS、iframe、懒加载私有属性或新增通用 VideoObject/浏览器爬取框架；不为识别触发 Jina、供应商详情或模型请求。依赖这些才能确认的内容属于暂不纳入项。

## 6. 数据保存、状态归属与缓存

### 6.1 一份设置，没有第二套业务权威

独立后台页面的读取和保存仍归既有 presentation 模块：

- `/admin/columns` loader 使用现有 `adminGet` 读取 **GET `/api/admin/settings/presentation`**。这是在已有保存资源路径上补 GET，直接调用 `loadPresentationSettings()`，复用现有 `AdminPresentationSettings` DTO、adminHandler 认证及禁止缓存响应；不增加栏目 service、另一套 DTO 或 `/api/admin/columns` CRUD。
- 写入继续使用原 **PUT `/api/admin/settings/presentation`** 和 `savePresentation()`，settings key、锁、审计动作与权限不因 Web 页面换路径而改名。
- `/admin/settings` 继续读取原 GET `/api/admin/settings` 的二维码、通知和预算。迁移编辑器时，将本分支添加的 presentation/defaults/updatedAt 从该聚合返回及 Web Settings 类型中移出；该页不再展示或读取栏目配置。当前代码中的消费者只有设置页和本次 presentation API 测试，需同步改读新 GET；不重命名原设置路径，也不把预算/二维码链接批量改成栏目管理。
- 两个 GET 只拆原有读取职责。栏目配置异常不能使预算设置打不开，通知/预算读取失败也不应挡住栏目管理。沿用现有错误页/重试；不兜底为空表单后允许覆盖。

继续保存同一条 `settings.site_presentation`。在已有 navigation 数组原位扩展，不另建自建栏目清单后再维护另一份排序关联：

| 数据 | 最小形状及归属 |
| --- | --- |

- 行业默认仍在 `industry/`。旧设置缺少 label 或自建行时保持当前行为，无须为旧值补写数据库。预置 ID 有限、自建 ID 格式受限；字段白名单和逐项长度、类型、数量校验，不接收 HTML、组件名、SQL 或任意条件表达式。
- `contracts/presentation.ts` 和 `admin/presentation.ts` 同步扩展解析/规范化：保留合法自建行，不再因默认清单没有它而删除；缺少的预置项按默认补齐。展示名称/分组/链接通过现有导航模块的小函数解析，不做插件注册器。
- 保存沿用现有事务、同 key 锁、upsert 与审计；整份配置及审计共同成功，返回服务器规范值和修改时间。仍是最后一次有效保存，不新增版本令牌、自动合并或冲突编辑器。
- 由于本期没有删除操作，锁内读取当前值后，若提交漏掉任何已经保存的自建 ID，拒绝本次保存并提示刷新后重试，保留草稿。这只防止旧表单/并发新建把栏目及旧链接删掉；不把它扩展成通用并发版本系统。“恢复默认”也必须保留这些 ID 并按第 3.1 节隐藏，走同一保存接口。
- 行业升级移除的预置项不再显示，新增预置项按行业默认补齐；不能重新开启 FEATURES 关闭的模块。如果自建栏目引用的分类不再存在，保留该定义并在后台指出待修正项，该栏目显示配置暂不可用，不自动去掉分类扩大结果；其他合法栏目继续可用。不持久化另一项“可用状态”。标签不在建议词表不等于无效，合法标签可正常返回空结果。
- 后台读取失败显示错误，不能伪装成空配置再覆盖。公共元数据可使用默认导航降级；读取自建内容时必须严格解析对应定义，缺失返回 404，配置故障或已失效的分类返回 503，不使用全站默认条件替代。隐藏不参与内容访问判断。

### 6.2 媒体补齐不触发重新分析

当前 `contentHash` 不含媒体。`upsertMaterial` 的旧媒体填空早于旧 hash/seen 判断，正文修订又会全量写 media；因此确认信息必须在这些现有分支中一致处理，不能只在后台查询或新插入路径接通。

- 在同源/同作品校验、文章锁及当前 revision/media 快照下合并。保留既有图片，未知输入不清除确认，不能让旧 seen 结果在早退之前补回已纠正的标记；正文修订分支也使用相同规则。
- 不同类型字段的作用范围要区分：普通图文类型并不反证没有视频附件。明确反证必须覆盖本条完整媒体，并能利用已有来源更新时间/结果关联证明未过时；无法证明新旧顺序或事实冲突就跳过并列入补齐报告，不新建媒体事件流或版本状态。`articles.raw.resultId` 不会随所有更新刷新，不能当作最新证据时间线。
- 单纯媒体修正不改标题正文、content hash、revision、处理状态或模型结果，不入队分析。若现有正常采集同时带来正文修订，其原有处理继续执行，不能把正常修订伪装成 metadata-only。
- 连接点覆盖手工导入、平台订阅及主采集。已有媒体非空也可补；已导入结果可继续幂等返回，历史补齐直接调材料领域受控合并，不重放导入任务。
- X 必须覆盖 SocialData `tweetMedia → xPostToCandidate`、Redfox 主采集与搜索导入，以及未来补证后的 AgentKey X 导入/订阅；公众号覆盖 `wechat-collection → importWechatResult`、Redfox `mp-redfox-execution` 主入口与手工详情导入。RSS 候选和现有正文提取的媒体保存也调用同一材料规则，不另建视频执行器。
- AgentKey X/微博缺媒体输出证据时保留现有安全投影，不为让某供应商“全绿”猜字段。缺口只影响对应记录视频资格，不改变已有查询/订阅功能。
- 本次仅网站 DTO 增预览，v1/RSS/MCP 字段、selected ledger 不变；不为媒体单独增加公开 revision。ETag 已按响应内容计算。
- 不新增回执、预算、任务状态或恢复流程。事务失败回滚，重复运行幂等；正常采集原有付费边界不变，媒体识别/展示本身不新增网络请求。

### 6.3 配置与页面刷新

- 复用 `/api/site/meta`，仅公开可安全展示的配置；后台修改人、审计理由不返回公共接口。
- 一期已恢复 root 正常导航时的元数据更新，追加改名和自建继续沿用，避免整个浏览会话永久沿用旧栏目。后台“查看前台”使用完整文档导航；不增加定时轮询或全局推送。
- 保存后台值立即可回读。公开页面遵循现有 HTTP/SSR 缓存，到期/重新验证后更新；必须在保存反馈中说明刷新与缓存时效，不承诺全站即时变化。meta 当前为 60 秒；部分完整页面比它更长，不能用 meta TTL 冒充全站上限。
- 栏目隐藏不是权限撤回，因此不为它引入 CDN 清理服务。内容权限变更仍走既有即时读过滤/投影/缓存规则。
- 媒体新字段进入响应 ETag；视频筛选加入 pool 计数缓存键。进程内计数缓存最长 30 秒，前台可见时效还受上述 HTTP/SSR 缓存影响，不能把 30 秒当作端到端更新保证。

## 7. 历史内容与迁移收尾

本方案不新增业务表，也不预设必须新增 SQL 迁移。JSON 媒体形状扩展和设置键可增量落地；索引只在代表性本地数据的查询计划显示必要时增加，不先建一套视频索引体系。

追加的改名/自建同样只扩展已有设置 JSON，不改文章分类、不回填标签或复制历史内容。旧的无名称覆盖配置正常读取；新建栏目保存后立即按既有公开池筛选历史及后续内容。稳定 ID 不随改名、显隐、排序或恢复默认改变。

后台入口迁移只调整页面装配与读取连接：移动现有编辑器的唯一使用位置，保留其草稿、写入与审计职责；设置页不留旧编辑器或跳转。原 `/admin/settings` 仍提供其余设置，预算等既有链接不变。同步更新后台路由、同一 NAV、Settings 类型、相关读取测试和截图索引；以前设置页上的栏目截图明确标为迁移前证据，不能当作新入口验收。无需搬迁 settings 数据、双写、重定向表、兼容开关或新的角色权限。

旧版本的规范化会丢弃自建 ID，因此不能宣称任意旧版本均可编辑新配置。交付说明保留这一实际边界：回退到只识别固定栏目的版本前，先备份该 settings 值，停用旧版对此设置的编辑，再按已保存的旧兼容值恢复；恢复新版时再受控恢复自建定义。沿用既有备份/审计，不开发配置降级转换框架。旧版本没有 `/columns/:id` 路由，回退期间这些新链接不可用，应在操作前说明；正常运行中的隐藏/改名不受此影响。

历史视频不会凭空被识别。实施时先用独立测试数据验证，再提供受控本地补齐流程：

1. 只读盘点 articles.media、现有已存正文、已关联结果及可用回执。只按第 9 节证据确认含视频，列出可确认、无证据和冲突数量。旧 X `kind=video` 不能直接转 confirmed；只有仍保留原始 video/GIF 区分的证据才能补，无法区分的继续原样显示。
2. 只处理已存数据，不请求供应商/模型，不重新抓页面。已清理回执不重取，只有封面或无可靠归属的视频信息不补。正文证据只读原始材料正文，不把模型生成 HTML 当事实。
3. 复用结果—文章关联与 typed identity，不能按标题、昵称或相似 URL 串证据。快手/视频号沿已有人工导入的本条原文和核实依据；不能凭不透明 ID 补造作者。历史材料变化或证据顺序不明时跳过。
4. 分批、可重跑、默认 dry-run；脚本调用同一材料领域合并，不另写业务 SQL。真实库执行另行授权，写前备份并留文章 ID、受改字段前后值和证据引用。恢复只在当前值仍等于本轮写入时恢复本轮字段，不覆盖后续更新；清单/备份不进 Git，不输出播放流或原始回执，不新增恢复表。
5. 不重采、评分或改变来源权限、发布时间/回填标记。不因视频页为空开启采集。
6. 隐藏入口不撤回内容；代码回退前验证旧图片消费方兼容无 URL 视频项。旧代码若会丢失确认字段，暂停相关补齐写入并采用兼容版本回退，不宣称任意旧版都能保留新事实；无需独立回退状态机。

### 9.2 剩余缺口与影响

- **X/微博 AgentKey 的媒体结构、抖音部分混合路线及Instagram轮播子项**：官方目前未给足字段，且现有安全投影未留必要信息；只阻塞相应记录确认。后续可先取得官方更具体合同，确需真实响应再单独授权。本次不调用、不换供应商兜底。
- **Redfox X 动图边界**：按官方明确video语义确认，但供应商未说明全部原平台GIF转换，不能承诺上游零误分；已知GIF/矛盾字段不确认。SocialData原始GIF明确排除，旧模糊数据不自动补。
- **只有列表、没有明确类型/附件**：优先已有同作品详情；仍无证据则不入视频栏目，不自动追加详情、转写或模型识别。
- **RSS/网页的脚本播放器、iframe、未取得的正文；JSON/外部raw缺合同**：暂不纳入，不为追求100%覆盖建设媒体抓取框架。内容仍按原有流程处理。
- **快手/视频号作者原文不足**：既有人工核验和隔离要求仍有效，不能用含视频标记解决身份或权限。
- **历史数量和证据保存情况**：本轮未读运行库，不能承诺历史全覆盖。未来授权 dry-run 只读已存证据；缺失的旧X视频/GIF原始区别不猜。

这些缺口只限制具体记录进入栏目，不阻塞栏目管理及已证内容链路。未知、冲突是检查结果，不新增待分类队列、供应商重试任务或持久化状态。

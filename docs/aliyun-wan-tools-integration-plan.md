## 1. 首批范围和产品落点

目标闭环：用户提供一段参考视频和一张人物照片，生成替换主角的视频；用户能看到报价、等待状态、失败原因，并播放、下载本人产物，必要时继续处理原任务。

| 范围 | 首批决定 |
| --- | --- |
| 供应商与模型 | 直连阿里云百炼；只接 `wan2.2-animate-mix`，不经 Redfox/AgentKey 转发。 |
| 模式 | 契约支持 `wan-std` / `wan-pro`；分别配置价格。最小真实验收先验证标准模式，专业模式未实测前单列状态。 |
| 入口 | 用户已确认：前台和 admin 均保留“视频创作”单一导航，内部四个独立 Tab：**文生视频 / 图生视频 / AI口播 / 视频复刻**。“视频复刻”使用独立两素材表单。 |
| 输入 | 一张本地私有人物照片、一段本地私有参考视频。首批按单主角场景验收。 |
| 输出 | 一段本地私有视频，关联原任务、模型、模式、实际媒体信息和供应商任务证据。 |
| 不作为首批承诺 | 多人定向替换、产品替换、逐字台词重写、音色克隆、独立录音驱动、自动裁剪/转码、整段视频百分百还原。 |
| 后续能力 | `wan2.2-animate-move` 可另批提供动作模仿；其他万相模型逐项核对能力和价格后再接，不预建空适配器。 |

原 Seedance 的文生视频、图生视频、AI口播及人物/产品/场景参考保持原供应商与合同。换人表单不展示 Seedance 的提示词、首尾帧、生成音频等无对应参数的控件；不能把新功能描述成可定制声音的 AI 口播。

“视频复刻”首批说明为“上传参考视频和人物照片，替换视频中的主角，参考原动作与场景”。Tab 名是业务入口，不承诺任意视频的精确复刻。

## 2. 当前系统盘点：复用什么，补什么

截至本轮工作区代码，系统没有单独完整的“第三方工具接入 SOP”。通用不变量已存在，具体连接方法散在历史供应商方案及当前实现中。本次应补工具清单，不能沿用工程手册第 5 节的信源接入示例来设计万相。

| 能力 | 当前证据 | 本批处理 |
| --- | --- | --- |
| 用户/管理员入口 | `apps/api/src/routes/user-tools.ts`、`user-handler.ts`，现有后台工具路由 | 复用登录、CSRF、no-store；新增万相创作与续查命令。匿名浏览不发起生成。 |
| 统一任务与结果 | `providers/operations/store.ts`；`0039_collection_operations.sql` 的 `operation_runs` / `operation_results` | 复用 actor＋commandKey 幂等、冻结输入、步骤版本、执行代次/CAS、结果事务。一次性工具的订阅成员为空；不新建万相任务表。 |
| Worker 与轮询 | `providers/operations/queue.ts`、`jobs.ts`、`execute.ts`、`recovery.ts` | 复用 `operations.execute` 和延迟步骤；补显式分发、恢复扫描、只读 poll 和 save 登记。 |
| 回执和次数预算 | `providers/receipts.ts` | 复用 `paidRequest`、原始响应先落库和预算锁；新万相 service 必须纳入缺预算拒绝规则。 |
| 积分 | `users/credits*.ts`、`member_tool_prices`、`member_credit_run_links` | 复用报价、预占、交付结算和原任务续查共享 charge。积分价格由管理员显式设置，不由供应商人民币价自动换算。 |
| 工具归一化 | `users/tool-input.ts`、`tools.ts`、`tool-history.ts`、`tool-read.ts` | 视频分支目前只认 Redfox Seedance；增加明确的 provider/model 分支，包括报价、执行、历史和续查。 |
| 本地私有素材 | `operations/assets.ts`、`users/tool-assets.ts` | 复用不可变文件、SHA-256、归属、删除保护、本人读取。现有 `uploads/redfox/` 路径保持兼容，不为本批迁移旧文件。 |
| 媒体校验 | `operations/asset-media.ts` | 图片已有解码检查；视频仅验证容器头，缺时长/尺寸探测。需先补服务端媒体元数据。 |
| 供应商素材交付 | `providers/redfox/media-upload.ts` | 当前证明绑定 Redfox。新增阿里云交付适配；不复用 Redfox 上传结果或 URL。 |
| 对象存储 | `operations/backup.ts` | 现有 S3/COS 上传用于备份，没有业务媒体 OSS 暂存与签名读取能力；不可默认复用备份桶或凭据。 |
| 产物保存与展示 | `redfox/video-execution.ts`、`lib/http-fetch.ts`、`users/tool-results.ts`、前后台视频结果组件 | 复用安全下载、私有文件登记和播放下载，补万相 save 步骤保护。用户 DTO 不输出签名远端 URL。 |
| 成本统计 | `admin/redfox-costs.ts`、`providers/receipts.ts` 的 attempt.usage | 复用回执用量字段，万相费用按任务去重读取，不新增成本结果类型、表或唯一索引。 |

以上路径除注明 apps/database 者均相对 `packages/backend/src/`。已有 `PlatformOperationDescriptor` 和采集切换的 provider 枚举不适用于视频创作，本批不扩这些协议。

## 3. 先行执行：第三方工具接入 SOP 补充

### 3.1 文档归属

实施前只在工程手册补一节简短的“第三方工具接入”清单：入口与所有权、官方合同与请求性质、配置与预算、素材与产物、成本与积分、恢复连接点及最小验收。链接本方案，不复制项目原则或引入新的审批流程。

**这不是一次全站工具架构改造。** 下面的必要连接点随万相首条完整流程一起实现，不要求先统一其他供应商，不提取通用视频 Provider 框架。历史 Redfox/AgentKey 方案只作背景。

### 3.2 必须先补齐的实现边界

1. **新供应商默认阻断。** `receipts.ts` 当前仅对 `redfox.*` / `agentkey.*` 的缺预算行拒绝。万相必须显式纳入；默认 0 的迁移种子不能代替缺行检查。恢复器未知 provider 的 `COLLECT_ENABLED` 兜底不能成为万相许可。
2. **视频工具的明确分流。** 保留 `videos` / `videos/query` 工具种类及原合同；在视频功能内用明确 provider/model 判别输入、执行和恢复。不能把两种模型全部字段并入一个充满可选项的大表单。
3. **服务端媒体事实。** 报价前取得真实 duration、尺寸、流类型；不信任浏览器填写的秒数。文件与探测结果按 hash 关联，提交时重核所有权、可用性与同一份事实。
4. **按任务费用与按请求次数分开。** 确定供应商计费单位、用户计分取整规则和唯一任务成本身份，再添加价格数据。
5. **完整登记新步骤。** 同批补执行分发、恢复白名单、只读 poll、已落盘恢复、文件删除保护及会员续查参数继承。只加 HTTP client 不算接通。

这些是万相接入所需的局部改动，不表示现有 Redfox/AgentKey 已全部存在同类线上故障。共用 `createRun/paidRequest/queueOperationStep/saveResult/advanceRun`，仅在实际重复的位置提取功能内常量或小函数；不抽取公共上传引擎、状态机或模型注册表。

## 5. 素材交付：正式路径与隔离验证分开

### 5.1 正式路径

使用已授权的私有 OSS 媒体 prefix 和范围受限凭据，不强制新建 bucket，也不默认取得现有备份桶权限。后端交付两份本地素材，生成供应商可读取的签名 HTTPS URL；前端只见本地素材 ID。

对象键按 run＋输入角色＋文件 hash 确定。交付进度只保存 `fileKey/hash/objectKey/expiresAt`，provider、model、actor 和配置身份从原 run 取得。**只复用同一任务的重试/恢复**，不做跨任务上传缓存、证明表或复用选择器。

- 输入交付的签名期限须覆盖允许提交及供应商读取窗口；过期且尚未提交时可刷新同一对象签名，不能改变逻辑回执身份或制造新任务。
- 已取得 task_id 后，上传过期不是重生成理由；继续查原任务。
- 引用中的实际临时 URL 不作为去重身份；身份使用稳定对象/hash 和非敏感配置。请求的受控原始回执与普通日志/用户 DTO 分开处理。
- **前台和 admin 的详情、诊断及导出都走脱敏投影**，仅展示任务 ID、HTTP 状态、主机等必要排障信息，不透传签名参数或完整临时 URL。现有 admin 视频结果组件会输出 `r.data`，不能直接复用其整包 JSON 展示。原始响应先落回执不等于原始响应可透传管理页面。
- 明确签名期限与暂存生命周期，覆盖本地处理和云端有效窗口；优先用 OSS prefix 生命周期清理，不另建清理平台。源文件和本地产物继续沿现有保留策略。
- 复用本地 `stored_files` 与现有配额，不新建素材库。正式 OSS 是供应商交付暂存，不自动成为公开资产库或备份系统。

### 5.2 隔离验证边界

阿里云[临时文件上传](https://help.aliyun.com/zh/model-studio/get-temporary-file-url)仅保留为调研备注：48 小时引用、官方不建议用于生产。**首批不实现该路径**；本地桩、真实验收和正式使用统一走 OSS，避免第二套上传适配器和 fallback。

### 5.3 媒体探测与保存

在 `operations/asset-media.ts` 相邻的功能模块新增受限视频元数据探测。建议使用固定版本 `ffprobe`：只读已校验的本地文件，禁用网络协议，禁止 shell 拼接，限制运行时长、输出量和并发；将运行依赖同步到实际容器。当前仓库没有该依赖，不能假设部署环境已有。

范围仅为本地 MP4 元数据与基本视频流检查，不逐帧分析、不转码、不新增媒体处理队列。探测失败或尺寸/时长越界在提交前拒绝；输出检查容器、视频流、时长、尺寸和音轨存在性，用于验证文件和如实展示。

产物下载继续使用 `guardedDownload` 的 URL/DNS/重定向和大小限制，不附带模型鉴权头。输出保存仍受本地文件上限约束；超限或失效时进入保存待处理，保留供应商成功和成本事实，不能重提交。新万相 save 步骤同时登记在删除保护和恢复扫描中。

## 6. 执行、轮询和恢复

建议 provider 使用 `aliyun`；操作键使用 `aliyun.wan.animate-mix.generate` / `aliyun.wan.animate-mix.query`，步骤限定在同一命名空间。名称需在契约、分发、恢复、预算与测试中一次对齐。

```text
选择两份私有素材 → 服务端校验/探测 → 报价与确认（会员）
  → 同事务创建 operation_run、预占积分、入队
  → 素材交付 → submit → 延迟 poll → 私有保存 → 交付结算
                          ↘ 原任务续查/保存恢复 ↗
```

复用现有六种业务状态 `active/waiting/needs_review/stopped/completed/failed`，不新增供应商专用状态表。远端状态放适配器进度与回执，页面显示由业务步骤和持久证据派生。

| 场景 | 行为 |
| --- | --- |
| 重复点击/本地提交超时 | actor＋commandKey 同输入复用原 run；同 key 改参 409，不重预占。 |
| 上传 | 对同一对象/hash 验证已有交付，失败有限恢复；上传结果不等于生成已经提交。 |
| submit 响应已落回执，业务事务未提交 | 重放解析得到原 task_id，推进 poll，不再 POST。 |
| submit 网络超时且没有可靠 task_id | receipt unknown、run needs_review；禁止自动重发或换供应商。当前合同未确认供应商创建幂等键，不承诺 exactly-once。 |
| PENDING/RUNNING | 下一次 poll 使用递增序号与独立回执身份，不能永远复用第一次等待响应。 |
| SUCCEEDED | 保留任务/usage/结果地址，转 save；只有完整本地产物可交付时才完成。 |
| FAILED/CANCELED | 记录已证实的供应商终态；按照交付与积分规则处理，不能把所有 HTTP 错误等同远端失败。 |
| UNKNOWN/陌生状态 | 不假定失败、不自动退分或重生成；区分 task 过期、不存在与传输未知。 |
| poll 429/明确暂时错误 | 有界退避，保留原 task_id；未授权切换模式或模型。poll unknown 沿既有 30 分钟最多一次自动恢复规则。 |
| 超出本地轮询额度/时限 | 停在原任务待处理，保留 task_id；不是生成失败。 |
| save 下载失败/进程中断 | 重试保存或续查同 task 获取当前仍有效的结果地址；不保证供应商延长 URL 有效期。完整文件已落盘但未登记时只做本地恢复。 |
| URL/task 过期且无本地产物 | 明确交付缺口，人工核对积分与成本，不自动购买第二次生成。 |
| 本地停止/关阀 | 停止后续外发，不声称已取消云端或退款；允许必要本地收尾。首批不接远端取消 API。 |

建议首轮 poll 15 秒，其后按 15/30/60 秒有界退避；总窗口沿用现有视频的 **2 小时**，万相首批另外建议 **最多 40 次 poll**，均冻结在 run。这样可容纳既有 unknown 的 30 分钟等待，但仍以剩余次数及总截止为先；超过截止不自动放行。恢复沿原累计上限计数，不能通过重启或查询子任务重置。首批额度耗尽后停止并人工核对，不提供扩额；现有 `controlOperation` 只有恢复/停止/放弃，不宣称其已有增额能力。

单次网络请求和本地收尾必须留在现有 180 秒队列 expiry、约 195 秒 Worker 退出窗口内；上传两份素材拆分持久步骤，每步有独立超时和取消信号。长生成只通过延迟 poll 等待，不在 handler 中 sleep 数分钟。

会员“继续处理原任务”仍通过 `videos/query` 引用本人原 run，继承原模型/模式、地域/业务空间、素材身份、task_id、交付参数与剩余额度；复用原 charge，恢复报价为 0，新子任务不可与原任务同时执行。admin 也从原任务恢复，不开放任意 task_id 查询入口。

## 7. 预算、用户积分和供应商成本

### 7.1 请求次数与外发

建议分别设 `aliyun.wan.media`、`aliyun.wan.video`、`aliyun.wan.poll`。按实际网络步骤定义计数，默认分钟/小时/天均为 0；缺行同样阻断。素材交付需要复用预算准入与尝试记录，即使某步骤没有模型费，也不能无限重试。OSS 容量/流量费与模型费分开标明。

新增 service 要能出现在现有通用预算设置中。次数限额不是人民币金额上限；真实验收必须另列生成次数、模式、时长和费用范围。新 provider 不借用 Redfox 剩余额度，也不由采集开关控制。

### 7.2 用户积分

沿用现有整数积分公式与一次性确认报价，建议本地计价秒数为 `ceil(durationMs / 1000)`，UI 同时显示真实时长与计价秒数。例如 5.2 秒按 6 个本地计价单位报价。**这是本地产品建议，不是阿里云计费规则，也未据此设置正式价格。**

报价 hash/快照包含 provider、model、mode/tier、两份素材 hash、探测版本与时长、取整规则、参数及价格版本。报价后改素材、模式或价格则重新报价。原始探测事实与归一化输入由服务端保存，不接受客户端伪造秒数。

价格维度为 `kind=videos`、`provider=aliyun`、`model=wan2.2-animate-mix`、`tier=wan-std/wan-pro`。会员价格默认不启用；admin 不扣会员积分，但仍走供应商预算和回执。

完整交付后按用户已确认报价结算；供应商实际秒数不自动改写报价。确认失败且无交付/成功证据才释放；unknown、停止、部分结果、远端成功本地保存失败保留占用并进入 review。交付时长明显异常不得直接按完整交付结算，应保留实际用量并核对。续查沿一个原 charge，不重复扣分。

### 7.3 供应商费用

北京官方当前标准/专业原价分别为 **0.6 / 0.9 元每成功输出秒**；10 秒示意费用为 6 / 9 元。优惠和实际账单可能不同，来源见[价格页](https://help.aliyun.com/zh/model-studio/wan2-2-animate-mix)。这些金额不是会员积分售价。

复用 `receipt_attempts.usage` 保存规范化任务用量，成本读模型按任务去重。**不新增成本 result kind、唯一索引或保留例外，不改积分交付分类。**

1. 原生成 run.input 在提交前冻结模式、当前配置身份和成本单价快照。poll 的非敏感 requestSummary 关联原 run、提交 receipt 和具体 attempt；这些关联由后端从原任务推导，不接收客户端指定。
2. `paidRequest` 先落原始响应，合同校验通过并检查当前执行资格后，在同一业务事务幂等补记该 poll attempt 的 `usage.wanTask`：任务身份、终态、输出秒数、冻结价格与原提交关联。仅补元数据，不修改原始响应、状态、时间或 poll.cost；同一 attempt 重放须得到相同事实。
3. 成本读模型按原任务冻结的供应商配置身份＋task_id 全局去重，再按原提交 attempt.started_at 过滤统计；不能用运行时最新配置或先截取 poll 的时间窗口。页面标明“按本地提交时间归属，结果返回后补入估算”，不冒充供应商账单日期。跨日续查、重复终态响应与保存重试只算同一任务一次。
4. 多份证据一致才计算 `outputSeconds × 冻结单价`；用量缺失或证据冲突显示未知/待核对，不算 0，也不取最后一份掩盖冲突。没有账单证据只标 `estimated`。
5. 现有日常保留任务只清旧 attempt.response，不清 usage，因此沿用即可。成本看板增加一个万相任务聚合分组；既有 HTTP 尝试数、Redfox 账单和会员积分保持各自口径。

该方案只增加万相局部用量补记和成本读取，不把费用混入交付结果。未来真有多家相同需求时，再判断是否抽共享模块。

供应商成功但产物保存失败时，供应商成本仍存在；会员是否完成交付由会员账本单独判断。这两份事实不能用同一个“成功/失败”布尔值替代。

## 10. 当前结论与启用前依赖

现有工具体系适合接入万相，不需要另建任务、积分或素材平台。新增成本集中在：万相专用协议和恢复接线、服务端媒体探测、正式私有 OSS 交付、按输出秒计的任务成本，以及前后台两素材表单。

正式启用前需要北京业务空间和可用模型账号、获授权的私有媒体 OSS 配置、会员积分售价、次数预算及真实验收范围。开发中的常规实现和桩验证按本方案推进；已有授权不重复询问，缺少哪个实际外部条件就只阻断对应阶段。

## 11. 本轮评审结论（2026-10-29）

结论：沿既有任务、回执、积分和私有文件体系做一个完整工具功能，架构可行。原方案存在可收窄的设计，已修订：

| 评审项 | 修订结果 |
| --- | --- |
| 用户入口 | 已按用户决定改为独立第四 Tab“视频复刻”，前台/admin 一致。 |
| 前置范围偏大 | SOP 只补一节清单；必要代码连接随万相流程实现，不先统一全站供应商。 |
| 成本结果类型引发连锁改动 | 改用既有回执 usage＋任务聚合读取，删除新 kind、唯一索引、清理例外及积分排除规则。 |
| 素材交付考虑过宽 | 固定单地域/单业务空间、仅 OSS、仅同 run 重试复用；不做第二上传路径或跨任务云缓存。 |
| 表单容易重复或串协议 | 前后台共用复刻表单，保留各自提交外层；第四 Tab 隐藏 Redfox 专用查询，键盘按实际 Tab 数量工作。 |

保留权限、真实媒体时长、预算缺行拒绝、提交未知不重发、原任务恢复与保存失败不重生成，这些直接保护用户结果和费用，不以“精简”为由删减。当前未发现需要新增通用平台的依据；本轮结论是方案评审，不是代码或供应商验收通过。

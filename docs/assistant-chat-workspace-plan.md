# 助手聊天工作区改版方案

日期：2026-10-30；修订：2026-10-31。状态：既有三栏和真实接口流程已完成相应验收，见[三栏验收](reviews/2026-10-30-assistant-chat-ui-acceptance.md)及[真实联调记录](reviews/2026-10-31-assistant-live-acceptance.md)，未部署。第12节输入区增量已实现并完成本地验收，见[输入区验收](reviews/2026-10-31-assistant-inputs-acceptance.md)，未部署。

本方案承接[统一底座接入方案](xiaohongshu-agent-integration-plan.md)及[首版验收记录](reviews/2026-10-30-assistant-v1-acceptance.md)，第1–11节记录既有三栏改版及执行反馈；第12节是本次增量的范围权威，包含必要的技能绑定、文本材料和费用授权后端适配。沿用 assistant-ui + AI SDK + 业务系统的职责、现有价格、积分账本、预算和执行链；不再将本次增量描述为纯前端改动。

## 1 结论和用户已确认范围

助手成为网站独立一级导航“助手”，综合入口称“创作助手”，专属入口称“小红书助手”。桌面以左侧助手与会话历史、中间聊天、右侧稿件构成工作区；手机以聊天优先。综合入口既有快捷动作，也接受自由描述，由既有模型及技能目录选择任务，意图不清楚时询问。

推荐保留网站导航能力，将其和助手导航整合在同一条左栏，上下分区、可折叠；不要在现有网站侧栏外再增加另一条完整的助手侧栏。这里的“整合且可折叠”是本轮研究后的建议，用户已确认按该三栏方案实施。

用户确认的边界：独立导航入口；聊天为主的三栏；手机适配；改善等待反馈与使用体验；保留现有后端和计费；先写方案、暂不部署。“等待功效”在本方案按等待反馈及交互效率处理。

我们的选择是“独立入口 + 单一左栏 + 可折叠网站导航”，是结合上述模式和当前代码的设计判断，并非照抄某个竞品的完整布局。暂不增加全站悬浮聊天、Agent 构建器、自动化触发器或协同编辑。

## 3 入口和外壳

### 3.1 独立一级入口

- 普通桌面网站侧栏新增“助手”，与“数据工具”并列；不再用“← 数据工具”解释助手的父级。它与当前数据工具一样是固定产品入口，不塞入后台严格校验的 `NavigationId` 内容栏目配置，因此无需改后端导航 schema。现有 `/agent` 是对外 Agent 接入说明，与用户聊天助手分开保留。
- 普通手机页面的主导航新增“助手”一级项。当前默认四项可变为五项；保留已有站点配置控制的内容入口，不因加入助手私自隐藏日报或其他栏目。
- 工作区内部左栏顶部保留品牌和“网站导航”折叠按钮；当前“助手”一级项始终明确。展开后显示现有站点配置允许的入口，包括数据工具；这些入口不复制另一套权限或栏目配置。
- 左栏下部为“新对话”“创作助手”“小红书助手”及会话历史，底部复用账户、积分入口、主题切换。较短窗口中导航区有高度上限，历史列表独立滚动，账户保持可达。
- 网站导航默认折叠以突出当前工作；用户可展开，并记住纯布局偏好。折叠不会隐藏返回网站的途径。工作区左栏整体也可收起，通过顶部菜单恢复。
- 助手开关关闭、未登录或无权限时，独立入口仍落到明确的说明/登录状态；不加载他人历史，不让导航点击触发模型。

### 3.2 路由建议与兼容

| 用途 | 新前端地址 | 兼容方式 |
| --- | --- | --- |
| 综合创作入口 | `/assistant` | 原 `/tools/assistant` GET 跳转到新地址 |
| 小红书入口 | `/assistant/xiaohongshu` | 原对应地址 GET 跳转 |
| 已有会话 | `/assistant/sessions/:sessionId` | 原会话地址保留 sessionId 跳转，不重建会话 |

`/api/assistant`、sessionId、runId、commandKey 和计费业务含义保持不变。统一修改前端链接帮助函数、站内推荐入口及登录返回地址；历史收藏继续可用。已有 pending command 不能因为 URL 改名而重放或清空。旧路由只导航，不代理或重发写请求。跳转保留合法查询参数及现有私有响应 `ACCOUNT_HEADERS`。当前 `safeAccountReturn` 已允许同站助手地址，不新增登录豁免。

链接收口包括 `data.ts` 的 href helpers、会话删除后的跳转、`run-history-data.ts` 和 `tool-run.tsx` 的回会话链接、原 `/tools` 助手卡片以及对应测试。数据工具页可保留辅助推荐链接，但不能继续是助手的主入口。

当前 root 对非管理页统一套 SiteShell。实施时仅为助手路由分支选择 AssistantWorkspaceShell，正常页和 ErrorBoundary 保持一致，避免原 180px 侧栏、max-width 容器及手机底栏仍包在工作区外。优先由共享布局/路由元数据明确边界；如需路径判定，匹配完整路径段，不误中 `/agent` 或 `/assistant-other`。不做全站布局重构。

## 4 桌面及手机的具体体验

下面是结构示意，不是最终颜色或像素稿。复用现有字体、颜色、圆角和深浅主题。

```text
┌─────────────────┬────────────────────────┬────────────────────┐
│ 品牌 / 网站导航 ▾│ 创作助手    当前任务状态 │ 稿件 1 / 版本 v2   │
│ 助手（当前）     │                        │                    │
│ ＋ 新对话        │ 我：把这段改成小红书文案│ 标题               │
│ 创作助手         │ 助手：目标读者是谁？   │ 正文               │
│ 小红书助手       │ 我：刚入职的年轻人     │ 备选标题 / 标签    │
│                 │                        │ 来源               │
│ 会话历史 / 筛选  │ 当前任务卡 / 费用确认  │                    │
│ 会话 A           │                        │ 预览 / 编辑 / 版本 │
│ 会话 B           │ 引用稿件 v2            │ 复制 / 保存 / 转交 │
│ 账户 / 积分      │ [描述需求或回答问题] ↑ │ 用这版继续修改     │
└─────────────────┴────────────────────────┴────────────────────┘
```

| 宽度/场景 | 布局及行为 |
| --- | --- |
| 宽桌面，建议 ≥1280px | 三栏。左栏约 240px，稿件约 380–460px，中间获得剩余空间；聊天宽度不足时先收左栏或稿件，不挤窄正文 |
| 中等窗口，建议 768–1279px | 左栏改抽屉；空间足够时聊天与稿件并排，至少留约 420px 给聊天。放不下两栏则使用“对话 / 稿件”切换 |
| 手机 <768px、横屏低高度或高倍率缩放 | 单栏聊天优先；顶部菜单打开助手与历史，“对话 / 稿件”切换正文区域，稿件在全宽页面编辑 |
| 尚无稿件 | 中间欢迎与聊天占主位，右栏默认关闭；产生稿件后宽屏可首次展开，手机显示“稿件已生成”入口，不强制跳离正在输入的对话 |

断点是初始实现依据，最终以正文可读宽度和实机验收为准。双栏稿件至少约 320px，计入内边距与间隔后不满足聊天最小宽度就切单面板。现有项目 `lg` 为 961px，实施时不能拿它当 1024px 或代替本方案断点；使用助手范围的明确容器规则，并给 grid 子项设置合理收缩边界。不得为了达成三栏让 390px 手机出现横向滚动。

手机工作区不叠加原网站底栏，站点导航保留在顶部菜单抽屉中；输入框位于可视区域底部，处理 `dvh`、键盘和安全区。桌面/手机共用同一会话 controller、runtime、输入状态和轮询，不能隐藏两套同时挂载的聊天树。切页签只切换视图，不创建请求或重置待提交状态。抽屉支持焦点约束、Esc 关闭和回到触发按钮；导航成功后关闭抽屉。

聊天与稿件分别滚动。用户位于消息底部时随新消息滚动，向上阅读时停住并显示“有新消息”；完成、轮询或稿件更新不能抢焦点。切回同一会话恢复本次浏览期间的滚动位置，根级 ScrollRestoration 不误控制内部滚动。

## 5 一次真实创作如何完成（现有逐次确认路径）

### 5.1 从空白开始

1. 点击一级“助手”进入创作助手，看到输入框和“小红书创作”“公众号创作”等快捷动作。公众号目前展示“未开放”，不可伪装成已可执行；其他动作由 `/options` 的可用性及原因驱动。
2. 用户直接输入需求，或先点快捷按钮。快捷按钮只选择本次任务及给出输入提示，不创建付费任务。小红书专属页使用同一组件，仅配置、说明和可用动作不同。
3. 点击“发送”后，如尚无会话，先通过已有幂等命令免费建会话，再取得本次报价。界面立即显示“正在确认本次费用”，不要求用户先点一次“新建”再重复发送；未确认前没有模型执行。
4. 输入区上方出现费用确认卡：本次任务、实际积分、余额是否足够、报价有效状态及“确认并开始”。发送按钮附近预先注明“发送后先确认积分”。尚未确认时，取消可继续改需求；修改输入、快捷动作、引用版本或会话版本后，旧报价不可继续使用。已经确认并发出的提交则冻结其原输入、引用版本、报价及命令身份，不能被下一轮草稿改写。
5. 确认后创建原有 turn；收到服务端接受结果后，用户消息才进入正式历史。传输期间可显示“正在提交”的临时输入预览，但不能伪装成已保存消息。新建会话响应丢失也只按同一命令键恢复，不重复创建。
6. 助手有疑问时在消息区显示问题，底部同一输入框切到“回答这个问题”。回答走既有 answer 接口，不再创建报价/新回合；原回合后续如需另外付费工具，仍独立确认。
7. 稿件保存后右侧可阅读、复制、修改、查看版本，也可把指定已保存版本加入下一轮需求，例如“保留结构，把语气改得更自然”。

### 5.2 消息、任务和稿件如何分工

- 聊天区展示真实用户/助手消息，区分角色，保留上下文；不再把一串管理表单当成聊天主界面。
- 当前任务卡只解释最新/当前回合：状态、待回答问题、工具提案及可执行操作。详细工具结果默认折叠，失败和需用户处理的动作始终可见。
- 报价、工具授权、系统状态属于界面操作卡，不伪装成模型说的话。后端只保存稿件却没有自然语言收尾时，可显示“稿件已保存”的系统提示，不编造已持久化的助手回复。
- 现有 DTO 没有每个历史回合的完整状态与进度，也没有稿件与 turn 的关联。第一版不拼“每条历史消息对应哪个稿件”的时间线，不显示虚构消息时间；稿件面板是会话级。
- 多份稿件按稳定身份展示，各自有版本；默认保留用户选择。首次进入选择稳定首项即可，不称其为“最新生成”。只有当前页面观察到新增 artifact/version 才打“有更新”标记。

### 5.3 输入框与快捷操作

底部只保留一个主输入框。普通创作和回答补充问题使用不同草稿槽，避免进入提问状态时覆盖用户正在写的下一轮需求。执行期间允许记录下一轮草稿，但明确提示需等待当前回合结束；第一版不自动排队，不自动发送。

支持多行输入、中文输入法组合态保护；Enter 发送/进入费用确认，Shift+Enter 换行，中文候选词确认不触发提交。手机使用可见发送按钮。前端长度上限沿服务端合同，不静默截断。现有引用材料用可移除标签呈现；文本上传和三个底部入口按第12节扩展。

assistant-ui 保持现有 ExternalStoreRuntime 适配持久消息；新 UI 不切换成直连模型的默认聊天 transport。报价、回答、批准、停止、恢复继续由已有客户端和服务端执行。

## 6 等待、异常和恢复

| 真实状态 | 用户看到什么 | 可操作与约束 |
| --- | --- | --- |
| 读取会话 | 保持页面结构的短骨架、正在读取 | 超时给读取重试；不创建 turn |
| 获取报价/提交命令 | 明确当前动作及禁用重复点击 | 保留输入；未知提交结果不可生成新 commandKey |
| `executing` | 按实际动作显示“正在调用创作接口”等状态及轻量活动指示 | 不展示假百分比、虚构细步骤或模型思维内容；停止仅按现有允许状态开放 |
| `waiting_question` | 真实问题和“需要你补充” | 主输入框切回答模式；一键定位待答问题 |
| `waiting_approval` | 检索对象、范围、价格和单独确认按钮 | 普通“好的”不算付费批准；按 proposalRevision、报价有效期及余额校验 |
| `waiting_child` | “正在获取参考资料”及真实工具状态 | 可看已返回资料；不把反复刷新变成重新检索 |
| `completed` | 有保存证据时显示“稿件已保存”，给出查看入口 | 可写下一轮；不强制切走正在编辑的稿件 |
| `stopped` | 已停止以及已有产物 | 服务端 canResume 为真才给继续；不承诺取消已发出的外部请求或自动退款 |
| `needs_review` | “本次结果需要核对”的通用提示、已有工具状态及联系管理员路径 | DTO 没有具体审核原因或用户核对接口；仅提供刷新及当前允许的停止，不用普通“重试生成”绕过未知外呼 |
| 轮询失联/离线 | “状态更新暂时中断，上次已知状态为…” | 保留已读内容；恢复连接先读取，不假定任务成功、失败或仍在执行 |
| 会话过期/无权限/版本冲突 | 明确原因，保留可恢复的本地输入 | 登录恢复或重新读取；不自动提交原付费动作 |

现有后端没有 token 流和可信 ETA。首版呈现完整消息加真实状态刷新，保留可见页面约 2.5 秒轮询；对已有消息不做逐字动画。约 15 秒尚未完成时给简短等待说明；更长等待提供“刷新状态”和可用的停止入口，不能把经过多少秒等同服务端执行超时。恢复页面后如需计时，只写“本次查看已等待”，不能伪造任务总耗时。

后台标签页暂停读取，回到前台先同步；切会话取消旧读请求，检查 sessionId 与 eventSeq，防止迟到响应覆盖新会话。新事件序号仅用作刷新依据，不当作完整步骤日志。

待提交命令键和冻结的 pending 输入目前只在页面内存中保存。同一 SPA 生命周期内切会话再回来可恢复原提交；整页刷新、重新登录或新标签页后先读取服务端状态，不能承诺找回原命令键或自动重发。若原提交状态仍无法确认，提示核对，不能通过新建命令猜测恢复。原提交稍后返回时，只清理属于该命令的输入快照，不清空用户后来写的草稿。

用户切换页面不会自动停止服务端任务。离开前提示未保存编辑和未发送草稿的真实保存范围：当前草稿只在本次页面会话内保留，整页刷新后不保证恢复。本轮不把敏感稿件额外写入 localStorage，也不声称草稿已自动保存到服务器。

## 7 右侧稿件面板

面板承载标题、正文、备选标题、标签、来源，以及预览、编辑、版本选择、复制和转交。保留现有结构化字段及安全来源链接，不加自由 HTML 执行、在线发布或未经验证的富文本协作。

- 编辑走原 `baseVersion` 并发校验；只有保存成功才显示“已保存”。活动回合或待核对状态下沿后端限制禁用保存，并说明原因。
- 有未保存内容时，切稿件/版本、转交、新对话或站点跳转必须先处理本地修改；允许取消离开、保存（当前可保存时）或明确放弃。单纯收栏、手机切视图不丢编辑。
- 轮询发现新版本时，提示“有新版本可查看”，不覆盖当前编辑区；遇到版本冲突保留本地内容，重新读取后由用户决定。
- “用这版继续修改”引用已保存的 artifactId/version，并以标签加入下一轮输入。未保存修改需先保存或明确继续引用旧版本。
- `artifactVersions` 已接通；报价/待提交对象绑定引用。2026-10-31修复后，显式选定某作品旧版会替换该作品默认最新版，并冻结该版本的真实来源；其他作品及历史仍可能作为上下文，不承诺模型只看这一份稿件。第12节进一步明确显式移除材料的语义。
- 转交其他助手继续复用已有 handoff，显式选择稿件与版本；不能悄悄把当前会话的 assistantId 改掉。点击另一助手只进入其入口，不自动迁移当前会话或资料。

### 12.2 用户主路径与作用域

| 路径 | 操作及预期 |
| --- | --- |
| 默认创作 | 输入需求 → 发送 → 真实费用确认 → 技能选择/必要澄清 → 执行 → 保存稿件；不先强制选技能或材料 |
| 手动技能 | 选技能 → 输入需求/可选材料 → 发送；后端约束该任务的技能，冲突时澄清，不静默换技能 |
| 带文件 | 选择文件 → 上传/提取 → 显示可用与可查看文本 → 输入需求 → 报价/提交；文件未可用不取创作报价 |
| 修改稿件 | 从右栏“用这版继续修改”或“＋”引用指定版本 → 描述修改 → 新任务；保留真实来源和版本关系 |
| 额度内自动 | 先显式设置授权 → 用户发送需求 → 服务端检查真实报价与剩余额度 → 自动确认并执行，展示费用；不主动创建下一任务 |
| 回答问题 | 回答模式只补文本，走原answer命令，不建报价、不重收创作费；材料/技能选择不能修改当前冻结任务 |

技能选择在本会话记住，下次输入可继续使用或切回自动；新会话默认自动选择。它是下一次任务的偏好，不是会话身份，切换不能把creative变成xiaohongshu或改变既有回合。执行期间可保留下一轮文字草稿，不新增自动排队；回答模式隐藏/禁用材料和技能变更，下一轮草稿独立保留。需要新增文件或换任务时明确结束当前处理，再发起新任务。

待发送内容、技能、材料及版本改变后，作废旧报价并重新读取；不得在自动模式下把修改后的新输入悄悄当成刚才已发送的请求。已发出的命令冻结输入、选择、报价、授权依据及幂等身份，响应丢失只核对/恢复原命令。

### 12.3 技能选择：单一目录与明确约束

- 自动模式沿现有模型步骤，根据用户要求、对话和引用作品，在当前profile允许的候选中选择；不新增独立的付费意图分类请求，不用关键词表替代语义判断，也不声称已有准确率指标。
- 手动选择通过稳定actionId映射到允许的skill/module，服务端先缩小候选集合，再允许load_skill。仅传taskHint、靠提示词劝模型遵守不算实现。客户端不能指定任意版本、工具或供应商。
- 下拉项：自动选择、通用写作、小红书创作、小红书改写；小红书专属入口只显示相关可执行项。公众号未开放不进入执行候选、不能发送报价。
- 手动选择与文字冲突时在原任务内询问；若用户要切换已冻结范围，转为新的明确选择及报价，不借回答问题扩大权限。自动模式继续改稿优先考虑被引用作品的类型；不同平台的需求确实不明才询问。
- 用户看到所用技能的产品名称及真实动作，不显示M1/M2或供应商作为按钮名称。加载与读取规则不另外收费；实际模型请求仍计入原任务预算。
- 现有profile/action目录增加少量已实现输入能力与可用性信息，复用于下拉、上传accept和服务端校验；不建立动态插件注册平台，不由文件扩展名决定要使用的技能。

### 12.4 文本材料：复用私有素材，补齐输入闭环

复用现有 `/api/tools/assets` 的认证、上传传输、文件存储、归属、配额、幂等和下载/删除能力。当前该入口主要接受媒体，TXT解析只用于操作输出，因此必须扩展既有受限输入类型，不能复制一套assistant上传Handler、存储目录或配额系统。复用文本提取与校验函数；MD按纯文本材料处理，不执行其中脚本或新建文档渲染器。

首版限制：UTF-8非空TXT/MD，支持一次多选，也可分多次添加；当前待发送的文件附件累计最多10个，沿用输入引用合同的10项上限。附件非必填，直接输入需求即可创作；10个是本次提交的文件附件上限，不是账号素材总数或整个会话的历史上传上限。单个文件字节限制不高于现有文本附件2 MiB。消息字符、会话快照以及模型上下文限制另行校验，文件小于2 MiB不意味着模型一定容纳。为避免现有JS分词器在超长连续文本上阻塞，分词片段另限制为8 KiB；超限提示分段或缩小范围，不修改原文。通过单文件有界提取后标为“可用”，合并材料的上下文在报价前再校验；超限保留文件与需求并要求缩小范围，不静默截断、不自动摘要、不调用付费模型读取。

输入区显示“已添加N/10”；仍在列表中的上传中、处理中、可用及失败文件均占一个名额，原卡重试不增加数量，移除后释放名额。选择后先检查已有附件与本批文件的合计；超过10个时，本批暂不加入、不发起上传，保留原列表和需求，并提示“最多添加10个附件，还可添加N个”，由用户重新选择或移除原附件，不静默截取前几个。多选复用既有逐文件上传接口和独立状态，无需新增批量上传接口；提交时后端再次校验引用数量。

附件位于输入框同一圆角容器顶部，以独立轻量卡片横向排列并换行，手机也不退回整行列表。卡片显示文件名、图标及上传/处理中/可用/失败状态，右上角“×”移除；点击卡片查看纯文本，失败可独立重试。卡片区域限高滚动，短屏中输入与发送保持可见。任一仍被选中的附件未就绪时阻止该次报价/发送；用户可移除问题附件后发送其余材料，不得静默跳过。材料用途默认参考，可在需求中说明，无需逐个填写必填分类。

输入的持久语义：

1. 上传文件先进入现有用户私有素材，完成提取后用现有会话输入机制保存文本及文件身份/内容哈希/来源；只有提交成功的回合按其明确选择冻结内容。新会话可在本地先上传，发送时复用既有幂等建会话/关联流程，失败不得重复关联。
2. 当前 `inputIds=[]` 会回退读取全部会话输入，不能直接用于新的“移除全部附件”。新输入合同明确区分旧客户端未指定选择与新客户端显式空集合；新界面移除后不能又自动带回输入或稿件。既有历史消息不因此擦除，界面不承诺已出现的材料从模型历史彻底消失。
3. 报价绑定最终文本快照、文件身份/内容哈希、稿件引用版本和技能选择。已有文件、跨助手转交、历史稿件都必须核对所有权；显式引用旧版不混入同作品新版。
4. 移除附件只取消本次引用，不等于删除私有文件；文件仍计入原素材配额。取消报价、切换或删除会话不顺手删除共享素材。现有素材删除保护需识别助手引用；来源文件不可读或被删时，禁止新引用，已经持久化的授权文本快照仍按会话保留规则读取，不反向恢复原文件访问权。
5. 未发送附件列表与原文字草稿一样仅保证当前SPA生命周期内按账号/会话保留；刷新后不承诺自动还原未发送列表，也不能重复上传。服务器已保存材料按权限读取，用户仍可从现有素材管理查看文件。跨账号清理前端引用，不能泄露另一个账户的文件名或文本。

上传和本地文本提取不占创作积分；后续OCR/转写如接入付费服务，必须有独立报价、授权、回执和可用结果，不能因文件已上传就视为获准外发。

### 12.5 费用模式：保留现有计费，只扩展授权来源

费用控件先以简短菜单展示“每次确认 / 额度内自动”；选择每次确认直接维持或关闭自动模式，不弹出额度表单。默认“每次确认”，确认卡主区只显示本次积分、必要余额/有效状态及“取消 / 开始”，需求与详细规则折叠。等待确认时优先展示报价，暂收起编辑表单；取消后恢复原需求与附件。200积分创作/修改、20积分检索是当前隔离联调价，正式运行仍读取现有后台已生效价目，不能硬编码或通过本方案修改真实价格。选择“额度内自动”才打开短弹层：主区仅保留额度输入、可选检索、当前价格/已用额度及“取消 / 开启”两个按钮；“仅本会话，超额再询问”作为简短说明，完整规则折叠，重新读取按钮仅在异常恢复时显示。授权语义仍须满足：

- 明示仅当前会话生效，可随时关闭；新会话/跨助手转交不继承授权。
- 用户设置正整数的自动确认总额度，默认不替用户批准金额。示例1000积分不是生产默认或新的支出授权。
- 展示可自动确认的创作范围及当前价格；可选允许“每次创作最多自动确认1次小红书查询”，默认未勾选，并显示查询价格。额外查询需逐次人工确认，仍受既有任务次数、权限及预算限制。
- 展示由范围和已确认价目得出的单次创作自动确认合计上限：按当前测试价仅创作200，含一次查询最高220。不是另一个必须填写的高级配置，也不是改变原任务内部模型次数限制；额外人工批准的查询另列费用。
- 确认后显示自动模式及剩余额度；发送前可看当前创作价，后续查询及结算明细持续可查。不会把上传/选择技能当成发送动作。

这里的总额度是“自动确认额度”，不是钱包余额或整个会话包含后续人工授权的绝对支出上限。达到额度时暂停新增自动确认，用户可关闭、明确重新设置授权，或对该动作单独人工确认；人工额外支出必须显示为额外授权，不悄悄提高/恢复自动额度。原有手动费用确认仍作为完整可用路径保留。

后端最低合同：

1. 在assistant领域保存绑定owner/session的版本化授权记录（范围、金额上限、已确认价目、启用/撤销事实），每个自动确认动作关联该授权版本和原quote/run/charge。不是新钱包；已用/预约金额来自现有账本和关联，不另存可漂移的计费状态机。
2. 自动确认仍生成与实际输入绑定的有效报价，检查权限、价格版本、会员资格、总预算/会员池及钱包余额。随后在既有创建任务/预占/入队事务内，原子校验自动额度并记录授权依据；父任务和查询child均纳入。禁止前端模拟点击确认，禁止模型提供授权ID或自行授予费用权限。
3. 自动额度按本会话所有自动授权版本累计：剩余额度＝当前确认总上限－历版自动确认已结算费用－尚未释放的自动预约；失败/未知且未核账的占用仍计入。人工额外授权不计入自动额度。预约释放后额度可恢复；同一命令重放只关联一次，不再次占额度。按会话授权和现有会员/钱包锁序处理并发，两个标签页不能各自使用同一余额。自动检索计数绑定原turn，停止/恢复/重新启用不能清零。
4. 自动总额度、父子合计单任务自动上限或每轮自动检索次数耗尽时，停止自动确认并展示逐次人工确认入口及额外费用；报价未批准不产生新的付费调用。人工确认不能绕过任务本身的硬次数限制、权限、余额或预算；已达这些限制时须明确说明原因，不展示无法执行的确认按钮。新工具、价格版本变化、授权范围变化或结果未知不能自动越过，保留原任务和恢复入口；未知结果先核账，不能另买一次。
5. 设置费用模式只影响之后新发起的任务，不追认已经发出的提交或原有待确认提案。已接受任务的授权范围冻结；关闭/撤销自动时，尚未获得批准的后续付费动作回到手动确认，已批准/已发出的请求沿原事实执行和核账。关闭不是停止或退款；停止仍用既有任务控制。即使关闭页面，已接受任务也可在原授权边界内继续。
6. 重新开启或提高额度必须显式确认，不通过切换按钮重置同一会话的累计费用历史。授权版本变化保留关联；新限额按第3条公式包含历版已结算费用和未释放预约。例如已自动花费800积分、无未释放预约，重新设置总上限1000积分后只剩200积分。用户只是改变界面选择，不能改写旧quote、charge或run。
7. 意图识别/技能加载/补充回答沿原创作任务，不重复收创作费。实际供应商调用仍经receipt和预算，未知结果不得自动重买。结算继续按交付证据，不新增“一条聊天消息必扣一次”或“所有对话免费”的承诺。

该能力需实施后端授权及必要的增量迁移，属于本次最主要的业务变更；不能只隐藏确认卡就视为完成。此方案更新不授权部署、改正式会员价格或新增真实付费测试。

### 12.7 实施顺序与验收

实施顺序：①技能下拉和服务端严格绑定；②TXT/MD上传、材料/稿件选择及快照；③会话自动授权与既有账本接线；④桌面/手机端到端验收。各步复用同一控制器和命令链，未接通的入口保持不可执行；不以仅有按钮替代闭环。

| 验收项 | 最小证据 |
| --- | --- |
| 默认路径与发现性 | 不配置即可完成手动确认创作；欢迎快捷按钮与会话下拉选择一致；切助手不串会话/授权 |
| 技能选择 | 手动范围无法加载其他模块；冲突问答不换技能、不重报价；自动代表性需求可路由；未开放项不收费 |
| 材料与报价 | 无附件可发送；一次多选及多次追加累计10个可用，第11个或整批超限在上传前拦截且保留原列表；占位/移除/重试计数及后端数量校验一致；TXT/MD有效、空文件/非UTF-8/伪类型/大小和上下文超限、逐文件失败重试；未就绪不发起；更换材料旧报价无效；移除最后一项不回退全选 |
| 来源与生命周期 | 跨用户拒绝；旧稿版本/真实来源保留；取消/移除不误删素材；删除保护及刷新恢复范围与提示一致 |
| 自动授权 | 未开启保持手动；范围内不重复弹窗；价格变化/超额转待确认，余额/权限/硬次数限制说明阻断原因；额外查询须人工批准且不提高自动额度；停止/撤销/恢复不绕范围；待确认旧请求不被追认 |
| 并发与账本 | 双标签页争用、重复提交、响应丢失、父子事务中断、预约释放、未知结果、额度调整及重新开启均不重复占额/扣费；历版累计，已自动花800再设总额1000只剩200；原手动工具路径回归 |
| 体验 | 390px及宽桌面，至少一个短窗口/键盘展开场景；文件多选与追加、N/10提示、10张附件卡和长文件名不横向溢出；三个控件、附件失败、费用弹层、焦点/Enter不误发送；保留对话目录与稿件切换 |
| 执行反馈 | 上传/提取/等待授权/实际执行/保存分别显示真实状态；无假进度，无供应商内部信息，无额外付费轮询 |

先在独立测试库和本地桩完成预算/权限/并发回归，再按另行授权选择必要真实联调；先前28次模型与1次检索计数不得重置或冒充本次新功能证据。当前用户已授权实施和本地测试；不提交、推送或部署，不新增真实付费调用。

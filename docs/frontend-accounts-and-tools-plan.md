# 前台账号、后台用户管理与数据工具方案

日期：2026-10-28
状态：账号、工具与首版试用积分方案均已确认，代码及本地验收已完成，尚未生产发布。

## 1. 目标与已确认范围

建立一条完整路径：**管理员在后台创建用户 → 用户在前台登录 → 使用数据工具 → 查看自己的任务和结果 → 管理自己的账号。**

已确认的产品决定：

- 暂不开放自助注册，账号由管理员创建。
- 第一版身份功能包括当前账号展示、个人资料、修改密码、退出登录。
- 第一版开放全部现有查询、AI 搜索、图片/视频创作、辅助工具与私有素材；管理功能除外。
- 收藏与已读同步、会员等级、不同工具权限属于后续扩展；本期保留升级边界，不提前实现这些功能。
- 首版采用管理员发放的试用积分，包含报价、预占、结算、流水与异常核对；没有自动初始额度或默认工具价格。
- 账号、工具与积分代码已完成接通；验收证据和待完成项目见第 9 节。

本期不包含邮箱/手机验证码、社交登录、找回密码邮件、邀请注册、支付充值、会员购买和组织/多租户。忘记密码由管理员重置。

当前决策状态：

| 决策 | 已确认方式 | 影响 |
| --- | --- | --- |
| 第一版工具范围 | 已确认：全部现有工具，管理操作除外 | 包括查询、创作、辅助工具、素材及对应结果闭环 |
| 用户使用额度 | 管理员发放试用积分，包含积分账户、任务预占、结算和明细；暂不充值 | 后续可复用账务基础接入新的积分入账来源 |
| 积分定价与初始额度 | 新用户零积分，无种子价目；管理员根据实际成本显式定价和发放 | 无匹配价格时不能提交；明确配置零积分可提供免费工具，不规定积分与货币兑换率 |

上述确认包含试用积分实现，不包含生产迁移、真实付费验收或发布授权。

## 2. 当前代码事实

### 2.1 账号与页面

- 管理员账号与会话仍位于 `admin_users`、`admin_sessions`，`/api/auth/*` 用于后台登录；新增普通用户使用 `site_users`、`site_sessions` 与独立的 `aihot_user` Cookie。
- 管理接口依赖 `adminHandler`，普通用户接口依赖 `userHandler`；两类身份不能互相代替。
- 前台为 React Router SSR，经 HTTP 访问 API；不直接访问数据库。
- 公共根 loader 只加载公共站点元数据。公开页面采用共享缓存，不能直接往该 loader 填入当前用户资料。
- Web 服务端将 `/admin`、`/account`、`/login`、`/register`、`/tools` 及其子路径归为私密路径，同时保护 HTML 与 `.data` 响应。

### 2.2 数据工具

管理员入口保留 `/admin/data-tools`；新增前台 `/tools`，提供 X 查询、平台查询、AI 搜索、图片创作、视频创作、辅助工具与本人私有素材。供应商余额和全站账单仍仅在后台。

管理员命令通过 `/api/admin/redfox/*` 提交，普通用户命令通过 `/api/tools/*` 提交；二者复用领域命令写入 `operation_runs` 并入队。Worker 调用供应商，沿用 `paidRequest`、预算、回执与结果持久化；用户任务同时接入积分授权。

当前边界：

- `operation_runs.actor` 已持久化，且 `(actor, command_key)` 唯一，可同时承担任务归属与幂等作用域。
- 前台任务、结果与素材使用独立的所有权过滤和 DTO，不直接开放后台读取接口。
- `stored_files.owner_actor` 记录新素材归属；生成素材还通过其任务结果确认归属，历史无归属素材不向普通用户开放。
- 供应商总余额和全站账单查询已在前台目录与服务端执行许可两处排除。

调查入口：`apps/api/src/routes/admin-auth.ts`、`admin-redfox.ts`、`admin-assets.ts`，`packages/backend/src/providers/operations/`、`operations/assets.ts`，以及 `apps/web/app/routes/admin/redfox.tsx`。

## 3. 用户路径与界面

变更前：管理员登录后台后使用工具；普通读者没有账号和工具入口。

当前路径：普通读者从前台导航进入数据工具，未登录时跳转登录，登录后回到原页面；工具任务与账号管理均在前台完成。

现有公开资讯阅读、管理员登录、采集订阅、公开内容发布方式保持现状。

### 3.1 前台入口

| 页面 | 行为 |
| --- | --- |
| `/login` | 用户名与密码登录；失败保留用户名，提供明确提示；登录成功回到安全的本站目标页 |
| `/register` | 仅说明“暂未开放注册，请联系管理员开通”；不提供可提交的注册表单 |
| `/account` | 显示用户名、昵称、普通用户身份与积分余额/流水；修改昵称与密码；退出登录 |
| `/tools` | 工具目录、输入表单、我的执行记录与私有素材入口 |
| `/tools/runs/:id` | 单个任务进度、结果、文件和适用的恢复操作 |

桌面侧栏提供“数据工具”和账号入口，移动端从“更多”进入。登录页直接说明账号开通方式，不以“注册”按钮诱导用户进入不可完成流程。

公共页面的身份菜单在浏览器挂载后独立请求当前身份，响应禁止缓存；公开 HTML 不携带用户名、CSRF 或会话信息。登录、退出和路由变化后更新菜单，避免显示上一个账号。

私密页面在窗口重新获得焦点、恢复可见或收到身份更新通知时检查会话；用户 ID 或 CSRF 改变、或会话失效时重新加载，丢弃旧账号的本地页面状态。网络失败不触发无限刷新。

### 3.2 后台用户管理

新增 `/admin/users` 和后台导航“用户管理”。

- 列表显示用户名、昵称、启用状态、创建时间、最近登录时间，支持搜索与分页。
- 创建用户：输入用户名、昵称和初始密码；账号立即可在前台登录。
- 编辑昵称、停用/启用、重置密码。首版不提供删除账号，保留任务归属与审计。
- 停用立即使所有现有会话失效；重新启用后必须重新登录。
- 重置密码后撤销原会话，管理员自行通过已有沟通渠道交付新密码；系统不自动发送邮件或消息。
- 创建与重置成功后清空密码输入，不允许查询或回显已存密码。
- 普通用户不能进入此管理页面或创建账号，也不能通过请求字段把自己改成管理员。
- 选中用户后可查看可用/占用积分与流水，人工发放积分或带理由纠错；新用户积分为零，创建账号后由管理员显式发放。

现有管理员保留对全站执行记录的排障能力，包括普通用户任务；普通用户只见自己的记录。该访问范围须在实际上线时与站点隐私说明一致，法律文案仍由站点负责人确认。

### 3.3 工具使用

工具目录复用当前描述符、参数约束与供应商选项；适合动态渲染的查询使用现有描述符，图片/视频等复杂输入采用专门表单。前台采用当前站点样式，不把整套后台页面嵌进去。

提交前展示输入说明、本次积分报价、当前可用积分和占用规则。提交后立即跳到执行记录，显示排队、处理中、等待、完成、失败或需要管理员处理；积分状态与任务状态分别显示。

- 查询结果：展示条目标题、正文摘要、关键指标与来源，长正文和详细字段可展开，查询统计单独显示。
- AI 搜索：答案优先，支持安全的段落、列表、标题和代码排版与复制，引用来源独立展示。
- 图片：网格预览，复用站点 Lightbox 放大与切换，显示尺寸和下载原图入口；过期或加载失败有明确提示。
- 视频：直接播放与下载，末帧独立展示和下载；浏览器无法播放时提供下载提示。
- 转写、字幕、评论：展示适合阅读的结果，长列表分页。
- 素材：上传、选择、预览与下载自己的素材；参考素材支持用于图片和视频创作。
- 页面自动刷新只读取已有状态，不因打开页面、刷新或查看结果创建付费任务。
- 异步任务恢复优先从本人执行记录进入，不让用户任填别人的供应商任务编号。
- 失败保留输入；重复提交与网络超时重试沿用同一幂等键，避免重复创建任务。
- 本地停止只影响后续本地调度，不能宣称撤销供应商已接受的请求或退还费用。

任务详情首先显示成果，提交、轮询和参考素材等执行过程默认折叠；成果与过程分别计数和分页，每页 50 条，不会因过程记录较多而遮住最终答案。完整 JSON 导出以下载开始时的数据库快照为准，流式输出全部已保存成果，不受页面加载条数限制；后来保存的成果需再次导出。

原任务与续查任务提供双向入口，关联须匹配本人身份、原积分占用与工具类型。执行记录显示具体工具名称及输入摘要，支持关键词、类型、状态筛选，先过滤再分页；筛选条件保存在 URL，进入详情、续查及返回列表时保留。列表处于首页且有活跃任务时更新状态，加载更早记录后保留当前浏览位置，通过手动刷新回到最新记录。

### 4.1 第一版权限

| 能力 | 未登录读者 | 登录普通用户 | 管理员后台 |
| --- | --- | --- | --- |
| 阅读公开内容 | 可以 | 可以 | 与读者相同的公开投影 |
| 自助注册 | 关闭 | 关闭 | 后台创建用户 |

| 提交已开放工具 | 不可 | 可以，受积分规则与全站预算约束 | 现有能力 |

后台管理员身份与前台普通用户身份分离。管理员如需体验前台工具，应创建一个普通用户账号；不自动把管理员 Cookie 当作普通用户登录凭证。

### 4.2 后续扩展边界

- **稳定用户 ID**：昵称和密码变化不改变任务、素材或未来收藏的归属。
- **集中授权入口**：认证提供“是谁”，工具授权检查“能否使用、能否访问此对象”；后续等级与工具许可接入同一入口。
- **会员与管理员分离**：后续会员等级不通过授予管理员角色实现。
- **收藏/已读同步**：未来独立增加以 `user_id` 关联的数据表和同步接口，再决定浏览器旧数据的导入策略；本次不改变本地收藏和已读行为。
- **积分与支付分离**：首版实现整数积分、发放、预占、结算和明细；后续充值订单或会员赠送可作为新的积分入账来源，不改变工具结算主链路。本期未实现支付、充值或会员订单。

保留这些明确边界即可，不提前建设通用 RBAC、组织租户、权限配置平台或同步引擎。

## 5. 技术边界与数据设计

### 5.1 账号

新增 `site_users`：稳定 ID、唯一用户名、昵称、密码哈希、基础身份、启用状态、创建/更新时间及最近登录时间。

新增 `site_sessions`：会话令牌哈希、用户 ID、CSRF 值、创建及过期时间。

当前规则：用户名规范化为小写，3–32 位字母数字及 `._-`，以字母或数字开头；昵称 1–80 字；密码 12–128 字符。密码采用随机盐的异步 scrypt，不以明文或可逆加密存储。

普通会话使用独立 Cookie，HttpOnly、SameSite=Lax，HTTPS 环境启用 Secure，固定七天过期。登录与敏感改密限速；每次鉴权核对账号仍启用，不仅相信浏览器 Cookie。

停用、密码重置、用户改密与登录建立会话通过用户行锁协调，防止旧密码校验完成后越过停用或改密创建新会话。改密后要求所有设备重新登录。

登录保护要按实际部署核对：单实例可以使用有界内存限速；如果生产为多实例，需共享限速或复用统一网关策略，不能宣称实例内限速是全站限速。

### 5.2 任务与素材

普通用户任务统一使用服务端生成的 `user:<id>` actor，禁止客户端指定归属。

- 任务列表、详情、分页、结果导出、停止/恢复/放弃都在查询与命令边界校验所有者。
- 素材增加可空 `owner_actor`，新上传写入本人 actor；历史素材不自动分配给任何普通用户。
- 系统生成文件通过 `operation_results → operation_runs` 确认本人归属，不能因 Worker actor 为 system 就对所有用户开放。
- 除列表隐藏外，文件直接下载、Range 请求、参考素材输入和供应商上传结果引用也执行相同权限检查。
- `taskId`、`sourceResultId`、`fileKeys`、`uploadResultId` 等引用均验证所有者。查询既有异步任务还要匹配原提交的模型、平台或搜索 family。

前台独立定义结果 DTO，只包含业务展示需要的标题、正文、来源、状态和文件；不直接返回后台 detail 对象、供应商原始响应、回执、队列内部信息或管理动作。第三方文本按不可信内容处理，链接限制为有效 HTTP(S)。

| `packages/contracts/` | 账号与前台工具 DTO、必要的能力标识 |

### 5.4 当前接口

| 接口组 | 主要接口 |
| --- | --- |
| 账号 | `GET /api/account/me`，`POST /api/account/login`、`logout`、`password`，`PATCH /api/account/profile` |
| 注册关闭 | `POST /api/account/register` 明确拒绝，不创建账号 |
| 用户管理 | `GET/POST /api/admin/users`，`PATCH /api/admin/users/:id`，`POST /api/admin/users/:id/password`；列表支持 `q`、`cursor`、`limit`，返回 `users` 与 `nextCursor` |
| 工具 | `GET /api/tools/options`，`POST /api/tools/quote`，以及 `/api/tools/{kind}` 提交命令；提交携带 `input`、`quoteId` 和 `Idempotency-Key` |
| 本人任务 | `GET /api/tools/runs`、`/runs/:id`、`/runs/:id/results/export`；合法状态下 `POST /runs/:id/{resume,stop,abandon}`；分页使用 `after` |
| 本人素材 | `GET/POST /api/tools/assets`，`GET /assets/:key`、`GET /assets/:key/content`、`DELETE /assets/:key`；文件键按 URL 编码，下载支持 Range |
| 本人积分 | `GET /api/account/credits?before=...&limit=20`，返回余额、流水与下一页游标 |
| 管理积分 | `GET/POST /api/admin/users/:id/credits`；发放/调整使用 `amount`、`kind`、`reason` 与 `Idempotency-Key` |
| 积分价目 | `GET/PUT /api/admin/tool-prices`；更新携带完整规则与 `expectedVersion`，后台页面为 `/admin/tool-prices` |
| 异常核对 | `GET /api/admin/credit-charges`，`POST /api/admin/credit-charges/:id/reconcile`；核对提交 `consume`、`reason` 与 `Idempotency-Key` |

正常工具 `kind` 包括 `query`、`x-account`、`x-tweet`、`images`、`videos`、`ai-search`、`transcriptions`、`xhs-comments`、`media-upload`。支持续查的生成/异步工具使用对应 `/query` 命令，输入只接受本人的原始 `runId`，复用原计费任务。没有充值或会员接口。

普通用户接口不复用管理员 Cookie。写操作校验 CSRF/Origin，登录入口防登录 CSRF；鉴权及输入错误使用明确的 401/403/400/409，临时不可用返回可恢复提示。

所有账号、私密工具、结果、下载和对应 `.data` 响应禁止共享缓存。公开资源维持原有缓存与发布投影，不因已登录而增加未公开正文。

### 5.5 当前关键上限

| 项目 | 当前实现 |
| --- | --- |
| 普通用户会话 | 固定 7 天；停用、重置密码与用户改密撤销所有会话 |
| 登录/改密尝试 | 15 分钟窗口内，每账号对应操作 10 次、每客户端合计 30 次、每 API 实例合计 200 次；实例内限速不等于多实例全站限速 |
| 用户工具提交 | 同时最多 5 个 active/waiting 任务，每分钟最多新建 10 个任务 |
| 报价 | 有效期 10 分钟；每用户每分钟最多 30 次，最多保留 100 条未消费报价 |
| 私有素材 | 每用户最多 200 个未删除文件、合计 1 GiB，上传与生成文件均计入；单文件格式和大小继续遵循工具选项 |
| 小红书评论 | 每任务明确请求 1–1000 条，不接受“全部” |
| 积分数值 | 使用整数；单次报价及价格系数最高 10 亿积分，可用/占用余额各最高 1 万亿积分；这些是技术边界，不是默认额度或兑换率 |

## 6. 首版试用积分与成本保护

复用现有“用户显式提交 → 任务持久化与事务入队 → Worker → 预算/回执 → 结果”的路径，不在页面 loader 或 API 读取中调用付费供应商。

全站服务预算与 `MODEL_CALLS_ENABLED` 等既有开关继续有效。本次开发和验收使用本地供应商桩，不自动启用真实调用或修改生产预算。

### 6.1 已确认的积分范围

首版接入完整但小范围的积分闭环。管理员开通账号并发放试用积分，用户消耗积分使用工具；没有实现充值、转赠、签到、兑换码、自动周期赠送、有效期或会员套餐。

查询、图片与视频的成本差异较大，统一“每天调用若干次”不能表达这些差异。积分按工具及参数定价，预占、结算和不可变流水独立持久化，为后续新增积分入账来源保留边界。

### 6.2 用户和管理员看到的功能

- 账号页：可用积分、任务占用积分，以及发放、消耗、退回等明细。
- 工具表单：输入参数后显示本次所需积分；不足时保留输入，提示联系管理员补充。
- 执行记录：显示该任务占用多少积分，是否已结算或待核对。
- 用户管理：管理员人工发放积分、填写理由、查看流水；重试同一次发放不能重复入账。
- 异常处理：管理员在任务证据下决定结算或释放，纠错用新增调整记录，不修改历史流水。

积分不会每天自动清零，发放后余额持续保留。提交频率、同时执行任务数以及本地上传容量单独限制，积分充足也不能绕过这些资源保护。

### 6.3 按业务任务报价

用户支付的是一次可理解的工具任务。该任务内部的供应商提交、轮询、受控重试和必要的素材处理纳入报价，不逐个 HTTP 请求向用户重复扣分。

| 工具类型 | 首版报价维度 | 完成依据 |
| --- | --- | --- |
| 平台/X 查询、常规辅助工具 | 工具类型、供应商及明确的单次查询范围 | 有效响应已保存；有效的空结果也属于完成，不承诺一定查到内容 |
| AI 搜索 | 所选模型/引擎，限定输入范围 | 答案与对应结果保存可读 |
| 图片创作 | 模型、分辨率、请求张数与参考图处理 | 报价约定的可用产物已交付 |
| 视频创作 | 模型、时长、分辨率、参考素材及音频等参数 | 约定视频及必要产物已交付 |
| 转写、字幕、评论和批量任务 | 供应商实际支持的时长/条数/批次或有界任务档位 | 约定结果已保存；部分交付按明确规则核对 |
| 本地素材上传、查看已有结果、下载、页面状态刷新 | 首版不扣积分，受文件大小、容量与频率限制 | 不触发新的付费处理 |
| 显式向供应商上传素材 | 单独报价；如已属于生成任务的必要步骤则纳入该任务报价 | 供应商上传结果保存并可复用 |

每种已开放工具必须有明确价格或明确免费规则。价格使用整数积分，按版本配置；服务端根据工具和规范化参数计算，不能接受客户端传入的扣分金额。

现有报价公式为：**基础积分 + 生成图片数量 × 每张积分 + 视频秒数 × 每秒积分 + 参考素材数量 × 每个参考素材积分**。价格按工具类别、供应商、模型、档位精确匹配；模型或档位空值只匹配未设置值，不代表通配。可额外指定最多 12 条参数精确匹配条件，保留数字、文本与布尔类型；匹配条件更多者优先，同等优先级存在冲突时拒绝报价。所有系数明确设为零才表示免费。

报价与输入、价格版本及有效期绑定。用户提交时价格或参数变化则返回重新确认，不静默提高扣分；已接受任务冻结原报价，执行期间调价不影响它。

对成本取决于输出数量或未知时长的能力，管理员定价前仍需核对供应商协议支持的边界，不能把本地结果分页上限当作供应商计费上限。首版按已配置规则冻结任务报价，不实现通用按上游实际用量自动补扣；未知时长等组合采用管理员明确的固定价策略，差额风险由站点承担。评论已限制为每任务 1–1000 条，不开放无限“全部评论”。

现有供应商价格记录只能作为制定价目表的证据之一，需核对计费单位、失败/轮询收费和参考素材处理成本。积分与人民币的对应关系及工具定价另行确认，不默认 1 分等于固定金额。

### 6.4 预占、结算与异常处理

正常路径：**服务端报价 → 用户提交 → 预占积分并建立任务 → Worker 执行 → 确认完成后结算**。

| 情况 | 积分处理 |
| --- | --- |
| 可用积分不足或输入无效 | 拒绝建立付费任务，不扣分 |
| 任务接受成功 | 对应积分从可用转为占用，与任务和入队共同提交 |
| 按报价完成并交付 | 将占用积分结算为消耗，一次任务只结算一次 |
| 已确认失败且未交付结果 | 在无在途/未知请求且无交付或供应商成功证据时释放占用；用户不收费，供应商已发生成本由站点承担 |
| 请求超时、供应商结果未知 | 保留占用，进入核对；不自动退款后重新购买同一任务 |
| 供应商成功但本地结果保存失败 | 优先恢复保存，期间保留占用，不再次创建生成任务；若最终无法交付则按核对决定处理 |
| 部分成功 | 先尝试恢复交付，不能因总任务失败全额退回；首版由管理员根据预先公布的交付规则核对扣除与退回数额，暂不做自动按比例退款 |
| 用户停止/放弃 | 根据持久化结果与请求状态决定释放或转人工核对；已发出请求、已有产物或停止后仍需确认时保留占用，不承诺取消即退款 |
| 同一请求重试、Worker 重复投递或恢复 | 复用原业务任务与积分占用，不重复扣分 |

既有异步任务的“查询结果”可能创建新的运行记录。积分不能简单地每个 `run_id` 都扣一次：恢复原任务结果应关联原计费任务，避免同一生成任务重复收费；如果用户确实发起新的、独立收费查询，必须重新明确报价。

任务状态与积分状态分别持久化。不能简单把所有 `failed` 映射为全额退款、所有 `completed` 映射为全额扣分；结果可能已部分保存，或供应商已成功但本地仍需恢复。当前视频主文件已交付但要求的末帧缺失时转人工核对，不自动全额结算。管理员在 `/admin/tool-prices` 的待核对页查看占用和执行记录，填写实际扣除数额与理由，余下占用退回；运行中任务或仍有 pending 请求时拒绝人工终结。

### 6.5 最小数据与事务边界

用户领域已增加以下持久事实：

1. **积分账户 `member_credit_accounts`**：用户 ID、可用积分、占用积分。余额只作为可校验的事务汇总，不接受前端修改，不允许并发扣成负数。
2. **积分流水 `member_credit_entries`**：不可变的发放、预占、扣除、释放、调整记录，包含用户、数额、关联计费任务、幂等标识、操作人、原因和时间；纠错追加流水。
3. **任务与报价**：`member_tool_prices`、`member_tool_quotes`、`member_credit_charges`、`member_credit_run_links`、`member_credit_reconciliations` 保存版本化价格、冻结报价、原始/恢复任务、占用状态和核对幂等记录；状态转换只能结算或释放一次，恢复链不能建立新的重复占用。

检查积分、预占、创建任务和入队在同一数据库事务内完成。各工具命令将用户积分授权传入真实的任务创建事务，事务失败共同回滚，不先扣分再调用独立命令，也不先入队再补扣。

结果完成与积分结算在任务状态事务中共同提交，重复执行不重复结算。外部请求仍遵循现有回执恢复语义，数据库事务不承诺外部只收费一次。

积分只约束普通用户的工具任务。管理员现有采集、运营任务仍沿用原服务预算，不自动消耗某个普通用户积分。管理员发放积分不会提高全站供应商预算；预算不足时即使用户积分足够，任务仍会等待或明确被阻止。

### 6.6 后续扩展

充值订单、会员周期赠送等后续功能只需在订单或周期确认后幂等地记入积分流水；积分消费仍走同一报价、预占和结算路径。等级控制哪些工具可用，积分控制可消费多少，二者不混成一个角色字段。

如未来引入积分有效期、不同来源的消费顺序或现金退款，需要另行扩展积分批次和支付订单模型；首版不假装已解决这些规则。

**已确认采用试用积分作为主要使用额度控制。** 具体工具价格与发放数额由管理员显式设置，系统不会自动填入；并发、报价与存储上限见 5.5 节。部分交付保留占用并交由管理员核对。

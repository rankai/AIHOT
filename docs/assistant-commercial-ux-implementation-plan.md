# 创作助手商用体验优化实施方案

日期：2026-11-13。状态：**第一批 A 已按后续授权实施并完成核心局部及隔离浏览器验收，未提交、未部署；B 已实现并通过核心局部测试及代表性大小屏浏览器验收；C 的 DOCX 已实施并完成核心局部及代表性浏览器验收，未部署**。基线：`dev@0bcebb5` 及对应 localhost:3000 部署。依据：[商用体验评估 U1–U8](reviews/2026-11-13-assistant-commercial-ux-audit.md)。实际证据与未覆盖项见[第一批验收记录](reviews/2026-11-13-assistant-history-acceptance.md)及[第二批验收记录](reviews/2026-11-13-assistant-delivery-acceptance.md)。方案本身不替代付费、日常数据写入、提交和部署授权。

## 1. 目标与本轮范围

让用户能找到旧会话与作品、理解异常及积分后果、快速比较方案，并方便复制或下载所选作品。沿用现有三栏工作区、统一技能入口和任务系统。

按两个实施批次安排 U1–U7；U8 材料格式另行推进，DOCX 已实施并验收，其他格式仍后置：

| 批次 | 范围 | 用户能得到什么 | 完成条件 |
| --- | --- | --- | --- |
| A：历史与异常 | U1 归档找回、U2 异常解释、U3 标题搜索与重命名 | 旧作品找得到；知道任务为什么停住、接下来做什么、积分是否已确定。 | 归档可找回，搜索覆盖所有本人会话，改名不影响任务；异常提示与实际操作后果一致。 |
| B：比较与交付 | U4 方案概览、U5 复制导出、U6 能力说明、U7 图片放大 | 三套方案容易比较；文案方便拿走；能检查封面细节；知道不同动作需要什么材料。 | 仍操作原任务及精确作品版本，编辑和阅读位置受保护，无新增费用步骤。 |
| C：按需扩展，不随 A/B 默认实施 | U8 常见材料 | 已选 DOCX，减少用户转换文件格式的工作。 | 按 [DOCX 专项方案](assistant-docx-input-plan.md)落实解析、限制、失败与验收；实施结果见 [DOCX 验收记录](reviews/2026-11-13-assistant-docx-acceptance.md)。 |

A 完成并验收后再做 B。每批按可独立检查的小改动实施；开发代理负责实现，主审复核业务边界与差异，浏览器验收按用户要求交给 GPT-6.1 Terra Ultra。模型选择是执行分工，不代替实际检查。

## 2. 沿用的业务规则

- 费用模式仍是当前的**默认自动、可选每次确认**，入口紧挨发送按钮。自动模式按发送时保存的授权执行；手动模式在会话内确认一次。当前浏览器保存的用户选择不被本轮改写。
- 一个任务沿用一份已确认范围和费用上限；任务内回答、选封面方案不重新报价。余额不足不执行；停止和结束仍按既有事实结算。补积分、查看作品、恢复归档、改名和刷新页面均不授权新执行。
- 原价目、供应商接口、预算、成本中心、任务幂等、停止和异常恢复机制保持。结果未知不重发、不先退分；本方案不改任务 64 或其他真实任务。
- 一套小红书 Skill 继续包含写作、改写和封面能力，不拆成三个技能。已完成的 Markdown 展示、精确版本直达、研究依据折叠、下载和未保存编辑保护继续复用。
- 不新增钱包、工作流引擎、搜索服务、独立作品库或另一套状态存储；A/B 预计不需要数据库迁移。新增历史管理接口与用户说明字段属于局部扩展，不能写成“纯样式改动”。

## 3. A 批：历史找回、命名与异常提示

### A1. 历史列表与标题搜索（U3）

**当前路径：** 按助手筛选 → 按创建时间浏览 → 逐个打开相似标题。

**目标路径：** 在左侧输入“搜索会话标题” → 查看结果 → 打开原会话；同一列表可切换“未归档 / 已归档”。助手筛选保留，手机仍在现有侧栏抽屉内操作。

界面：

- 一行紧凑搜索框，支持清空；输入短暂稳定后查询，Enter 可立即查询。输入过程中不挤掉当前对话或触发草稿保护。
- 搜索只匹配会话标题，大小写不敏感；不暗示已搜索正文、附件或作品全文。无结果时提示“没有找到相关会话”，可清空搜索或切换归档范围。
- 标题旁/下方显示已有创建日期，长标题保持紧凑截断；完整标题可在会话页查看，手机不依赖悬停。
- 保留创建时间排序，改名不把旧会话顶到列表开头；本批不增加置顶、文件夹、标签或按最后活动排序。

后端与读取：

- 扩展现有 `GET /api/assistant/sessions`，新增标题关键词和归档范围参数；未传时保持当前未归档行为。服务器先按本人、非删除、助手、归档状态和关键词过滤，再分页，不能只过滤已加载的 50 条。
- 继续每页 50 条，以 `created_at DESC, id DESC` 稳定排序；使用服务器产生的精确时间与 ID 游标，返回 `nextCursor`，多取一条判断下一页。不要用前端毫秒精度时间重建游标，也不新增总数统计。
- 现有 `sessions` 字段保持；新前端和两个 SSR 读取入口一起使用游标。旧 `before` 参数在切换期仍按原语义接受，与新游标同时传入时拒绝。待部署切换完成并确认无旧调用方后移除旧参数，届时单独收口，不建设长期双轨分页。
- 关键词使用参数化查询并按字面匹配 `%`、`_` 等字符。复用现有每用户 100 个未删除会话的限制和 owner 索引，本批不增加全文索引、缓存或搜索基础设施，也不调整会话上限。
- 切助手、归档范围或关键词时重置游标；加载更早才追加。复用原 AbortController、去重和列表刷新事件，旧响应不得覆盖新筛选；自动刷新保持当前全部筛选条件。

### A2. 归档找回与恢复（U1）

**目标路径：** 会话菜单归档 → 左侧切到“已归档” → 打开并查看原消息/作品 → 点击“恢复会话” → 回到普通列表。

- 复用现有归档入口及提示，保持当前活动任务期间的界面限制，不扩大允许归档的范围。
- 已归档页继续可读；顶部给出轻量归档提示和“恢复会话”按钮，普通输入仍按现有归档规则禁用。恢复后仍留在该会话，刷新列表；不额外弹出确认向导。
- **恢复只解除 `archived_at`。** 原任务、原作品、原引用与历史费用不变；不调用任务恢复、消息队列继续、报价、生成或结算，也不清除 `queue_paused`。
- 恢复后能否提交新需求，继续服从当前任务、待核对请求、暂停队列、技能启停和余额等既有规则。若仍有暂停队列，保留原“继续排队消息”路径，不能恢复归档就自动发送。
- 删除与归档明确分开：已删除会话不出现在归档列表，也不能恢复；本批不增加回收站。归档不释放现有会话数量配额。

实现沿用会话控制路由，新增恢复动作，复用 `userHandler`、`ownedSession`、现有事务及锁序、会话事件通知。恢复响应丢失时先读取当前状态确认，不盲目重复操作。

### A3. 重命名（U3）

**目标路径：** 会话页现有“更多”菜单 → 重命名 → 编辑标题并保存 → 页头和历史列表同步。

- 复用已有轻量对话框和命令反馈；使用当前创建标题的长度约束（去首尾空白、1–160 字符）。不新增 AI 自动命名调用。
- 仅改变会话标题；不改第一条需求、作品名称、任务快照、报价和消息内容。
- 空标题就地提示；取消不保存；网络失败保留输入；保存期间防重复点击。

**A2/A3 的并发与权限边界：**

- 只允许本人操作非删除会话，复用原登录、同源/CSRF、错误映射和 no-store 策略。
- 元数据修改不递增用于报价/回答的业务 `session.revision`，避免改标题让有效报价或在途回答失效。通过已有会话事件和历史刷新通知更新界面。
- 重命名携带原标题与目标标题，行锁下核对；已是目标标题则按成功处理，另一标签已改成其他标题则保留用户输入并提示更新后再改。
- 恢复携带读取到的精确归档时间；已恢复视为成功，期间重新归档则提示刷新，不让旧操作恢复另一轮归档。复用已有时间字段，在会话快照补充精确值，不建新版本表。
- 请求超时先读取快照核实，只有目标状态已达到才显示成功；不因这些可逆操作去修改原任务恢复记录。前端命令工具的请求键不被误当作已实现的服务端持久幂等。

### A4. 异常状态、停止含义和求助（U2）

现有 `needs_review` 下的“停止”会终止后续运行并进入既有结算处理，**不是关闭提示**。当前任务主动停止后不能假称随时能续跑；未知的外部请求也不因停止而立即退款。本批只调整现有状态投影、文字与帮助入口，不改变停止函数和恢复规则。

| 状态 | 默认给用户看的信息 | 操作保持 |
| --- | --- | --- |
| 正常运行 | 已有真实业务步骤或“正在处理”。 | 输入为空时，发送位置承担停止；有内容时沿原回答/排队规则发送。 |
| 等用户选方案/补充 | “选一个方案后继续”或实际问题。 | 复用原问题和提交，不重报价，不多一个停止按钮。 |
| 任务需要核对处理结果 | “任务暂时停下了，需要确认处理结果。先不用重新发送。”金额按真实保留/结算状态补充，不猜退款时间。 | 保留“查看处理结果”，它只读状态；提供下述反馈入口。 |
| 待核对时用户可停止 | 在输入框附近就地说明“停止会结束后续执行，费用仍按实际使用结算”；按钮可访问名称明确为“停止当前任务”。 | 不隐藏真实停止能力，不新增弹窗；点击后继续走原停止请求，提交中禁用，成功后才写已停止。 |
| 已停止但费用未确定 | “后续执行已停止，实际费用尚未确定。”确有已保存作品时再提供查看入口。 | 继续展示原处理结果入口；有确切结算后才展示实际用分/退回。 |
| 页面读取失败 | “暂时无法获取最新状态，请重新连接。你的输入已保留。” | 读取失败不显示成任务失败，也不触发重新发送。 |

上表是表达原则，金额、能否继续、能否停止必须取已有后端事实；不能为配合文案制造新状态。`needs_review` 也可能来自本地异常、子任务失败或交付未保存，不等于供应商仍在处理，也不证明系统或管理员正在核对。只有现有事实明确指向在途或未知请求时才补充对应说明，不能伪造后台进度或根因。避免每处重复长篇费用说明，默认保留一句当前情况和一个主要下一步，详细原因仍按需展开。

“联系管理员”目前实际通向反馈表，不是即时客服。本批将其标成“反馈问题”，复用 `/feedback` 的 `from` 参数带回会话地址；提供“复制问题信息”取得任务标识和简短状态，用户自行决定是否粘贴提交。沿用离开保护，不带原需求全文、材料或敏感信息，不自动提交、不声称已经有管理员接单、不编造处理时限。返回会话保留草稿与阅读状态，不自动恢复任务。

## 4. B 批：比较方案和作品交付

### B1. 三套封面方案概览（U4）

**当前路径：** 逐段阅读长布局描述再比较。**目标路径：** 先看三套紧凑概览 → 展开感兴趣的方案 → 在原选择区确定方案。

- 复用 `CoverPlanBody` 和已有结构字段 `name/layout/palette/prompt/aspectRatio/sourceIds`。现有数据没有独立“风格摘要”，本批不假定该字段存在。
- 每套概览只呈现名称、比例、布局节选和配色。节选是原文的视觉截短，标明可展开；不生成新语义摘要，不伪造适用人群或效果，不调用模型补历史数据。
- 对话的选择行和作品页使用同一组已有字段；手机为纵向紧凑卡片，桌面有足够宽度才并排。用现有颜色、间距和选中状态，不恢复黑色大按钮或横向大表格。
- 详细布局、提示词与研究依据按需展开。缺字段的历史方案显示可用字段与原文，不猜补；展开状态绑定对应作品版本，普通刷新不折回，切版本不串状态。
- 原待回答区域仍是唯一的方案提交入口，继续携带 `schemeId + artifactId + version` 并沿原任务执行。历史方案页保持查看、复制和原有引用方式，不新增绕开授权的生图按钮。
- 方案选择后不多确认一次费用；正在看旧版或编辑其他稿件时，任务进展不强行切走。

### B2. 文案复制与文本下载（U5）

默认主按钮保留“复制文案”，输出可读纯文本：主标题、正文、标签各一次；不混入研究附录、备选标题或内部记录。其他操作收进现有轻量菜单，避免多排按钮：

| 操作 | 输出内容 |
| --- | --- |
| 复制原格式 | 所选版本原有 Markdown 文字；沿用现有标题/标签去重。 |
| 复制标题 / 复制标签 | 已保存的主标题或标签；不存在标签则不显示该项。备选标题旁提供局部复制，不把所有标题塞进默认全文。 |
| 下载 TXT | 与“复制文案”一致的 UTF-8 可读文本。 |
| 下载 MD | 与“复制原格式”一致的 Markdown 文本。 |

- 复用 `artifactText()`、所选版本读取与现有复制反馈。封面设计方案保留整份方案/单套提示词的既有复制语义，不强行套文章的标题正文规则。
- 当前没有成熟 Markdown 转纯文本依赖。优先从 `ResultText` 提取显示/导出共用的局部解析语义：保留段落、列表、链接地址、表格行和代码内容；不认识的语法保留原文，不用全局正则删字符，不建设完整 Markdown 引擎。
- 共用解析若影响工具页显示，必须保持该页面原行为；不把下载文字转为可执行 HTML。
- 文本下载在前端以 Blob 完成，标题与版本构成安全文件名；使用后释放资源。不新增导出服务、服务器文件存储、公开链接、费用项目或模型请求。
- 所有操作针对**当前选择的已保存版本**。编辑状态下不悄悄导出旧稿：隐藏或禁用这些操作，简短提示先保存；取消编辑回到原已保存版。继续沿用已有未保存保护，不另复制一份编辑状态。
- 图片下载实现不变；普通文本复制不保证公众号富文本排版可直接发布，富文本导出留待后续。

### B3. 能力说明与动作发现（U6）

第一批完成状态用语，本批补输入处的简短帮助：

- 新对话和会话中的技能菜单继续来自同一启用目录。小红书保留一个技能；选中后就地提供写作、改写、封面三个已有动作，复用已有动作选择处理，不新增技能或路由。
- 每个动作使用一句“需要什么 / 能交付什么”的说明，例如“提供原文，改写成小红书笔记”“提供主题，研究参考并设计封面”。完整图或仅方案的交付范围仍由当前输入和原报价识别确定；说明不默认替用户选更贵范围。
- 自动选择状态只说“描述需求后，为你选择合适的技能”，不假装已选定具体能力。
- 说明放在现有菜单/动作附近或空输入提示，正文有内容时保持简洁。选择不自动写模板，不覆盖文字、附件和引用；继续使用 `chooseDraftAction` 清理失效的旧交付选择，不自动报价。
- 动作用途放入现有 binding 的可选短用户说明字段，经原 catalog/actions/options 投影；旧包没有说明仍显示原标签。原模块描述含供应商、M1/M2 等内部信息，不能直接透传。不开新帮助目录、配置表或第二份前端硬编码能力清单。
- 用户说明仅作为当前目录的可选展示元数据，旧包缺少时显示原标签，不回填或改写历史包。仅扩展 binding 的展示字段、未改变执行资源与合同时，不为说明文案强制升级技能执行版本。若确需修改受完整性保护的资源，按现有发布规则生成新包版本并保留原版，不得原地重算旧包哈希；完成相应目录加载局部验收。已确认任务继续使用原快照与原包，说明更新不得重新选择技能、重新报价或替换绑定版本。

**已排除重复开发：** 当前共用 `communication` 指令已经要求不播报加载技能、模块和接口，封面续跑也复用。旧任务中的技术化话术不是新指令失效的证据。本批不再叠加同义提示词、不改写历史回复；仅处理仍存在的 UI 用语。以后新任务确实复现，再定位具体输出来源。

### B4. 图片放大与细节检查（U7）

**目标路径：** 作品中点图 → 全屏大图 → 切换“适应屏幕 / 原始大小”检查小字 → 关闭回到原版及原阅读位置。

- 复用公共 `Lightbox` 的 Portal、Esc、焦点返回和背景滚动锁；现有组件只有适应屏幕，不能仅接入就宣布手机细节查看完成。
- 局部增加原始尺寸查看，图片在弹层内部滚动，不造成底层页面横向溢出。点击图片/滚动不误触关闭；关闭按钮始终可触达。本批不增加画布编辑器或手势库。
- 公共组件原调用保持默认行为，新增能力只在需要的调用中启用；用一个既有工具图片页面做代表性回归。
- 只打开当前作品的精确版本图片，不预取所有历史图片。切会话或切版本关闭旧预览；新作品到达不替换正在看的旧图。
- 读取失败就地提示，沿用鉴权与资源保护；不把失败转成重新生成。下载继续使用原组件和精确版本，不暴露新的公开资源地址。

### 发现并修复：同名引文/代码被误当作重复标题

- 触发：主标题为“标题”，正文以 `> 标题` 或行内代码形式的同名字段开头。
- 原因：`artifactText()` 使用整行 Markdown 转换后的纯文本等值去重，无法区分真正标题与引用/代码正文；复制原格式、MD 和纯文本均可能丢失这一行。
- 最小修复：仅去重字面标题或明确 ATX 标题；引用、行内代码等正文保留。现有 `## **标题**` 的标题去重继续有效。未扩建解析器、引入依赖或更改文案数据。
- 监督执行：主代理负责 A 批及整体边界复核；实际配置的 GPT-6.1 Sol High 进行 B 批有界复核并修复，主代理独立检查修补差异。仅改 `data.ts` 和既有 `assistant-data.test.ts`，新增一个合并回归用例。
- 验证：新增回归在旧实现失败；修复后 `assistant-data` 14/14、共用工具展示 `tool-results` 2/2 通过，`git diff --check` 通过。复用 Node 24、无数据库与外部副作用的局部验证。没有 UI 结构或事件变化，未重复此前浏览器矩阵或无关全量测试。
